## 2. How work runs from now on

### 2.1 The model

- Vamos now runs from plain Claude Code on Koss's Mac. The working folder is /Users/koss/Developer/VamosTaxi.eu.
- There is ONE controller session. It works in that folder, on main.
  - Only the controller commits and pushes main.
  - Only the controller applies live migrations, deploys Workers and cleans branches.
  - The controller puts its name on .planning/CONTROL-BOARD.md.
- Every other session is a job session.
  - A job session runs GSD with Koss's CLAUDE.local.md.
  - It has its own vamos-wt worktree and its own branch, cut from origin/main.
  - It builds and tests, merges origin/main back in, and writes a hand-over file. Then it stops.
  - It never deploys, never writes to the live database and never pushes main.

### 2.2 Rules learned today (keep all of them)

1. **Standing order.** Koss, 13:41:15Z (17:41), verbatim: "coomit and deply all after verify dont ask me".
   It means: once the checks pass, commit, merge and deploy without asking him again.
   This quote is from the coordinator transcript. The project timeline file ends at 13:22Z, so it is not in that file.
2. **Never without his word**, even under the standing order:
   - the live Stripe key;
   - the vamostaxi.eu domain cutover;
   - price book row 18 Publish;
   - deleting test bookings;
   - wiping data.
3. **Fresh reviewer.** A new session, not the builder, reads every money, sign-in or database change before it ships. Opus plans and reviews. Sonnet builds.
4. **One session per job.** Parallel jobs never touch the same files. Each plan lists its exact files. In the shared translation files (app/vamos-i18n-dict.js, apps/web/i18n/messages/*.json) a job adds only its own keys.
5. **Signatures.** Koss signs discuss, design and plan before a build starts. Ask him one decision at a time, in plain words, with the recommended option first. Never re-ask what .planning/decisions/ already answers.
6. **A bare "ship" counts.** When Koss types "ship" in a job's own session, that is a Ship.
7. **Clean GitHub.** Koss, 11:41:32Z (15:41): "I don't want any PR that is finished. Push it, merge it, and clean it. Remove it. Any branch that is committed to main is finished and deleted. I want GitHub always clean."
   How it is done: archive tag first, then delete the branch, the worktree and the PR.
8. **Deploy with the live env flag.** Use `--env staging`. It points at Worker `vamos` on vamostaxi.site, which is live.
   At 13:33Z a deploy without the flag created the stray Worker `vamos-web`. It was deleted at 13:45Z.
   Never run the "Deploy Staging" GitHub workflow from a job. It can deploy the live Worker.
   deploy-production.yml deploys on any pushed `v*` tag. None exist.
9. **Pinned Supabase CLI.** Regenerate database.types.ts with `pnpm exec supabase` (version 2.115.0), then run `db:types:check`. The global 2.118 prints a different layout and fails the check.
10. **Seed re-pin.** Any change to seed.sql means re-pinning packages/db/supabase/tests/seed_idempotent.test.sql to the counts in the seed header.
    - main (after /confirmation): content_strings 2692, no_param_reason 96.
    - B7 branch: content_strings 2693, no_param_reason 97.
11. **Full check set.** typecheck, lint, lint:css, i18n:check, check:legal-claims, check:numbers, check:public-env, check:db-fences, db:seed:check, test:unit, build. Add db:types:check for any migration. Run pgTAP from an empty database on the session's own ports. Never use port 54322; it belongs to the main "vamos-taxi" test database.
12. **Migration numbers.** Ask the controller for a number before writing a migration file. Check every remote branch for that file name first. The next free number is in section 7.
13. **Ship routine (controller).**
    - Clean clone of main plus the squash. Run all checks.
    - Apply any migration verbatim and read it back.
    - Deploy with the env flag.
    - Run live GETs.
    - Make a backup tag of main, an archive tag of the branch, then delete the branch.
    - Update the board.
14. **Resolve rule** (13:39Z). Mark a finished job as done at once. Under the new model, update the board and close the session.
15. **Design system.** Keep Vamos's own design system, not ui-system (Koss, 10:57Z).
16. **Mac safety check (auto mode).**
    - Sessions on the Mac refuse deletions, rule edits, plan signatures and self-modification when the order only came relayed from another session.
    - It went as far as refusing a git read for a job that rewrites the rule files.
    - The controller refused twice (13:17Z and 14:01Z) to edit the files that define its own role, as self-modification.
    - A relayed Ship that carried Koss's own message did go through.
    - The fix: Koss types the exact words in that session himself. For deletions he types "yes, delete". For a rule change he types the change.
    - In the local model Koss talks to each session directly, so this should rarely bite. But expect the controller to refuse changes to its own rules unless Koss types them.
17. **Cloudflare token.** The controller's Cloudflare token has no Web Analytics or RUM write scope. Koss flips those switches in the dashboard himself.
