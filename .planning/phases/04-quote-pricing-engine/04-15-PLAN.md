Open the write door Phase 3 reserved and could not build.

leaves `QUOTE_PG_ROLE` untouched.

Postgres, inside the write transaction, against the verified payload — not by a Worker clock, not
by a UI countdown, and not by a handler that might forget the `if`.

Worker in the picture.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `anon` (the quote identity) → `price_snapshots` | An unauthenticated public role gains a write path for the first time |
| Caller-supplied `p_lock_exp` → the expiry decision | The one argument that decides whether a 30-minute promise is still good |
| Caller-supplied jsonb → an append-only, immutable row | Nothing written here can ever be corrected by UPDATE |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-38 | Elevation of Privilege | Granting `anon` INSERT on `price_snapshots` directly, which would also permit arbitrary rows with caller-chosen totals and version flags | mitigate | Path (a): one `SECURITY DEFINER` function is the entire write surface; a direct `insert` as `anon` still raises `42501`, asserted as case (11) |
| T-04-39 | Tampering | Lock replay — presenting a held, expired token and getting a snapshot written anyway because a handler forgot the check | mitigate | The RPC raises on `p_lock_exp <= now()` evaluated by Postgres inside the transaction, and inserts nothing; the count-unchanged assertion (case 6) is what proves "nothing", not merely "raised" |
| T-04-40 | Elevation of Privilege | A caller passing `rate_version_is_live => true` against a draft version to make a placeholder amount chargeable | mitigate | No such argument exists in the signature (grep-asserted), and `tg_snapshot_rate_version_flag` overwrites the column from `rate_versions` regardless (D-33) |
