## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `surcharges.predicate` jsonb → kernel | Untyped database jsonb becomes a control-flow decision |
| Client-supplied extras quantities → `quantity` predicate | The one predicate whose input the customer controls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Elevation of Privilege | A malformed or empty `predicate` evaluating to "applies", attaching an unversioned charge | mitigate | An unknown `kind`, an empty object and an unresolved zone all return `applies: false` with an `unresolved` reason; plan 04-04's publish gate refuses `{}` on a `draft → live` transition so the shape can never reach a chargeable version. Acceptance: `predicates.test.ts` asserts each of the three cases |
| T-04-04 | Tampering | A client-supplied quantity inflating a `quantity` surcharge line | mitigate | The predicate reports the quantity; the **amount** comes only from the pinned rate version (plan 04-03), and plan 04-08's zod boundary bounds the quantity ranges before the kernel is reached. This module never reads an amount at all |
| T-04-05 | Repudiation | A night surcharge that cannot be justified months later because the rule lived in code | mitigate | `why` carries the predicate kind, the window, the `tz` and the wall-clock value that satisfied it, and is written into the snapshot's `basis.why` — the recomputation never needs the deployed code (research T2, §13) |
</threat_model>
