# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Framing.** Phase 4 ships no booking-widget React port — `04-CONTEXT.md`'s Phase Boundary is explicit:
*"No booking-widget React port — Phase 5. Phase 4 ships the contract the widget consumes."* This
document is therefore not a page-by-page layout spec; it is the **binding contract** between the
`/api/quote` engine (`04-RESEARCH.md`, `04-API-CONTRACT.md`) and the already-ported Vamos component
inventory (`apps/web/components/`, landed in Phase 1) that Phase 5 must implement against and
`gsd-ui-checker`/`gsd-ui-auditor` can verify without waiting for Phase 5 to exist. It answers, for
every state the engine can return: *which ported component, which prop, which i18n key.* Two
genuinely new interaction patterns not covered by Phase 1's Component State Matrix (the quote-lock
countdown, the return-leg presentation) are specified here as **compositions of existing
components**, not new Design Components — per `CLAUDE.md`'s own test ("do not fork a component to
change one value; add the prop" / compose, don't restyle).

No new colour, font, radius, shadow or spacing value is introduced anywhere in this document. Every
visual value is a `--vt-*` token already declared in `design-system/tokens/` and already carried
into `apps/web/public/brand/tokens/` (Phase 1). Every amount is the literal placeholder `CHF 000`
(`formatAmount(null)` — `apps/web/lib/currency.ts`) — Phase 4 emits `null` for every `*_rappen`
value (D-9, ADR-014 §5's "CHF matrix still open") and this document never asserts otherwise, not
even in a worked example.

This agent ran in the background and could not ask the user questions. Every decision below that is
not a direct citation of `04-CONTEXT.md`, `04-RESEARCH.md`, ADR-014 or an existing ported component
is recorded in **Assumptions (made without asking)** at the end, for a human to confirm or overrule
before Phase 5 planning locks it in.

## Component Contract for the Quote Flow

Every row cites the requirement it satisfies, the exact `04-RESEARCH.md` §14 i18n key (or the new
key this document proposes when §14 has none), and the ported component/prop it binds to.

### A. Vehicle class board — eligibility (QUOTE-02) and price (QUOTE-03, QUOTE-10)

`apps/web/components/transfer/VehicleCard.tsx` is the board unit. One card per `classes[]` entry
in `QuoteResponse` (`04-CONTEXT.md` `<specifics>` — Economy, Business, Van; `first` does not ship,
ADR-014 D-38).

| `classes[]` state | `VehicleCard` prop binding | i18n key | Notes |
|---|---|---|---|

**Board-level `pricing_live=false` gate (QUOTE-10, D-9 layer 4).** This is a **data state, never a UI
conditional on an environment flag** — `04-RESEARCH.md` §8 is explicit: *"formatRappen(null) → CHF
000. Not a UI conditional."* Concretely: every card's price slot already reads `CHF 000` because
`total_rappen` is `null`; the widget's primary continuation action (selecting a card / a "continue"
CTA, whichever Phase 5's layout uses) is `disabled` and captioned from `quote.pricing_pending`
("Prices come once the fare table is approved") **because the data says so**, not because a
`pricing_live` boolean is read in component logic. No component in this phase's inventory needs a
new `pricingLive` prop — the existing `disabled`/`price` props already carry the whole state.

### B. Sticky price panel — `PriceSummary` (QUOTE-03, QUOTE-05, QUOTE-10)

`apps/web/components/transfer/PriceSummary.tsx`, in the sticky right rail (`top: 96px`, unchanged
container contract from `checkout.dc.html`/`.claude/CLAUDE.md`).

| State | Binding | Notes |
|---|---|---|
| `empty` (no route entered yet, or a same-place/place-out-of-box/min-advance refusal — see §H) | `empty`, `emptyMessage` | new: `quote.empty.subtitle` (reuse mock's `needTrip`: "Add your trip to see prices," 4-lang confirmed in `home.dc.html`) |
| `loading` (any `/api/quote` or `/api/quote/reprice` in flight — this is **more frequent** than a route re-geocode: pax/bags/date/time/extras/coupon changes all reprice without a new Directions call) | `loading`, `loadingLabel` | reuse mock's `getting` (see board table above) |
| populated (`classes[i].lines[]` for the **selected** class only — the board's `shown_alternatives` is server/evidence-side, D-73; the widget renders one class's lines) | `lines={classLines}`, `total={null}` → `"CHF 000"` | **Lines render in server-provided array order and are never resorted or grouped client-side** — the pipeline order (fare → surcharge → extras → round-trip → coupon, D-41) *is* the display order and is the one order a customer's Stripe-dispute reading of the receipt can verify against. `kind:"included"` → `muted:true`; `kind:"discount"` → `credit:true` — this maps onto `PriceSummary`'s existing `PriceLine.muted`/`.credit` props with **zero UI change**, exactly as `04-RESEARCH.md` §13 states. |
| a line's `amount_rappen: null` because it is `kind:"included"` (waiting) | line renders via `formatAmount(null)` inside its row, `muted:true` | `price.surcharge.waiting_airport.label` `{minutes}` = **60** (ADR-014 §5, no longer NULL) or `price.surcharge.waiting_city.label` `{minutes}` = **15**. Both render `CHF 000` today; only the former is permanent. |
| `note` (policy reassurance under the total) | `note` | Reuse checkout's existing "Fixed price, all taxes and tolls included. Free cancellation up to 24 h before pickup" pattern; the free-cancel window is a confirmed number (24h) per `settings_versions`, not a `data-tok` gap. |
| `pricing_live: false` continuation-disabled caption | `note` (replaces the reassurance note while disabled) | `quote.pricing_pending` |
| system-level refusal after a well-formed request (`route_unavailable`, `expired`, `price_changed`, `engine_changed`, generic `quote.error`) | `error` | See §H — this is the **only** place `PriceSummary.error` is used; field-level refusals (same_place, min_advance) use `empty`, not `error` — there is a valid, well-formed price board that simply hasn't been requested yet, which is a different fact than "the engine tried and failed." |

### C. Quote lock and 30-minute countdown (QUOTE-04) — new composed pattern

No existing component models a countdown. This is a **composition**, not a new Design Component:
`Icon name="clock"` + a `.vt-dir-keep` `mm:ss` figure + (near expiry) a tone change — the same
"colour step, never a glow" law every other state in this system already follows (`CLAUDE.md` §
"Never use glow effects").

| Sub-state | Composition | Copy (new keys — see Assumptions) |
|---|---|---|
| Locked, > 2 minutes remaining | Row inside the sticky price panel, below the total, above `note`: `Icon name="clock" size={15} color="var(--vt-text-muted)"` + text, body-sm (14px), **not** the Figures scale (a countdown is an ambient signal, not a hero number — it must never visually compete with the total price it sits below) | `quote.lock.countdown` — "Price locked · {time}" (`{time}` = client-ticked `mm:ss`, `.vt-dir-keep`) |
| Locked, ≤ 2 minutes remaining | Same row, icon and text colour step to `var(--vt-danger)` — a **discrete tone swap**, not a filling/glowing bar. If a `ProgressIndicator` is used instead of bare text (planner's call), its `tone` prop steps from `"charcoal"` to `"danger"` — `ProgressIndicator` has no coloured `box-shadow` in its ported CSS, so this composition cannot introduce a glow by construction. | `quote.lock.expiring_soon` — "This price expires soon — pay now or get a new one" |
| Expired (`0:00`, or a `409 quote_expired` from the server) | The countdown row is **replaced** by the board-level `Alert` refusal defined in §H (`quote.error.expired`) — the countdown itself has no terminal-state copy of its own beyond stopping. | `quote.error.expired` (already 4-lang, §14) |

**This client-side countdown is decorative, exactly as `04-RESEARCH.md` §5 states of the Worker-side
check it mirrors** — the real gate is Postgres `now()` inside the checkout transaction (D-61); a
paused tab, a clock-skewed device or a bypassed countdown must never be able to extend the window.
No UI copy in this phase should imply the countdown itself is the enforcement mechanism.

### D. Return-trip leg presentation (ADR-006, QUOTE-02) — new composed pattern

`RouteSummary` (`apps/web/components/transfer/RouteSummary.tsx`) models exactly one pickup/dropoff
pair; it has no built-in concept of a second leg. Composition for `mode: "return"`:

1. **Outbound leg** — one `RouteSummary` exactly as today: `pickup`/`dropoff` from the trip, `meta`
   = `[{icon:"calendar", label: outboundDate}, {icon:"clock", label: outboundTime}]`. Kickers stay
   `common.pickup`/`common.destination` (unchanged, already 4-lang, already used by RouteSummary).
2. **Divider + return kicker** — `border-top:1px solid var(--vt-border-subtle)` with `padding-top`
   from the spacing scale (`--vt-space-4`, 16px) — the exact divider rule already used between
   `RouteSummary` and `PriceSummary` in `checkout.dc.html` and between Card sections generally. A
   small UPPERCASE label above the second block reuses the mock's own trip-type word: `common.return`
   (source `return_`: "Return"/"Rückfahrt"/"Aller-retour"/"ذهاب وعودة" — already 4-lang, `home.dc.html`).
3. **Return leg** — a second `RouteSummary` with `pickup`/`dropoff` **swapped** (the vehicle returns
   the traveller to the original pickup point — see Assumptions for why this is inferred, not
   sourced), `meta` = `[{icon:"calendar", label: returnDate}, {icon:"clock", label: returnTime}]`.

**Pricing consequence, not a layout one:** the return-trip discount (`price.line.return_discount`,
10% of fare per ADR-014 §5, U16 closed) is a **single booking-level line** in `PriceSummary.lines`
(§B) — it is not duplicated per leg, and it must not be rendered inside either `RouteSummary` block.
Child seat / oversized luggage, by contrast, **do** duplicate onto both legs as separate priced
lines (D-45, one per `leg_seq`) — each renders as its own `PriceSummary` row
(`price.surcharge.child_seat.label`/`price.surcharge.oversized_luggage.label`), never merged into
one "×2" line. Extra stops apply to the outbound leg only (D-67) and therefore only ever appear
once regardless of trip mode.

## H. Refusal / error taxonomy → component mapping

one component and one placement, so two different plans never invent two different treatments for
the same key.

| Key | Component | Placement | Tone |
|---|---|---|---|

| `quote.extras.error.max_stops` / `.max_child_seats` | `Counter error` | inline | danger |

| `quote.error.rate_limited` | `Toast tone="danger"` | transient, top of viewport | danger |
| `quote.error.turnstile_required` | `Toast tone="neutral"` | transient | neutral |
| `quote.error.temporarily_unavailable` | `Toast tone="danger"` | transient | danger |
| `quote.error.mode_not_offered` | `Toast tone="danger"` (the `Tabs` item for `hourly` does not render at all per §G, so this is a defence-in-depth path only, e.g. a stale client) | transient | danger |
| `quote.error` (generic engine failure) | `Toast tone="danger"` fallback, or `PriceSummary.error` if it occurred mid-board-render | transient / sticky panel | danger |

**Why `PriceSummary.empty` and not `.error` for field-level refusals:** same-place/place-out-of-box/
min-advance are facts about an **input that hasn't produced a well-formed request yet** — the correct
board state is "no quote to show" (`empty`), with the actionable message living on the offending
field. `PriceSummary.error` is reserved for a request that *was* well-formed and the engine (or a
version/lock mismatch) refused it anyway — a materially different customer situation, and the two
must never share a rendering path or a screenshot baseline.

## Four-Language Layout Contract

Extends Phase 1's contract (`01-UI-SPEC.md` § same heading) — not restated here except where this
phase adds something new.

**New `.vt-dir-keep` surfaces this phase introduces:**

| Element | Why |
|---|---|
| Countdown `mm:ss` (§C) | A figure, same rule as `PriceSummary`/`Counter`/`DatePicker` values |
| Flight candidate `{time}`/`{day}` (§F) | Same reasoning as `DatePicker`'s selected-value display |
| Coupon `code` inside the `Tag` (§E) | Already the rule for `price.line.coupon`'s `{code}` param (I-08); the applied-chip rendering is the same literal, wrapped identically |
| `VT-YY-####` | Not applicable this phase — no booking exists yet (Phase 7) |

**Must NOT wrap `.vt-dir-keep` (a translated word, not a code):** the "Fixed price" badge (§A),
"Return" leg kicker (§D), and every `quote.class.*`/`quote.error.*`/`quote.coupon.error.*` sentence —
these are ordinary translated prose and must follow the reading direction, exactly like

## Assumptions (made without asking)

This agent ran in the background (`commit_docs: false`, no user interaction available) and made the
following calls unilaterally. Each is grounded in the cited source but is **not** a literal quote of
a locked decision — a human should confirm or overrule each one before Phase 5 planning treats it as
final.

1. **Quote-lock countdown copy and composition (§C)** — no key in `04-RESEARCH.md` §14 covers "price
   locked · time remaining" or "expires soon" copy; the whole pattern (icon + `.vt-dir-keep` mm:ss +
   a 2-minute danger-tone threshold) is this document's own design, following the project's existing
   "colour step, never glow" law by analogy rather than a cited precedent. The 2-minute threshold
   number is arbitrary.
2. **Return-trip legs mirror the outbound addresses (§D)** — inferred from typical airport-transfer
   return-trip behaviour and from nothing in `04-RESEARCH.md`/ADR-006 contradicting it; ADR-006 fixes
   "one booking, two legs, one snapshot" but does not state whether the return leg's pickup/dropoff
   are literally swapped versus independently entered. If a future owner ruling allows an
   asymmetric return (different return dropoff), this presentation contract needs revisiting.
3. **`quote.class.price_note` and `quote.class.fixed_route_badge` promotion** — these are English
   strings already present in the compiled bundle's own source comment (`VehicleCard.tsx`) or the
   mock (`fixed`), but neither has a `04-RESEARCH.md` §14 row; this document assigns them key names
   under the `quote.class.*` namespace by analogy with the sibling keys already there.
4. **Flight-status `Badge` tone mapping (§F)** — on-time→`success`, delayed→`danger`, cancelled→
   `danger`, departed→`neutral`. `04-RESEARCH.md` specifies the `status`/`dir` API shape
   (`to-airport`/`from-airport`/`neither`/`cancelled`/`departed`) but not a visual tone table; this
   mapping reuses `Badge`'s existing non-tinted tone set without inventing a new one.
5. **`no_eligible_class`/`moved_to` placement (§H last two rows)** — left as a Phase 5 layout choice
   between a persistent `Alert` and the mock's existing trip-summary status line, since Phase 4 does
   not own widget layout; only the copy binding is fixed here.
6. **Ineligible-class `VehicleCard.price` slot repurposing (§A)** — directly matches the mock's own
   `labelFor()` behaviour (confirmed by reading `home.dc.html`), but restating it as this phase's

   line item in `04-RESEARCH.md`.
7. **`PriceSummary.empty` vs `.error` split (§B, §H)** — the field-error/board-error distinction is
