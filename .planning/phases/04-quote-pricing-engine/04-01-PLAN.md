<interfaces>
<!-- The kernel surface this plan freezes. Every later pricing module imports from here. -->

  roundHalfUp(numerator: number, denominator: number): number
      // exact integer ratio, half-up, both arguments must be safe integers, denominator > 0

  percentToHundredths(numericString: string): number
      // '7.35' -> 735 (hundredths of one percent). Digit regex only. parseFloat is banned.

  percentOf(baseRappen: number, hundredths: number): number
      // roundHalfUp(baseRappen * hundredths, 10_000)

  perKm(perKmRappen: number, distanceMetres: number): number
      // roundHalfUp(perKmRappen * distanceMetres, 1_000)

Every function returns a non-negative integer number of rappen. Discounts are computed as a
positive magnitude and carry their sign in the line's `kind`, so "half up" and "half away from
zero" coincide and no negative ever enters this module (D-07).
</interfaces>

    - `roundHalfUp(n, d)` with `n = 5, d = 2` is `3`; `n = 4, d = 2` is `2`; `n = 0, d = 7` is `0`.
    - `roundHalfUp` throws a `RangeError` when either argument is not a safe integer, when `d <= 0`, or when the intermediate product would exceed `Number.MAX_SAFE_INTEGER`.
    - `percentToHundredths('7.35')` is `735`; `('10')` is `1000`; `('0.05')` is `5`; `('100.00')` is `10000`.
    - `percentToHundredths` throws on anything not matching a `numeric(5,2)`-shaped digit string (`'7,35'`, `'1e2'`, `'-1'`, `''`, `'7.351'`).
    - Property: for any safe non-negative integers `base` and any two percents `p` and `q`, `percentOf(base, p) + percentOf(base, q)` is independent of evaluation order — pinning the basis makes percents commutative (D-06's justification, proven here at the arithmetic level).
    - Property: `perKm(rate, metres)` is monotonic non-decreasing in `metres` and equals `0` when either argument is `0`.
    - Property: `roundHalfUp(n, d) * d` is within `d` of `n` — the rounding never drifts by more than one denominator.
  </behavior>

    `<interfaces>`. Doc-header cites D-07 and D-53 in the `currency.ts` style, and states the

    nothing, and never formats — formatting is `lib/currency.ts`'s `formatAmount`, which is the
    only place a currency mark is written.

    `roundHalfUp` computes with integer arithmetic only: take the integer quotient and remainder,
    then increment the quotient when twice the remainder is at least the denominator. Guard every
    input with `Number.isSafeInteger` and guard the product before it is formed, throwing
    `RangeError` with a message naming the offending argument. Do not use `Math.round` (it takes a
    float and rounds half toward positive infinity, which differs from half-up on the negatives
    this kernel is designed never to see) and do not use `toFixed`.

    `percentToHundredths` matches the input against an anchored digit regex allowing one to three
    integer digits and an optional one- or two-digit fractional part, then builds the integer from
    the captured digit groups by string manipulation — never `parseFloat`, whose `'7.35' * 100`
