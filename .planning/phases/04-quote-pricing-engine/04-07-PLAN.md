<objective>
Two signed artefacts and one primitive.

The quote lock is what makes QUOTE-04 true without a database row: a 30-minute promise the server
can verify from the token alone, at any PoP, the instant it is presented — where a KV document
would lag up to 60 seconds across PoPs and a snapshot row would mean writing 40–120 immutable
jsonb rows per abandoned planning session (D-21's arithmetic).

The `vamos_qs` cookie is the same shape for a different reason: an unsigned UUID is client-mintable,
so `Cookie: vamos_qs=<fresh uuid>` would buy a new rate-limit bucket and reset the Turnstile
counter on every request. Signing it is what makes QUOTE-09's per-visitor gate a gate.

They share one primitive on purpose. Two independent HMAC implementations is two places for a
canonicalisation bug, and a canonicalisation bug in a signature is silent until it is a breach.

Purpose: QUOTE-04's server-side refusal and QUOTE-09's per-visitor identity, both provable without
a network, a database or a Cloudflare account.
Output: `hmac.ts`, `lock.ts`, `vamos-qs.ts`, their tests, and the phase's whole binding surface.
</objective>

  <behavior>
    - `canonicalJson({ b: 1, a: 2 })` and `canonicalJson({ a: 2, b: 1 })` produce the identical string.
    - Nesting is canonicalised recursively; arrays keep their order (an array's order IS data).
    - `undefined`-valued keys are omitted; explicit `null` is kept — the two are different facts about a pinned input.
    - `canonicalJson` throws on a value it cannot canonicalise deterministically: a `Date`, a `Map`, a `Set`, a function, a `BigInt`, `NaN`, `Infinity`, `-0`.
    - The output contains no whitespace at all.
    - `base64urlEncode`/`base64urlDecode` round-trip arbitrary bytes, emit no `+`, `/` or `=`, and `base64urlDecode` throws on a character outside the base64url alphabet.
    - `signHmac(secret, message)` is stable: the same pair always yields the same MAC.
    - `verifyHmac(secret, message, mac)` is `true` for a matching pair and `false` for every mismatch, including a MAC of the wrong length and a truncated MAC — it never throws for a malformed MAC.
    - A one-bit change anywhere in the message flips verification to `false`.
  </behavior>
  <action>
    Create `apps/web/lib/crypto/hmac.ts` exporting the five functions in this plan's
    `must_haves.artifacts`. Doc-header in the `logger.ts` two-hard-rules style, citing D-24, D-28
    and D-36, and stating the negative space: this module holds no secret, reads no `env`, calls no
    clock, and knows nothing about quotes or cookies — it is the one place a signature is computed
    and the reason there is exactly one canonicalisation in this codebase.

    Two hard rules to write into the header and honour in the code:
      1. Verification uses `crypto.subtle.verify`, never a manual byte comparison. WebCrypto's
         verify is constant-time by contract; a hand-rolled `===` over two hex strings leaks the
         position of the first differing byte to a timing attacker. This is not theoretical for a
         token an attacker can submit 8 times a minute.
      2. `signHmac` and `verifyHmac` operate on the ALREADY-ENCODED payload segment, never on the
         object. Verification must never re-canonicalise attacker-supplied JSON before checking the
         MAC, or a canonicalisation difference between mint and verify becomes a forgery.

    Implement `canonicalJson` as a recursive serialiser: objects emit `{` + sorted `"key":value`
    pairs joined by `,` + `}`; arrays emit `[` + elements + `]`; strings via `JSON.stringify` on the
    string alone (so escaping matches the spec exactly); numbers only when `Number.isFinite` and not
    `-0`; `true`/`false`/`null` literally. Throw a `TypeError` naming the offending path for
    anything else. Comment why a `Date` throws rather than being ISO-serialised: an implicit
    `toISOString` would make two structurally different payloads sign identically, and the caller
    should be forced to decide the string form of a timestamp it is pinning.

    Use `crypto.subtle.importKey("raw", …, { name: "HMAC", hash: "SHA-256" }, false, ["sign"])`
    (and `["verify"]` for the verify path), `extractable: false`. Encode with `TextEncoder`.
    Base64url via `Uint8Array` ↔ binary string ↔ `btoa`/`atob` with the three-character substitution
    and padding strip; both are available on Workers and in the Vitest `node` environment used by
