<objective>
Connect the pure kernel to the frozen book — through the one door that exists, on the one binding
that is allowed.

Two things could go quietly wrong here and both are billing bugs. Loading the rate book on the
cached `HYPERDRIVE` binding would put a ~75-second lag between the owner typing
`UPDATE rate_versions SET status='live'` and the engine noticing — acceptable for a review, not for
a charge decision. And letting `PRICING_PREVIEW` set `pricing_live` would make a staging draft look
chargeable, which is exactly the confusion the flag exists to avoid.

Purpose: QUOTE-03's "price every eligible class from a frozen version" and QUOTE-10's
`pricing_live=false` path, both as the DEFAULT behaviour rather than a special case.
Output: the mapping, the four wrapped RPC calls, and the composed load-and-price step.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hyperdrive cache → the `pricing_live` decision | A cached answer to a question whose answer changes at launch |
| Staging environment variable → production behaviour | One `wrangler.jsonc` file describes both |
| Database jsonb → kernel arithmetic | Where a `numeric` could silently become a float |
