## Phase Boundary

Every production folder is reviewed, one unit at a time. Confirmed bugs are fixed with a test
that fails before and passes after. Then code is simplified — reuse, dead code, needless
abstraction, wasted work — without changing what anyone sees or pays. Each unit: its own plan,
its own commits, its own line in the review record.

Planned against **the state after 26.0**: CI covers the booking funnel, `/dev/*` decided, the
visual-test baseline settled per the owner's 26.0 rulings. Plan 26.2-01 re-reads that state
before any unit starts; if 26.0 left something open, it is listed there, not guessed here.
</domain>

<decisions>
## Implementation Decisions

- **D-01 (owner):** Whole codebase, folder by folder, safest first, booking path last.
  Includes the live DC surfaces — `app/home/*.dc.html` (home is the live DC page),
  `app/pages`, `app/ops/*.dc.html` (the dashboard) and `app/vamos-*.js` — because they run on
  vamostaxi.site and dashboard.vamostaxi.site today.
- **D-02 (owner):** On the **booking path** (home box → `/checkout` → Stripe hosted page →
  return → "Booked", the webhook, the settle queue, the hourly purge and resend, pay links,
  Take card, extra-fare pay) **only confirmed bugs are fixed**, each with the owner's OK at the
  plan gate of that unit. No tidying there. Tidying is allowed everywhere else.
- **D-03:** Simplification changes no rendered output, no copy, no route, no API contract, no SQL
  behaviour. Proof per unit: tests green, and for UI units the same screenshots before/after at
  1440/1024/768/390.
- **D-04:** Applied migrations are never edited. A database finding becomes a new migration
  (applied verbatim with the Ship, read back, per `CLAUDE.local.md`) or a written deferral.
- **D-05:** Every commit passes `pnpm typecheck`, `lint`, `lint:css`, `test:unit`, `i18n:check`,
  `check:numbers`, `check:db-fences`, `check:public-env`, `check:legal-claims`. Nothing skipped,
  disabled or deleted to get green. A test is deleted only with the dead code it tested.
- **D-06:** Security-looking findings are written down and handed to Phase 20 (which runs
  next), unless they are plain bugs with an obvious fix; serious ones (Phase 20 D-17 meaning) are
  reported to the owner the same day.
- **D-07:** Design laws hold: no glow, no tinted yellow, tokens only, four languages, amounts from
  the price book as the owner set them — never an invented rate, CHF figure or legal line.
- **D-08:** Must-nots: no `sk_live_`, no `vamostaxi.eu`, no deploy, no `db push`, no Publish.
  One branch for the phase, cut from origin/main of that moment; hand-over to the control session.
