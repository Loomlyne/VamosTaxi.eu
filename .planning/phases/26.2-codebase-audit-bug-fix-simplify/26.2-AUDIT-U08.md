## Correctness

### U08-1 · A date filled from a flight reads "August" with the wrong weekday
- **File:** `app/home/home.dc.html:2281` with `:1418`. The writers are `:1616`, `:1667`, `:1676`.
- **What:** `const dateStr = s.dayLabel || (s.day ? this.fmtDate(s.day) : '');`, and `fmtDate(day) { … return dow[(day - 1) % 7] + ' ' + day + ' ' + t.mon; }`. `t.mon` is the fixed string `'Aug'` (`:872`; `'Aug.'`, `'août'`, `'أغسطس'` in the other languages), and the weekday is taken from the day of the month as if every month were August 2026. Three paths set a real `dayY`/`dayM` but `dayLabel: null`: the flight second-beat fill (`:1616`), the flight refresh (`:1667`) and `applyPendingTime` (`:1676`). `dateStr` goes to `WhenPicker value` (`:480`) and to `BookingSheet dateLabel` (`:593`).
- **Failure:** a customer picks ZRH as pickup and enters a flight landing Wed 14 Oct. The When field fills with "Fri 14 Aug", on desktop and in the phone sheet. The checkout strip (`whenLabel`, `:2301`, built with `Intl`) shows the right date, so the two disagree. This needs the flight API to return a plan; not reproduced on live.
- **Fix:** replace the fallback with `whenText(s.dayY, s.dayM, s.day, '', s.lang)` (already in the file, `:1166`). Then delete `fmtDate`, `dowRef` and `mon` from the four tables.

### U08-2 · One failed bookings poll empties the dashboard board
- **File:** `app/vamos-ops-data.js:191-203`, with `pickRows` at `:42-43`.
- **What:** `readyPromise = api("GET", base).then(function (json) { pending = false; loaded = true; list = pickRows(json, name).map(clean); emit(name); schedulePoll(); });`. `pickRows` returns `[]` for `{ok:false}`, and the API client turns every network error or non-JSON response into `{ok:false}`. Bookings re-hydrate every 3 s (`:164-178`), and also on focus and visibility.
- **Failure:** you have the board open, and a Wi-Fi blip or a single 5xx hits a poll. Every booking disappears and the empty state shows for 3 s, or until the next good poll. An open row loses its data under you. `rateBookCollection.hydrate` (`:394-405`) already handles this correctly: it keeps the list and leaves `loaded=false`.
- **Fix:** in `hydrate`, `if (!json || json.ok === false) { pending = false; schedulePoll(); return; }` before replacing `list`. Keep the D-35 "first load starts empty" behaviour: `list` is already `[]` at first load.

### U08-3 · A failed first reviews load stays empty for the life of the page
- **File:** `app/vamos-reviews.js:154-163`.
- **What:** `api("GET", listPath()).then(function (json) { pending = false; loaded = true; list = pickRows(json).map(fromApi); emit(); });`. On failure `loaded` latches to `true`, so `all()` and `published()` never ask again.
- **Failure:** on the public home, one failed `/api/reviews` hides the Trustpilot mark (`home.dc.html` `trustSummary`) and the reviews row until reload. On the dashboard Reviews screen, a failed load shows "no reviews". You could re-enter reviews that already exist.
- **Fix:** set `loaded = true` only when `json && json.ok !== false`. Otherwise leave it `false` so the next `all()` retries.

### U08-7 · Horizontal wheel over the reviews row is taken over
- **File:** `app/home/Reviews.dc.html:314-340`, bound `{ passive:false }` at `:292`.
- **What:** on a horizontal gesture, `if (e.cancelable) e.preventDefault(); e.stopPropagation(); … this.nudge(delta * 2.4);`. Vertical scrolling is left native, which is correct.
- **Failure:** a trackpad side-swipe over the reviews row moves 2.4 times faster than the browser would, through custom code. The law says wheel and trackpad scrolling stay browser-native on every surface.

### U08-9 · Components read `vamosLang`/`vamosCurrency` straight from localStorage
- **Sites:** `app/home/home.dc.html:832, 1175, 1178`; `app/home/SiteHeader.dc.html:348-349` (and the `pages/` copy); `app/home/HowItWorks.dc.html:1634`; `app/pages/AuthForm.dc.html:575`; `app/pages/ResetForm.dc.html:179`; `app/pages/checkout.dc.html:211` and `confirmation.dc.html:133` (not served); `app/ops/AuthForm.dc.html:468`; `app/ops/OpsSidebar.dc.html:155`; `app/ops/OpsSoon.dc.html:38`; `app/ops/OpsBoard.dc.html:228`.
- **What:** these are initial-state or bootstrap reads. Each component also listens to `vamos:locale` or `VamosLocale.onChange`, so it does relabel after a switch. The fallback writes (`home.dc.html:1466-1467`, `SiteHeader.dc.html:517, 523`) run only when `VamosLocale` is missing. Nothing reloads.
- **Failure (narrow):** `VamosLocale.read()` also honours the legacy `vamos.lang` key and validates the currency (`CURS[cur]`). The raw reads do neither. A visitor with only the legacy key, or a stale currency, starts in a state that differs from `VamosLocale` until the first `vamos:locale` event. `home.dc.html:832` sends the raw value to `/api/flight` as `locale`.
- **Fix:** `window.VamosLocale ? VamosLocale.lang() : 'en'` (and `.cur()`) at each site.
