<objective>
Port the eight form controls — the layer every booking, checkout and ops screen is built from —
with their focus, error, disabled and selected states intact and their copy resolving in four
languages.

Purpose: these are the controls a traveller touches one-handed at an airport, and the phase's
focus rule has a deliberate exception here that is easy to lose in a port: a text field's focus
signal is the charcoal border alone, because a yellow halo around a pill field reads as an error.
Getting that wrong across eight controls is the kind of thing a screenshot diff catches only if the
focus state is diffed, which is why every marked state gets its own baseline.

Output: eight typed, statically styled controls, reviewable side by side in four languages.
</objective>

    assistive-technology labels exactly like visible text.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor keyboard/pointer → form control | The first user-input surface in the product; real submission arrives in Phase 5 |
| caller-supplied error and hint strings → rendered DOM | Message text becomes page content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-24 | Tampering | caller-supplied error/hint strings | medium | mitigate | Error and hint props render as text nodes, never as raw markup, so a message sourced from a future server response cannot inject elements |
| T-01-25 | Elevation of Privilege | a disabled control still emitting a change | medium | mitigate | Disabled is asserted at the element level, not by styling alone, so a disabled control cannot be focused or changed by keyboard or script-driven click |
| T-01-17 | Tampering | ported CSS carrying a banned surface | medium | mitigate | Every forms file is asserted free of the banned yellow scale steps; the Plan 03 lint gate blocks the merge |
| T-01-26 | Information Disclosure | no input validation in this phase | low | accept | These controls process no submission and reach no server; validation and challenge protection are Phase 5's requirements. Accepted at ASVS L1 for a phase with no submission surface |
</threat_model>
