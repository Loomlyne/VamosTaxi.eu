<objective>
Complete the i18n runtime: the compatibility contract the platform rules mandate, the client-only
currency store, the booking draft persistence that makes the language switch survivable, and the
alternates and sitemap generated from one route list.

Purpose: ADR-001 names one condition under which its whole URL-segment approach is wrong — if a
half-filled booking widget cannot survive a language switch, language moves to a cookie. That test
is this plan's centre, not a nice-to-have at the end of it. The rest of the plan is the contract
that keeps every call site in every later phase working the way the platform rules already describe.

Output: a language switch that relabels in place and loses nothing, a currency switch that touches
only the mark, and search-engine alternates that cannot drift from the sitemap.
</objective>

  <action>
    ADR-001 replaces the mechanism, never the contract. CLAUDE.md mandates that contract
    platform-wide, so every function name, every subscription behaviour and the never-reload rule
    survive this port — what changes underneath is that language is now a route segment and strings
    resolve at render time instead of by walking the DOM afterwards.

    `locale-shim.ts` exposes the same surface the mock runtime does: read the active language and
    currency, set either, subscribe to changes with an unsubscribe returned, and format an amount.
    The language setter performs a soft navigation to the same path under the new segment — never a
    reload, and never a full document replacement, because that would discard exactly the state the
    next task is about. The subscription notifies on both language and currency changes, so existing
    call-site patterns keep working unchanged.

    `currency-store.ts` is deliberately client-only. D-16's reasoning is worth preserving in a
    comment: putting currency in a cookie would make every cached page vary four ways for a purely
    presentational choice. The server always renders the Swiss-franc mark and hydration swaps it,
    and the accepted cost is one frame of the wrong mark for a non-Swiss-franc visitor. Port the
    currency table from the mock runtime — symbol, spacing and name per currency — and the rule that
    matters most: the formatter swaps the mark and never touches the number. Until the real matrix
    lands the number is the placeholder figure; the charge is always Swiss francs regardless of what
    mark is displayed, which is the whole point of the display-only ADR.

    Mount both in the client boundary Plan 01 created, so no page has to wire them and no later
    phase has to remember to.

    Nothing anywhere may read the browser storage keys directly. That is a rule in CLAUDE.md and it
    is what makes the store swappable; assert it rather than trusting it.
  </action>

  <action>
    This is the task ADR-001 says the whole URL-segment decision stands or falls on.

    The cost ADR-001 accepts is that a soft navigation remounts the page subtree, so component state
    below the segment does not survive a language switch. For most pages that is invisible. For the
    booking widget it would mean discarding a half-filled form the moment a traveller switches to
    their own language — which is precisely the moment they are most likely to switch.

    `booking-draft.ts` is the fix and it is production code, not scaffolding: a typed draft shape
    covering the widget's fields — pickup, destination, date, time, passengers, luggage, flight
    number — persisted to session storage. Session storage rather than the URL because D-15 keeps
    pickup addresses and flight numbers out of the address bar, browser history and referrer headers,
    which is personal data the Swiss and European data-protection positions would rather not have
    there. Phase 4 extends the same store with the quote it computes; nothing about its shape here is
    provisional.

    `BookingDraftFields.tsx` renders those fields with the ported form controls, and the detail that
    makes or breaks the test: it reads its initial values **from the store on mount**, not from a
    state literal. RESEARCH Pitfall 6 is explicit that a state literal looks correct and gets reset
    by the remount, so the failure is invisible until someone actually switches language mid-form.
    Write to the store on change, not on unmount, so a switch mid-keystroke cannot lose the last
    field. Render it on the tracer page so the test has a real surface.

    Then write the acceptance test exactly as ADR-001 words it: fill the fields partially, switch
    language, assert every field's value survived. Run it in both directions, including into Arabic
    where direction flips as well. Add the return-visit half: close the page, reopen it, and assert
    the language choice persisted while the draft behaved as session-scoped storage should.

    If this test cannot be made to pass cleanly, ADR-001's own text says the correct response is to
    escalate and re-open the language-in-the-URL decision — not to ship a workaround. Say so in the
    summary if it happens.
  </action>

    includes a dev-only gallery route.

    the hydrated DOM — a hydrated assertion would pass even if the server had sent English and the

    each of the four languages assert the language and direction attributes and a known translated

    and assert the alternates block is present with all four plus the default.

    switch currency, capture it again, and assert the digit sequence and separators are byte

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| booking draft → browser session storage | Pickup addresses and flight numbers are personal data and are held client-side |
| language setter → router | A setter that accepted an arbitrary target could navigate anywhere |
| currency state → server | The boundary this plan deliberately never crosses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-31 | Information Disclosure | booking draft contents in the URL, history or referrer | high | mitigate | D-15 keeps the draft in session storage, never in the address bar; asserted by the absence of draft fields from any query-string construction. Session scope means the values do not survive the tab, which is the correct retention for pre-booking personal data |
| T-01-02 | Tampering | the language setter's navigation target | high | mitigate | The setter navigates to the current path under a locale drawn from the fixed four-locale routing object, never from caller-supplied input, so it cannot be used as an open redirect |
| T-01-32 | Information Disclosure | dev gallery routes indexed via the sitemap | medium | mitigate | Both the alternates helper and the sitemap walk one shared public-route list from which the dev routes are absent; asserted against the served sitemap |
| T-01-33 | Tampering | a displayed currency mark implying a different charge currency | medium | mitigate | The formatter swaps the mark only; the number never changes and the charge is always Swiss francs. The currency spec asserts byte-identity of the digits across a switch |
</threat_model>
