      name, anywhere in authored CSS. This is Law 02 plus the glow token at lint time. Write the
      banned names into the config from `laws.css`'s own alias block so the two lists cannot drift.

    Add a short `messages` override on each rule pointing at the law it enforces and at `CLAUDE.md`,
    so a failure reads as a rule of the product rather than a lint nag.

    Then run it against the tree Plan 01 left behind and fix what it finds in `Button.css` by
    converting physical properties to logical ones — never by relaxing a rule or adding a disable
    comment. If a rule and the design system genuinely conflict on a value, that is a finding to
    surface in the summary, not to silence.

  <action>
    Write the build-time replacement for `VamosLocale.coverage()`, which has no server-side
    equivalent because it walked the DOM. D-17 asks for two enforcement points; this script is the
    blocking half.

    RESEARCH's package audit rates the off-the-shelf candidate for this SUS — created in 2025,
    single-vendor, narrow purpose — and its own "Don't Hand-Roll" table names cross-locale key
    coverage as the honest exception where a small in-repo script beats a young dependency. So this
    is a script, deliberately, and that is why this phase installs no flagged package and needs no
    package-legitimacy checkpoint.

    Three checks, each with its own exit message naming the requirement it enforces:

    1. **Coverage (I18N-01).** Flatten each of the four message files to dotted key paths. English
       is the authority. Report every key present in English and absent from German, French or
       Arabic, and every key present in a non-English file and absent from English (an orphan left
       behind by a rename). Exit non-zero if either list is non-empty. Zero keys in all four files
       is a pass, not a crash — the tracer seeded only a handful and the migration lands in Plan 10.

    2. **Usage (I18N-01).** Walk `apps/web/{app,components,lib}/**` for translation-lookup calls
       with a literal key argument and report any key that exists in no message file. Skip calls
       whose argument is a variable rather than a literal, and say so in the output rather than
       silently ignoring them, so the gap is visible.

    3. **Parameterisation (I18N-06).** Report any English message whose text contains a bare digit
       run surrounded by words but declares no ICU placeholder. This is the class of bug the mocks'
       regex `patterns` array existed to catch after the fact — a string left English because it
       had a number in it. Catching it at authoring time is the whole point of D-13's move to ICU.
       Allow an inline opt-out marker in the message file for the genuine cases (a booking
       reference, a phone number) and require the marker to carry a reason.

    Also honour ADR-011 and ADR-012 while walking: copy inside a pending-value pill stays English
    on purpose and must not be reported as a coverage gap, and the four product names marked
    non-translatable during the D-18 migration are excluded from all three checks. Read the key
    that marks them from the message files rather than hardcoding the names in the script.

    Print a single-line summary of counts on success so a green run still tells the reader how many
    keys were checked.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party CDN → CI runner | The mock side of the diff used to fetch executable JavaScript from a package CDN |
| vendored test runtime → repository | Downloaded executable JavaScript now lives in the repo and must be provenance-recorded |
| message files → rendered HTML | Untrusted-looking content is authored copy, but a missing key must not leak a raw key path to a visitor |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering | mock-side test runtime | high | mitigate | React/ReactDOM/Babel vendored locally with recorded version, licence and SRI hash; the Playwright run asserts no non-localhost request, so the gate cannot silently start trusting a remote origin again |
| T-01-09 | Tampering | vendored test runtime imported by production | medium | mitigate | `tests/vendor` is asserted absent from every import under `apps/web/app` and `apps/web/components` |
| T-01-10 | Information Disclosure | missing translation key rendered to a visitor | low | accept | D-17's production behaviour is an English fallback, never a raw key; the coverage gate makes a missing key a merge failure, so the fallback path is a backstop rather than a routine outcome. Accepted at ASVS L1: no confidential data is carried by a key path |
| T-01-SC | Tampering | npm installs | high | mitigate | No package is installed by this plan beyond what Plan 01 already vetted; the key-coverage tool RESEARCH rated SUS is deliberately replaced by an in-repo script |
</threat_model>
