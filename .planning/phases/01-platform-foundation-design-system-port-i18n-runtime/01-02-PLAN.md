<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contributor working tree → repository | Credentials can be committed here |
| repository → GitHub Actions runner | The runner receives the Cloudflare token; a compromised Action reads it |
| build output → browser | Anything inlined into the client bundle is public |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | committed files, client bundle | high | mitigate | gitleaks at pre-commit and as the first CI job (before any artifact is produced); `check-next-public-allowlist.mjs` fails the PR on any undeclared client-exposed variable and scans the built assets for forbidden credential names; both gates are blocking per D-39 |
| T-01-SC | Tampering | third-party GitHub Actions | high | mitigate | Every `uses:` reference pinned to a full commit SHA with the version in a comment; verified mechanically in all three workflows. No `[ASSUMED]`/`[SUS]` npm package is installed by this plan |
| T-01-06 | Elevation of Privilege | production deploy workflow | high | mitigate | The production workflow triggers on a tag pattern only; a branch-push trigger is asserted absent, so no merge to `main` can publish to the apex before Phase 11 |
| T-01-07 | Tampering | concurrent CI runs on one ref | medium | mitigate | Every workflow declares a `concurrency` group: PR runs cancel in progress, deploy runs queue rather than race |
| T-01-08 | Repudiation | a gate silently no-opping | medium | mitigate | The pre-commit hook fails loudly when the scanner binary is absent rather than passing; no step may declare `continue-on-error`, asserted across the whole workflows directory |
</threat_model>
