# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Framing.** Phase 1 ships no finished product page — it ships the *foundation*: the 33-component
Vamos design-system port, the SSR-safe i18n runtime, and a dev-only states gallery. There is
therefore almost nothing to invent here. The palette, type, spacing, radii, motion, copy voice and
component inventory are already fixed by `design-system/` and `CLAUDE.md`; this document exists to
turn "port the design system" into a contract precise enough for a screenshot-diff gate, a
component-state checklist and an RTL/German pass to arbitrate — not to make new visual decisions.
Every value below is sourced from an existing file, cited inline. Nothing was invented.

## Component Port Fidelity Contract

What "pixel-identical to the `.dc.html` source" (Roadmap Phase 1, success criterion 2) means
precisely enough for the CI screenshot-diff gate (D-25) to arbitrate a PR:

| Dimension | Contract |
|-----------|----------|
| **Source of truth** | The rendered `.dc.html` mock in `app/`, never `design-system/_ds_bundle.js` read as prose — the bundle is reference-only (D-30) and is itself just the mock's dependency. |
| **Diff mechanism** | `@playwright/test`'s `toHaveScreenshot()`, one baseline per component **and per variant** declared in that component's `data-props` (D-29). Both sides (the `.dc.html` mock and the React port) render from a **locally vendored copy of React/ReactDOM/Babel** for the diff job (D-25 as amended) — no `unpkg.com` network egress, so a CDN hiccup cannot fail an unrelated PR (Open Question 3, `01-RESEARCH.md`). |
| **Viewports** | The four fixed breakpoints the whole project is checked at: **1440, 1024, 768, 390px** (`.claude/CLAUDE.md` § Responsive Design). A component whose layout genuinely does not change across breakpoints (e.g. `Badge`, `Icon`) may be diffed at 1440 and 390 only; anything with a responsive layout rule (`Table`, `SiteHeader`-composed patterns, `VehicleCard` grids) is diffed at all four. |
| **States per shot** | Every state in that component's row of the Component State Matrix below gets its own baseline — `default`, and additionally `hover`/`press`/`focus`/`selected`/`disabled`/`loading`/`empty`/`error` wherever that row marks ✓. A component is not "ported" until every ✓'d state has a passing diff, not just `default`. |
| **Tolerance** | `maxDiffPixelRatio: 0.01` (1%) per screenshot, Playwright's animations disabled (`animations: 'disabled'`) so in-flight motion (hover transitions, dialog entrance) never causes flake. **This exact ratio is a default, not yet owner-confirmed — the planner may tighten or loosen it once the first baseline set is reviewed.** |
| **Deterministic fonts** | Qurova, Poppins and the Arabic face must be fully loaded before either side's screenshot is taken (`page.waitForFunction(() => document.fonts.ready)` or Playwright's built-in font-ready wait) — a font-swap mid-capture is the single most likely source of screenshot flake in this stack. Font files are self-hosted (D-10, D-31), so this is deterministic across CI runs by construction, not a fallback to system fonts. |
| **Class-name identity** | The React port must emit the exact same `.vt-*` class names as the mock (D-24) — this is what makes "pixel-identical" *structural* rather than eyeballed. A diff failure whose root cause is a renamed class is a port bug, not a tolerance-tuning problem. |
| **CSS delivery** | Per-component CSS is **extracted** from the bundle's `injectStyles()` template-literal call into a static `.css` file the component statically imports (Pitfall 1, D-24 amended) — never the runtime `injectStyles` mechanism, which no-ops under SSR and would fail the diff on first server-rendered paint (flash of unstyled content). |
| **What counts as acceptable diff** | Anti-aliasing/sub-pixel differences under the tolerance ratio only. A diff caused by a missing state, a wrong token value, a renamed class or a layout shift is never "acceptable" — it blocks the PR (D-39: the screenshot-diff gate is blocking, not advisory). |

## Four-Language Layout Contract

**German (~30% growth).** Components whose text can realistically overflow, and the contract for each:

| Component | Risk | Contract |
|---|---|---|
| `Button` | UPPERCASE CTA labels grow ~30% in German | Pill width is intrinsic to content (`padding` + `width:auto`), never a fixed pixel width — the pill grows, it never truncates or wraps mid-word |
| `Tabs` | Tab labels | Same rule — flexible width per tab; if the row would overflow the container at 1080px German, `Tabs` scrolls horizontally rather than wrapping vertically (matches the project's existing "tables scroll, page chrome does not" pattern) |
| `Tag`, `Badge`, `StatusBadge` | Fixed-feeling pill shape with short labels | Must be sized to the **longest German lifecycle label** (e.g. "Zurückerstattet" for `refunded`), not the English one — verify at the German 1080px manual pass (`01-VALIDATION.md` Manual-Only Verifications) |
| `Table` headers | UPPERCASE column labels | Same horizontal-scroll fallback as `Tabs`; column min-width should be set from the German label, not English |
| `Input`/`Textarea`/`Select` labels & hints | Field kickers and hint text | `min-width:0` on the label/hint flex child (established pattern, `.claude/CLAUDE.md` § Responsive) so text wraps rather than clipping |
| `Alert`, `Toast` body copy | Longer instructional sentences | Body containers must not clamp to a fixed line count — allow natural wrap |

**Arabic (RTL).** Components with directional affordances, split by what must mirror and what must not:

| Must mirror (flip with `dir="rtl"`) | Why |
|---|---|
| `Tabs` / `StepIndicator` progression chevrons | Forward motion is inherently directional — "next" points toward reading direction |
| `IconButton` back/forward, `chevron-left`/`chevron-right` glyphs anywhere | Same reasoning |
| `RouteSummary`'s origin→destination arrow/icon | The visual journey direction must match reading direction |
| `ProgressIndicator` fill direction | Fill grows toward reading direction, not a fixed screen-left origin |
| `DatePicker` calendar nav chevrons | Same as Tabs |
| Any icon-plus-label pair using logical `margin-inline-start`/`padding-inline` | Enforced by the D-21 stylelint gate (`stylelint-use-logical`), not manual judgement |

| Must NOT mirror — carries `.vt-dir-keep` (`tokens/laws.css` law 03, `design-system/readme.md` §9) | Why |
|---|---|
| `CHF` amounts and all figures (`PriceSummary`, `StatTile`, `Counter` values) | Numerals stay LTR regardless of surrounding language, per the existing `vamos-locale.js` contract |
| Flight numbers, booking references (`VT-4821` pattern) | Codes are never mirrored |
| Times and dates (`DatePicker` selected value display) | Same reasoning |
| Phone numbers (the header's `tel:` pill) | Already `dir="ltr"` in the mock (`app/pages/coming-soon.dc.html`'s phone link) |

**Verification split** (per `01-VALIDATION.md`): the *mechanism* (no physical `left`/`right`
properties, `dir="rtl"` present in server-rendered HTML) is CI-enforced (D-21). Whether the
mirrored result actually *reads correctly* — nothing clipped, no text left-aligned inside a
mirrored container — is manual-only, checked per surface at 1440/1024/768/390px in `/ar`
(`01-VALIDATION.md` § Manual-Only Verifications). The dev gallery's real-locale-switch design
(above) is what makes that manual pass practical for a 33-component surface in one sitting.

## Focus, Motion & Reduced-Motion Contract

Sourced from `tokens/laws.css`, `tokens/elevation.css`, `tokens/motion.css` and the mocks' own
inline law-enforcement CSS (`app/pages/coming-soon.dc.html`, `app/pages/SiteHeader.dc.html`).

| Behaviour | Contract |
|---|---|
| Hover | A colour step only — primary buttons step to `--vt-accent-hover` (`--vt-yellow-500`), secondary to `--vt-charcoal-800`, ghost/outline to `--vt-grey-50` fill + charcoal border, rows to `--vt-grey-50`, links to `--vt-charcoal-700`. **Never** a shadow or glow change. |
| Press | Colour steps further (`--vt-accent-press` / `--vt-yellow-600`) **plus `translateY(1px)`**. Never a scale transform. |
| Focus (buttons, checkboxes, rows, cards) | `--vt-ring` — `0 0 0 3px rgb(253 194 11 / 0.45)` (`tokens/elevation.css`). Always visible; the product is used one-handed at an airport (`design-system/readme.md` §3 States). |
| Focus (text inputs — Input, Textarea, DatePicker field, Select trigger) | **Exception to `--vt-ring`.** The signal is the charcoal border alone: `.vt-input.vt-input--focus{box-shadow:none}` and `.vt-dp__field:focus-visible{box-shadow:none;border-color:var(--vt-charcoal-900)}` (`tokens/laws.css` law 01) — a yellow halo around a pill field reads as an error, not a focus state. |
| No-glow enforcement | `--vt-shadow-accent:none` is set in every component's own `:root` block, neutralising the design system's legacy yellow button-hover glow (`--vt-shadow-accent` itself still exists in `tokens/elevation.css` as `0 8px 22px rgb(253 194 11 / 0.34)` for reference/history — it must never be *applied*, only aliased away). D-32 additionally enforces this at **lint time**: stylelint fails the build on any coloured `box-shadow`, on `--vt-shadow-accent`, and on `--vt-yellow-50/100/200/300`/`-600/-700` in app CSS — runtime neutralisation alone is not sufficient across 33 ported components. |
| Transition timing | 80ms press · 140ms hover/focus · 200ms toasts/dialogs · 320ms sheets (`design-system/readme.md` §3 Motion). Easing `cubic-bezier(.2,0,.2,1)` standard, `cubic-bezier(.16,1,.3,1)` for entrances. Nothing scales, nothing springs, nothing loops. |
| `prefers-reduced-motion` | Honoured globally (`tokens/base.css`, PLAT-05). Lenis's own reduced-motion handling ports as-is from `assets/lenis-boot.js`'s house settings — this phase preserves it (via the `lenis` npm package + `lenis/react`), it does not rebuild it. Every `@keyframes`-driven entrance (header float-in, dialog rise-and-fade) gets a `@media (prefers-reduced-motion:reduce){ animation:none }` companion rule, per the pattern already in every mock. |
| Lenis | Single instance per page (PLAT-05), lerp 0.12, no bounce, `anchors:true`, `allowNestedScroll:true`, native touch/keyboard/scrollbar-drag, stops while a sheet locks the body. Mounted once in the client root layout; explicitly stopped/reset on `usePathname()` change so scroll position does not desync across Next.js client-side navigations (Pitfall 7, `01-RESEARCH.md` — the exact `lenis/react` API call should be re-verified against the pinned package version at implementation time). `data-lenis-prevent` on any panel owning its own scroll (tables, future ops board, code blocks). |

## Accessibility Contracts

| Requirement | Contract |
|---|---|
| Focus visibility without glow | Every interactive component's focus state must be visible (the `--vt-ring` or charcoal-border rule above) — "no glow" is a colour/blur constraint, not licence to make focus invisible. The global fallback rule `:focus-visible:not(input):not(select):not(textarea):not(.vt-btn){outline:3px solid rgb(253 194 11/.45)!important;outline-offset:3px}` (present in every mock's `<style>` block) ports verbatim as the catch-all for any element the component set doesn't otherwise style. |
| Contrast — yellow on charcoal / charcoal on yellow | The design system already constrains this rather than leaving it to per-surface judgement: **"Charcoal on yellow. White on yellow only at display size"** (`design-system/readme.md` §3 Colour) — i.e. small white text directly on `#FDC20B` is never used; only charcoal text on yellow, or white text on yellow at display/heading sizes where stroke weight compensates. The port must not introduce a new white-small-text-on-yellow combination anywhere (e.g. a badge or tag) that the mocks don't already use. |
| Touch targets | 44px minimum for anything a customer taps (`--vt-control-h-md`), 54px for booking-widget fields and primary CTAs (`--vt-control-h-lg`) — enforced by using the design system's own control-height tokens, never a custom height. |
| `aria-label`/`title`/`alt` in i18n coverage | These four attributes participate in string coverage exactly like visible text (I18N-01) — the D-17 build-time CI check (asserting every `en.json` key exists in `de`/`fr`/`ar`) must be wired to catch attribute-sourced keys too, not just JSX text content. The `Icon` component in particular renders no visible label of its own — every usage site's `aria-label` (when the icon isn't purely decorative) is a translatable string, not a hardcoded English default. |
| Decorative elements | `CheckerMark`, purely decorative icons, and the checker-tile pattern get `aria-hidden="true"` (already the pattern in `app/pages/coming-soon.dc.html`'s `<img data-cs-mark aria-hidden="true">`) — ported verbatim, not re-decided. |

## Typography

|------|------|--------|-------------|

| Body sm / xs | 14px / 13px | 400 | 1.6 (13px is the body-copy floor, never smaller) |

`--vt-font-body: "Poppins",system-ui,-apple-system,"Segoe UI",sans-serif`. Arabic mode swaps in

**This phase's actual typography surface** is narrow: the dev gallery (English only) and any
404/error copy. No new type roles are introduced — the port carries the existing 4-tier scale
(body/label/heading/display) and the separate figure scale verbatim.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~60%) | `--vt-bg-page` (`#F6F6F6`, grey-50) / `--vt-white` | Page backgrounds, default card surfaces — the two neutral grounds every screen is built from |
| Secondary (~30%) | `--vt-charcoal-900` (`#1E1F1F`) | `SiteHeader`/`SiteFooter` grounds, inverse cards, hero/voucher/trust-block surfaces, the future ops sidebar. Two background colours per screen maximum (`readme.md` §3) — white/grey-50 and charcoal, never a third. |
| Accent (~10%) | `--vt-yellow` (`#FDC20B`) | **Reserved for, and only for:** primary `Button` fill, the focus ring (`--vt-ring`) on non-input controls, active/selected navigation indicator, the `CheckerMark` motif (once per surface, top-right corner), the unread-notification pip/dot pattern (`--hd-dot`), and the yellow-arc CTA veil (marketing sections, once per page — not exercised in Phase 1). **Never** selection state (that's a 2px charcoal border), never a large text field, never a background wash. |

to white/grey and `-600/-700` to charcoal at the token layer (`tokens/laws.css`), *and* D-32 fails
the build at lint time if app CSS references those forbidden values directly, or any tone-tinted
kit default (`Alert tone="accent"`, `ListRow` yellow-50 lead tile, `Badge tone="warning"`) —
runtime aliasing alone is not trusted across 33 ported components (`CLAUDE.md` § "Never use
tinted yellow or brownish surfaces").

**The undecided fourth swatch (`#D4632B` / `--vt-orange`, D-07):** recorded as a token with
**no product-UI usage**. Nothing in this phase — or any phase until the designer states a role for
it — may reach for `--vt-orange` on any surface.

Accent reserved for: primary CTA buttons, non-input focus rings, active nav state, the checker
corner mark, unread-notification indicators, the once-per-page arc CTA band — never "all
interactive elements," never a generic highlight colour.
