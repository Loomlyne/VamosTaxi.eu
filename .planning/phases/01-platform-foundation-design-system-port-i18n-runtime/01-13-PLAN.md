<objective>
Port the shared header and footer — the two components every public page in the product is
required to compose — and mount them so that composition is structural rather than remembered.

Purpose: CLAUDE.md makes these mandatory on every public page and forbids hand-rolling either. The
404 and error pages this phase also ships have to render inside them, and Phase 5's eighteen public
routes inherit them. The header is also where the language and currency switchers live, so it is
where the locale contract from the previous plan meets a real control a traveller uses.

Output: a header with both variants and a working locale switch, a footer, and a layout that puts
both around every page automatically.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| language/currency switcher → router | A switcher that accepted arbitrary input could navigate anywhere |
| footer link destinations → shared route list | Link targets are generated rather than hand-written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Tampering | the header's language switcher | high | mitigate | The switcher offers only the four locales from the routing object and calls the shared setter, which navigates to the current path under a locale drawn from that same fixed set — it cannot be driven to an external target |
| T-01-34 | Spoofing | approximated payment provider marks | medium | mitigate | Marks that have not been supplied are stated in type rather than drawn from memory, so no mark misrepresents an acceptance the business has not confirmed |
| T-01-35 | Information Disclosure | the phone affordance exposing a link target on every page | low | accept | The business phone number is published contact information already on the live site. Accepted at ASVS L1 |
</threat_model>
