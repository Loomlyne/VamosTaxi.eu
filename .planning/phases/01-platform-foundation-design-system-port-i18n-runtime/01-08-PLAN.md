<objective>
Port the vendored smooth-scroll boot into a single client provider that keeps every house rule the
mocks already honour, and add the one behaviour the mocks never needed: staying in sync across
client-side navigation.

Purpose: PLAT-05 is satisfied by preserving the existing boot's behaviour, not by rebuilding it.
`assets/lenis-boot.js` already owns the single instance, the settings, the reduced-motion gate and
the sheet-lock stop. What it has never had to handle is a route change that replaces page content
without a reload — which is every navigation in the ported app.

Output: one smooth-scroll instance per page, provably singular, provably stopped when it should be.
</objective>

  <action>
    Move the vendored boot's behaviour into a client component, using the package form of the same
    engine rather than the script tag. RESEARCH's State of the Art table notes the older
    scoped package name is retired and its functionality merged into the main package, so search
    results using the old name are stale — use the current package and its React entry point.

    Preserve, exactly:
    - The house settings from the vendored boot: lerp 0.12, wheel multiplier 1, smooth wheel on,
      touch left native, anchors handled, nested scroll allowed, self-driven animation frame. These
      are the tuned values CLAUDE.md mandates; do not re-tune them while porting.
    - The body-lock synchronisation. The vendored file detects a lock by reading the computed
      overflow of the document and body elements and watching their style and class attributes for
      changes, stopping the instance while locked and starting it again when released. This is the
      mechanism the "stops while a sheet locks the body" rule depends on, and it is why a dialog
      does not scroll the page behind it. Port the detector and the observer, not just the intent.
    - The reduced-motion gate: when the preference is set, tear the instance down entirely rather
      than running it with a smaller lerp, and re-evaluate when the preference changes mid-session.
    - Regions marked as owning their own scroll continue to be skipped.

    Add what the mocks never needed. RESEARCH Pitfall 7: a single instance mounted once can lose
    sync with scroll position across client-side navigations, because the engine assumes a document
    whose identity does not change while the router replaces page content without a reload. Observe
    the pathname and reset scroll position on change, matching the mocks' own page-transition
    behaviour. The precise API call for this should be checked against the installed package version
    rather than taken from this plan — RESEARCH records it as assumption A1, confirmed in need but
    not in exact surface.

    Export a small `useVamosScroll` hook wrapping programmatic scrolling with the sticky-header
    offset already applied, so no call site hand-rolls the offset and no call site reaches for the
    instance directly. Mount the provider once in `providers.tsx`, which is the client boundary
    Plan 01 created for exactly this.
  </action>

  <action>
    Write the spec `01-VALIDATION.md` maps PLAT-05 to. Four assertions, each covering a rule that is
    otherwise only a claim in a document, all tagged so the narrower grep form runs them alone.

    1. **Singleton.** Navigate, then assert exactly one instance is live. Expose a count from the
       provider for test purposes only — a debug property on the window under a development flag,
       never a public API surface — rather than inferring the count from behaviour.
    2. **Reduced motion.** Run the page in a browser context with the preference set and assert no
       instance is running at all, since the port tears it down rather than softening it.
    3. **Body lock.** Apply the lock the way a sheet does — set the document overflow — and assert
       the instance stops; release it and assert it starts. Do both directions: a lock that never
       releases is as broken as one that never applies, and Phase 5's dialogs depend on the release
       half.
    4. **Navigation.** Scroll down, follow a client-side link to another page, and assert the new
       page starts at the top with the instance still running and still singular. This is the
       behaviour the vendored boot never had to provide, so it is the one most likely to regress.

    Also assert that a region marked as owning its own scroll is skipped, since the ported tables
    and the future ops board depend on it.
  </action>
