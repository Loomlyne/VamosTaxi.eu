<objective>
Port the nine core primitives — the layer every other component composes — from the vendored
design system into typed React components whose CSS is present in the server HTML, and stand up
the dev gallery that is the only place the not-yet-consumed components get reviewed at all.

Purpose: D-27 batches the port primitives-first because `Icon` alone is a dependency of the form
controls, the data components and the transfer composites. Getting this batch right also settles
the two questions that repeat 32 more times: where the CSS lives, and where the prop types come
from.

Output: nine primitives, a reviewable states gallery, and a screenshot-diff suite that fails a
pull request on a pixel regression.
</objective>

  <action>
    Apply the three-step port recipe Plan 01 proved on Button, to the three primitives that carry
    brand assets. `Icon` goes first because every other batch's icon slot resolves through it.

    The recipe, unchanged for all nine: copy the `const CSS` template-literal body sitting above the
    component function into `ComponentName.css` byte-for-byte; write `ComponentName.tsx` with a
    static import of that file at the top, the same destructured parameters and defaults the source
    declares, the same class-name assembly, and the same element tree in JSX; derive
    `ComponentNameProps` from that signature. Drop the style-injection call — it returns early when
    there is no document, so keeping it ships unstyled server HTML. Never reference the vendored
    browser bundle at runtime: it attaches to a browser global and expects a global React, which
    would make the whole UI client-only (D-30).

    The single permitted edit during extraction is converting a physical inline-direction property
    to its logical equivalent, which the lint gate from Plan 03 will insist on anyway. Values,
    selectors and `.vt-*` class names are copied, never rewritten — that is what makes the
    pixel-identity claim structural (D-24).

    Component specifics:

    `Icon` renders as a CSS mask over the vendored Lucide SVG, inheriting `currentColor`, exactly as
    the mocks do — not as a React SVG component, which would be a genuine rendering change from the
    source being diffed against (D-26). Its `name` prop is typed as a union built from the icon file
    names on disk rather than a bare string, so a typo is a compile error and Phase 5 cannot ship a
    silently missing glyph. Source the mask URLs from `public/brand/icons/` that Plan 05 vendored.

    `Logo` renders the brand SVGs, including the two white variants Plan 05 vendored; its variant
    union covers wordmark, lockup and mark across primary, reversed and white.

    `CheckerMark` is decorative pattern only. Port the mocks' assistive-technology treatment
    verbatim — the mock marks it hidden from screen readers and the port does not re-decide that.

    Export all three from the per-category barrel alongside Button. There is deliberately no root
    barrel, so the three sibling batches in Wave 4 never contend for one file.
  </action>
