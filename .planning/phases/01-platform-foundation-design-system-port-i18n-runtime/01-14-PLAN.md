    First, completeness. Assert that every one of D-23's 33 components has at least one committed
    baseline, and that every state its matrix row marks has one too. A component with only a default
    baseline is a component whose disabled or error state can regress unnoticed, which is the exact
    failure the per-state contract exists to prevent.

    Then the tolerance. UI-SPEC is explicit that one percent is a proposed starting value never
    tested against a real baseline set, and that this is the moment to settle it. Re-run the suite a
    few times on an unchanged tree and look at the observed diff ratios: if every stable component
    diffs at essentially zero, tighten the tolerance so a real regression cannot hide under it; if
    a specific component genuinely needs more room — a gradient-free but anti-aliasing-heavy glyph,
    a sub-pixel border — give that one component its own tolerance rather than loosening the global
    number for everything. Record the observed ratios and the final values.

    The rule that governs this, from the fidelity contract: anti-aliasing and sub-pixel differences
    under the ratio are acceptable; a diff caused by a missing state, a wrong token value, a renamed
    class or a layout shift is never acceptable and is a port bug. If a diff is failing, fix the
    port. Do not raise the number to make it pass.

    Finally, the phase-wide passes. Each batch already ran its own German and Arabic check, which is
    where a per-component problem gets caught. What those cannot catch is a cross-component problem
    — a rhythm that breaks when two categories sit together, a mirrored container that only misreads
    once it holds a mirrored child. So run the whole gallery once, end to end, in both languages, at
    all four widths.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| arbitrary URL → application | The not-found path is the catch-all for every unmatched request |
| dev-only routes → production deployment | The gallery must not survive a production build |
| error boundary → visitor | An error page can leak internal detail if it renders what it caught |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-36 | Information Disclosure | the error page rendering caught detail | high | mitigate | The error boundary renders the fixed dictionary copy only; the caught error's message and stack are passed to the structured logger and never to the response body, so an internal path or query fragment cannot reach a visitor |
| T-01-18 | Information Disclosure | dev gallery reachable in production | medium | mitigate | A route-group layout returns not-found on a production build and sets the robots header in every environment; absence from the sitemap and from every alternate set is asserted against the served output |
| T-01-02 | Tampering | unmatched locale segment reaching the not-found path | high | mitigate | The root not-found handles a segment that resolves to no locale, rendering English rather than attempting to load a dictionary for it — closing the last path where an arbitrary segment could reach the loader |
| T-01-37 | Repudiation | a loosened tolerance hiding a real regression | medium | mitigate | The configured ratio is asserted at or below the proposed starting value; a per-component override must carry a recorded reason, and the suite must pass twice consecutively to rule out flake being masked by tolerance |
</threat_model>
