<objective>
Move the whole brand layer into the application so it is served from one origin the WAF controls,
and give Arabic a typeface of its own instead of a hotlink.

Purpose: D-10 makes the Worker deploy self-contained; D-31 rules out third-party script and font
origins because, in the owner's own framing, the traveller is on airport wi-fi and a CDN will not
work for them. RESEARCH Pitfall 8 adds the sharper reason: the mocks' current Arabic font
mechanism discloses every Arabic-page visitor's IP to a company that is not on this site's
subprocessor list, which the nFADP position does not accept.

Output: every token, font, icon, logo and pattern the app renders comes from `public/brand/`, and
`/ar` is typeset.
</objective>

    Give Arabic a real typeface, served from this origin.

    Choose the face first. D-22 delegates the pick between two OFL candidates to whoever plans the
    font task, on how each sits beside Poppins. **Decision: Noto Sans Arabic.** Two reasons, both
    concrete. Its strokes are low-contrast and even, which pairs with Poppins' geometric evenness
    far better than the more calligraphic contrast of the alternative, so a mixed Latin/Arabic line
    does not read as two weights. And it is the face the mocks already render, so the Arabic screens
    the owner has already reviewed do not change appearance underneath a decision that was only ever
    about where the file is served from. RESEARCH's Open Question 2 asks whether the eventual
    designer pick might split display from body; implement one shared token now, matching what the
    mock runtime already does, and record the possible split in the ADR so the designer meets it.

    Download the OFL release of the four weights the mocks use directly from the upstream project —
    not through a webfont service — into `public/brand/fonts/`, alongside the OFL text.

    Write `public/brand/tokens/arabic.css` holding the `@font-face` declarations and a single
    swappable `--vt-font-arabic` token, plus the direction-scoped rule that points the display and
    body font tokens at it when the document direction is right-to-left. This is the same
    token-swap shape the mock runtime already uses, which is exactly D-22's "swappable token"
    design — the designer's eventual face replaces one value and no call site moves. Import it into
    the globals chain above the laws layer, so the laws file stays last.

    Then remove the dependency, don't just add an alternative: the app must never reach a webfont
    service. The mock tree itself stays untouched under D-03 — this is about what the app ships —
    so the check is that no file under `apps/web` references any external font origin, and that a
    real page load fetches every font from this origin.

    Record the licence the way ADR-009 recorded Qurova's: a new `ADR-013` naming the family, the
    exact upstream release and version, the licence and where its text is vendored, the fact that it
    is a stand-in pending the designer's pick, and the subprocessor consequence this change removes
    (which is the reason it is an ADR and not a commit message).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → third-party asset origin | The boundary this plan closes: today an Arabic page load crosses it |
| brand pack on disk → repository | Vendored binaries and SVGs enter the repo and must be provenance-recorded |
| request → image endpoint | A URL parameter selects a source asset and a transform |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Information Disclosure | Arabic webfont delivery | high | mitigate | The Arabic face is self-hosted from `public/brand/fonts/`; a real browser load of `/ar` is asserted to make zero non-localhost requests, so the visitor's IP and user-agent never reach a party outside the subprocessor list (ADR-010, conflict C25) |
| T-01-14 | Tampering | vendored font and icon binaries | medium | mitigate | Fonts and icons are copied from the in-repo brand pack, not downloaded, except the Arabic face which is taken from its upstream OFL release with the version recorded in ADR-013 |
| T-01-15 | Information Disclosure | image endpoint URL parameters | medium | mitigate | The image configuration restricts sources to this origin's own paths; no remote pattern is allowed, so the endpoint cannot be used to proxy an arbitrary third-party URL |
| T-01-16 | Repudiation | licence provenance for a vendored typeface | low | mitigate | ADR-013 records family, upstream release, licence and vendored licence text, matching the precedent ADR-009 set for Qurova |
</threat_model>
