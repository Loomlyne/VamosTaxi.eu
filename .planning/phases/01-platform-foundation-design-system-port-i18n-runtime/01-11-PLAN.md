<objective>
Port the four data components and the four transfer composites — the layer that will carry every
booking, price and route the product ever shows — with their empty, partial and loading treatments
built now rather than discovered when real data arrives.

Purpose: these are the components Phase 4's quote engine, Phase 7's checkout and Phase 8's ops
board all render into. Two of the product's binding rules live almost entirely here: an empty state
is stated in words rather than faked, and an amount's currency mark can change while its number
never does. Both are cheap to build correctly now and structurally awkward to retrofit once three
phases are composing them.

Output: eight composites, typed against a closed lifecycle union, reviewable in four languages.
</objective>

  <action>
    Four composites, each with a specific that goes beyond the recipe. These complete the transfer
    slice of D-23's 33; with this batch the corrected scope is fully ported.

    `StatusBadge` is a pure composition over the ported badge: it derives a tone and an icon from
    the booking status and renders the badge with them. Do not restyle a badge; compose one. Its
    value map in the source is the authoritative list of the nine lifecycle values, and it is
    exported here as a TypeScript union — this is the type Phase 8's board and Phase 9's lifecycle
    both build against, so extract the literal map rather than retyping the values from memory. The
    set is closed: there is no unknown-status fallback to design, because no tenth value can exist.
    An absent status renders no badge rather than an error badge. Every label resolves through the
    dictionary in all four languages.

    `RouteSummary` renders a two-stop rail with labelled stops and an optional meta row. Its source
    hardcodes the two stop labels in English; in the port they become dictionary lookups, which is
    the whole point of I18N-01. Two direction rules meet in this component and both must hold: the
    origin-to-destination rail mirrors under right-to-left because the visual journey follows the
    reading direction, while any time or code inside the meta row keeps its own left-to-right
    direction. It renders a loading state while geocoding and an empty state before a route is
    entered, and it must not collapse when the optional detail lines are absent.

    `PriceSummary` is where the currency rule lives. Never write a currency string into component
    logic — the mark comes from the currency layer and the number does not change when the mark
    does. Until the real matrix lands the amount renders as the placeholder figure, never an
    invented price, and a pending policy value renders as a labelled gap pill rather than a template
    token. It carries loading, empty and error states and a fixture with the discount line absent,
    which must not shift the layout.

    `VehicleCard` composes the card and the button. Selected is a strong charcoal border, disabled
    means the class exceeds the requested capacity, and loading means its price is still computing.
    Its capacity figures keep their direction inside Arabic.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| row and cell data → rendered DOM | From Phase 3 these values originate in the database; the renderer's treatment of them is fixed here |
| status value → badge tone and icon | An out-of-set value must not produce an arbitrary rendering |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-28 | Tampering | cell and row values rendered as markup | medium | mitigate | Cells render as text nodes, and a custom cell renderer receives typed row data rather than a markup string, so database-sourced values cannot inject elements once Phase 3 wires real queries |
| T-01-29 | Tampering | an out-of-set booking status | medium | mitigate | The lifecycle set is a closed exported union; an absent or unrecognised status renders no badge rather than falling through to an arbitrary tone, so a corrupted value cannot present as a valid state |
| T-01-30 | Information Disclosure | an invented or stale price shown to a customer | high | mitigate | No component contains a currency literal or computes an amount; amounts render as the placeholder figure until the real matrix lands and the pricing flag is flipped in Phase 11. Phase 4 owns server-authoritative pricing |
| T-01-17 | Tampering | ported CSS carrying a banned surface | medium | mitigate | The tinted lead tile is dropped rather than neutralised at runtime; every file in both categories is asserted free of the banned yellow steps |
</threat_model>
