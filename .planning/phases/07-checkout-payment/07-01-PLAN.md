two least-privileged Postgres roles every later Phase 7 write path runs as.

`booking_payments`, `stripe_events`, `booking_events` or `booking_notifications`, and `publicSql` is
branded to five public-content tables only. Two EXECUTE-only identities close that gap without
handing a table grant to any client-facing role.

table extended for Phase 7.

|----------|-------------|
| Stripe → our database | Settlement facts (currency, FX rate, presentment amount) arrive from a webhook and are written into a row the charge gate already validated |
| Data API (PostgREST) → `public` schema | Anyone holding the publishable key can call any function granted to `anon`/`authenticated` |
| staff session → `booking_payments` | A dispatcher (or a stolen staff JWT) reaching the settlement row directly |
