<objective>
Prove the three properties PAY-05 names — no double charge, no double confirm, no double email —
without a Stripe account, a live price or an owner decision; then, once the owner has answered the
one question only they can, run the real thing end to end.

Purpose: this phase's exit bar contains a genuine conflict. A real test-mode charge needs a
`rate_versions` row marked live, because `pricing_live=false` refuses every caller at
`/api/checkout/intent` by design and QUOTE-10 has no off switch. CLAUDE.md's Law 04 says never
invent a CHF price — not in a migration, a seed, a fixture or a screenshot. Both are correct and the
resolution belongs to the owner. What must not happen is either the conflict silently deciding
itself, or the whole phase being untestable until it is decided. So this plan does the offline proof
first, asks the question second, and runs the live pass third.

Output: a pgTAP file and a Playwright spec that run in CI forever, a signing helper, one blocking
decision recorded in writing, and a gated live E2E script with its runbook.
</objective>

|----------|-------------|
| test tooling → a real Stripe account | A secret key reaches a script; a live key reaching it would move real money |
| a fixture row → production | A synthetic rate version is one careless migration away from being chargeable |
| local fixture signing → the real verifier | A hand-rolled signer could make a broken verifier look correct |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
