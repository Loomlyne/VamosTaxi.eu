<objective>
Write the one route that turns a locked quote into a Stripe Checkout Session and a `pending`
booking, in that order, with a compensating expire when the database refuses.

Purpose: everything either side of this route already exists or is planned. Phase 4 owns the
quote-side refusal ladder and exports it. Plan 07-02 owns the seven-table transaction. Plan 07-04
owns the Stripe client. What does not exist is the twenty lines of sequencing between them — and
that sequencing is the whole security argument: a Stripe session created inside a transaction holds
a Postgres connection open across the network, a booking created before the session has no
`stripe_payment_intent_id` for a NOT NULL column, and a charge-gate refusal with no compensating
expire leaves a payable session pointing at a booking that does not exist.

Output: one route handler, four small modules it composes, three Vitest files, and the U20 answer
written down where the next phase will look for it.
</objective>

  SUMMARY that "a second payment attempt row against one booking" is deliberately not built here:
  it would need a second RPC and a second `booking_payments` INSERT path, and the window rule makes
  it unnecessary.
