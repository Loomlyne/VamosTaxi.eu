<objective>
Ship the one function that turns a verified quote into a booking.

Purpose: `02-SCHEMA-DRAFT.md` §14a states there is no INSERT policy on `bookings` for any client
role — "a quote is created by a server-authoritative route, never by the browser" — and Phase 3's
FC-04 finding names Phase 7's checkout INSERT as the first real definer RPC behind `asAnon`/
`asCustomer`. Seven tables have to move together or none of them may move: a booking with no payment
row is a burned reference, a payment row with no snapshot binding fails the charge gate, and a
coupon redeemed outside the payment transaction burns a use on an abandoned checkout.

Output: one migration, one pgTAP file, refreshed generated types.
</objective>

  as the **inserting** role and a `SECURITY DEFINER` body runs as the function owner. Unique partial
  indexes `bookings_idempotency` on `idempotency_key` and `bookings_quote` on `quote_id`.
  `status booking_status not null default 'quote'`; `locale` and `display_currency` NOT NULL.
- `public.booking_legs` (`…011`): `unique (booking_id, leg_seq)`, `scheduled_local text not null`
  (`'YYYY-MM-DDTHH:MM'`, Europe/Zurich wall clock), `estimated_duration_minutes` and
  `turnaround_buffer_minutes` nullable but required once assignment happens.
- `public.price_snapshots` (`…013`): `booking_id` nullable and set NULL→non-NULL only (the one
  mutation `…019_append_only.sql` permits, and only `service_role` holds `grant update (booking_id)`).
  `rate_version_is_live` is overwritten by `tg_snapshot_rate_version_flag` regardless of what the
  caller passes. `price_snapshots_policy_shape` requires five keys. `is_chargeable` is STORED
  generated — it reads NULL in `NEW` during a BEFORE UPDATE trigger, so never depend on it there.
- `public.price_snapshot_legs` (`…013`): PK `(snapshot_id, leg_seq)`.
- `public.coupon_redemptions` (`…015`): BEFORE INSERT trigger `tg_coupon_redemption_caps` takes the
  `coupons` row `FOR UPDATE` and enforces window/global/per-user caps, raising `restrict_violation`.
  `payment_id` is NOT NULL — so the redemption row is inserted **after** the payment row.
- `public.booking_payments` (`…014` + plan 07-01): BEFORE INSERT charge gate
  `tg_payment_matches_snapshot` requires `s.is_chargeable`, a non-draft rate version, `s.expires_at >
  now()`, `charged_rappen = s.total_rappen`, `s.booking_id = new.booking_id`, and
  `new.snapshot_id = bookings.price_snapshot_id` — so `bookings.price_snapshot_id` must be set
  before this INSERT.
- `public.booking_access_tokens` (`…012`): `token_hash bytea not null unique` with
  `check (octet_length(token_hash) = 32)`; `expires_at` NOT NULL, never hard-coded. The table's own
  comment: "the Worker hashes first (Phase 3), so the raw value never reaches pg_stat_statements or

  hash as an argument — this RPC follows that convention.
- `public.booking_events` (`…016`): 17-value `kind` CHECK including `booking.created`,
  `price.quoted`, `payment.intent_created`; `actor_kind` in
  `('customer','guest','staff','system','stripe','cron')`; `booking_events_price_has_snapshot`
  requires `snapshot_id` on any `price.%` kind.
- `public.settings_versions` (`…004`): `manage_link_validity_days`, `checkout_window_minutes`,
  `quote_lock_minutes`, `free_cancel_hours`, `cancellation_tiers`.

Signature — one function, `returns table (booking_id uuid, reference text, snapshot_id bigint,
payment_id bigint, replayed boolean)`:

  `public.checkout_create_booking(p_quote_id uuid, p_idempotency_key text, p_contact jsonb,
   p_locale text, p_display_currency text, p_snapshot jsonb, p_legs jsonb, p_coupon_id bigint,
   p_coupon_code text, p_manage_token_hash bytea, p_manage_token_expires_at timestamptz,
   p_stripe_payment_intent_id text, p_stripe_checkout_session_id text, p_charged_rappen rappen,
   p_actor_customer_id uuid)`

Declared `language plpgsql security definer set search_path = ''`. Argument notes to carry as
comments:
- `p_manage_token_hash` is the SHA-256 of 32 random bytes the **Worker** generated and hashed
  (Phase 2's stated rule and `manage_booking_cancel`'s existing convention). The raw token never
  reaches Postgres, so the RPC cannot return it — the route already holds it. This is a deliberate
  correction to `07-RESEARCH.md`'s Pattern 2 sketch, which generated the token in-database and
  returned it base64-encoded; state that correction in the header comment.
- `p_manage_token_expires_at` is computed by the caller as `max(leg.scheduled_at) +
  settings_versions.manage_link_validity_days` (30 days, ADR-014 §5 / Phase 4 D-44) — never
  hard-coded here, and never `Date.now()`-derived in the Worker: the caller passes a timestamptz it
  read from Postgres in the same request.
- `p_snapshot` and `p_legs` are the server-derived pricing decision and the resolved legs. The
  function must **not** accept a total the client could have supplied — the route's zod boundary
  already rejects `distance_m`/`total_rappen`/`rate_version_id`/`lines` from the request body, and
  the charge gate re-derives the comparison from the snapshot regardless.
- `p_charged_rappen` is the CHF figure. `charged_currency` is **not** an argument: the row is
  always inserted `'CHF'` with a NULL FX quadruple, because with Adaptive Pricing the settled
  currency is only known at webhook time and plan 07-01's `booking_payments_fx_currency_pair`
  enforces that pairing.

Body, in this order:

1. **Idempotent replay first.** `select … into` an existing `public.bookings` row where
   `idempotency_key = p_idempotency_key`. If found, return that booking's id, reference, its
   `price_snapshot_id`, its `booking_payments.id`, and `replayed = true` — do **not** raise, do
   **not** insert anything. This is the U20 retry-safety contract Phase 4's D-57 named and left for
   this phase. Add a second guard for the other unique index: if a row exists with
   `quote_id = p_quote_id` but a **different** `idempotency_key`, raise
   `'quote_already_booked'` with `errcode = 'restrict_violation'` — a legitimate retry carries the
   same key; a different key against the same quote is a second purchase attempt on a quote that is
   already spent.
2. **Snapshot.** Insert the chosen-class `price_snapshots` row (or call Phase 4's helper), reading
   `expires_at` as `now() + (settings_versions.checkout_window_minutes || ' minutes')::interval`
   computed inside this statement — never in the Worker, never as `timestamptz + interval` in a
   generated column or an IMMUTABLE context. Insert the `price_snapshot_legs` rows from `p_legs`.
3. **Booking.** Insert `public.bookings` with `status = 'pending'` stated explicitly (D-02),
   `customer_id = p_actor_customer_id` (NULL for a guest — PAY-03), contact fields from `p_contact`,
   `idempotency_key`, `quote_id`, `locale`, `display_currency`, `is_return` derived from the leg
   count. Let `reference` take its DEFAULT.
4. **Legs.** Insert `public.booking_legs` from `p_legs` — `leg_seq`, `direction`, pickup/dropoff
   text/place_id/lat/lng, `scheduled_at`, `scheduled_local`, `flight_no`, `vehicle_class_id`, `pax`,
   `bags`, `estimated_duration_minutes` (`04-API-CONTRACT.md` §10: the web path must not write a
   missing duration). Then `update public.price_snapshot_legs set booking_leg_id = …` for each leg.
5. **Bind.** `update public.price_snapshots set booking_id = <new booking>` (the one NULL→non-NULL
   mutation the append-only trigger permits) and `update public.bookings set price_snapshot_id = …`
   — both required before the payment INSERT, because the charge gate checks
   `new.snapshot_id = bookings.price_snapshot_id`.
6. **Payment attempt.** Insert `public.booking_payments` with `status = 'requires_payment'`,
   `charged_currency = 'CHF'`, the FX quadruple NULL, `stripe_payment_intent_id`,
   `stripe_checkout_session_id`. This fires the charge gate. Do not catch its
   `restrict_violation` — the route's compensating `sessions.expire()` depends on the exception
   propagating.
7. **Coupon.** When `p_coupon_id` is not null, insert `public.coupon_redemptions (coupon_id,
   booking_id, payment_id, customer_id)`. The `FOR UPDATE` that serialises concurrent redemptions
   already lives in `tg_coupon_redemption_caps`; do not add a second lock. Let its
   `restrict_violation` propagate — Phase 4 D-30's "consume at payment, in the same transaction as
   `booking_payments`" is exactly this ordering.
8. **Manage token.** Insert `public.booking_access_tokens (booking_id, purpose, token_hash,
   expires_at)` with `purpose = 'manage'` (D-03). Nothing else in this phase mints one.
9. **Timeline.** Insert three `public.booking_events` rows inside the same transaction (DATA-08,
   Phase 2 D-17 — application-written, never a trigger): `price.quoted` with `snapshot_id` set
   (required by `booking_events_price_has_snapshot`), `booking.created`, and
   `payment.intent_created` with `payment_id` set. `actor_kind` is `'customer'` when
   `p_actor_customer_id` is not null, otherwise `'guest'`; `actor_id` is `p_actor_customer_id`.
   Never put money in the payload — `booking_events` references a snapshot, it does not contain one.
10. Return the new ids with `replayed = false`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/checkout/intent` body | Untrusted contact details, extras, coupon and idempotency key |
| Worker → `checkout_create_booking` | Server-derived pricing crossing into an elevated definer context |
| Data API → `public` schema | Anyone with the publishable key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Tampering | Client-supplied total or currency smuggled into the booking | mitigate | The RPC takes no client total; the charge gate re-derives the comparison from the snapshot; the route's zod boundary rejects `distance_m`/`total_rappen`/`rate_version_id`/`lines` (plan 07-05) |
| T-07-08 | Tampering | Double-submitted checkout creating two bookings, two references, two charges | mitigate | `bookings_idempotency` partial unique index plus the RPC's replay-first branch returning the existing row; `bookings_quote` closes the different-key-same-quote case with `quote_already_booked` |
| T-07-09 | Elevation of Privilege | RPC reachable through the Supabase Data API with the publishable key | mitigate | EXECUTE granted to `vamos_checkout` only; pgTAP asserts the empty privilege set for `anon`/`authenticated` |
| T-07-10 | Information Disclosure | Raw manage token reaching `pg_stat_statements`, a query log or a Postgres error message | mitigate | The Worker mints and SHA-256-hashes; the RPC's parameter is `bytea`; pgTAP asserts the function source contains no `gen_random_bytes` |
| T-07-11 | Repudiation | A booking with no timeline entry explaining who created it | mitigate | Three `booking_events` rows written inside the same transaction with `actor_kind` `'customer'`/`'guest'` |
| T-07-12 | Tampering | Coupon redeemed twice past its cap by two concurrent checkouts | mitigate | `tg_coupon_redemption_caps`'s existing `select … for update` on the `coupons` row, inside this transaction; pgTAP proves the cap refusal |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | No package install in this plan |
