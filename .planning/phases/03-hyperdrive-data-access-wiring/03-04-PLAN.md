<objective>
Write the deployed half of the DATA-06 proof as source, and make it structurally impossible for
that source to reach production.

`apps/isolation-probe` is its own Cloudflare Worker with no production environment, deployed only
to staging, importing the identical `withIdentity` the app imports — because a probe that runs a
copy of the SQL proves nothing about the code that ships. It exposes a closed `impl` union
covering the correct path, four mutants and four hazards, behind a constant-time `PROBE_SECRET`
header that 404s opaquely without it.

**Nothing in this plan deploys, provisions, or talks to Cloudflare.** Every acceptance criterion
is a typecheck, a build or a grep. Deployment, the real config ids and the NC1–NC6 run are plan
03-07, deferred until the owner's Cloudflare credentials exist (D-29).

**Precondition (D-30):** Phase 2 executed. The fixture module is written against the applied
migrations, but it is not *run* here — it runs against the staging project in plan 03-07, so a
Phase 2 table that has not landed yet blocks the run, not this plan.

**This plan adds no migration (D-31).**

Purpose: the probe and the fixtures are the largest chunk of Phase 3's deferred half; writing
them now means plan 03-07 is a provisioning and measuring exercise, not a build.
Output: a staging-only Worker, a token verifier, schema-legal fixtures with guest and staff
pairs, and three production gates.

    Create `apps/isolation-probe/src/index.ts` as a hand-written `ExportedHandler<ProbeEnv>` —
    not an OpenNext re-export. Structure it as: gate, dispatch, report.

    **Gate.** Read the `x-vamos-probe` header and compare it to `env.PROBE_SECRET` with a
    constant-time comparison (equal-length byte loop, no early return). On mismatch, absence, or
    when `env.DEPLOY_ENV !== "staging"`, return an opaque `404` with no body distinguishing the
    reasons. Then verify the `authorization: Bearer` token with `verifyAccessToken` — an
    unverifiable token is a `401`, never a fallback to unverified claims.

    **Dispatch.** Parse `?impl=` against the closed union in `<interfaces>` — a `Record<Impl,
    handler>` keyed by the union type so TypeScript fails the build if a member is added without
    a handler, and an unknown value returns `400` without reaching any database. No caller-
    supplied SQL, ever; no interpolation of any query parameter into a statement.

    Handlers, one per member:
      - `correct` — `withIdentity(env.HYPERDRIVE_NOCACHE.connectionString, kind, claims, fn,
        { probe: __VAMOS_ISOLATION_PROBE__ })`. This is the shipped function (D-15/ISOL-01):
        delete any temptation to inline the SQL. `fn` reads the caller's own booking references
        and returns them. Production's sequential-await shape is what is under test — do not
        pipeline.
      - `session_in_txn` (NC1) — `sql.begin` + `set_config('role', …, false)` +
        `set_config('request.jwt.claims', …, false)` + COMMIT, then the caller's read. This, not
        the no-transaction variant, is D-01's actual footgun (ISOL-02): PG 17 keeps an
        `is_local=false` SET across COMMIT while Hyperdrive's `RESET` masks the no-txn case.
      - `session` — the same session SET with **no** transaction. Labelled in the response and in
        a comment as the U27 companion measurement, **not** NC1.
      - `nobegin` (NC2) — `is_local => true` on the plain `sql` handle, no `sql.begin`, then the
        read.
      - `nowrapper` (NC3) — `select count(*) from public.bookings` as `vamos_edge` with no
        identity at all. If this ever returns a number, the response must carry it so the harness
        can fail loudly: the design is void.
      - `cached` (NC6) — the same identity sequence against `env.HYPERDRIVE_CACHED` as
        `vamos_public`.
      - `waituntil_captured` (NC5 hazard) — open `sql.begin`, bind identity, return the HTTP
        response, then inside `ctx.waitUntil` run a SELECT **on that same `tx`** and report the
        outcome out-of-band (a `?drain=` follow-up endpoint or a row written to a probe-owned
        scratch table — choose the out-of-band channel that needs no new table; a follow-up
        endpoint reading an in-isolate map is acceptable here because the probe is the thing
        under test, not the app). ISOL-04: this must capture `tx`, not demonstrate the fenced
        pattern.
      - `waituntil_fenced` (NC5+ positive) — a **new** `withIdentity` inside `ctx.waitUntil`.
        Labelled a positive control in the response so the harness never applies the mutant rule
        to it.
      - `abandon` (NC4 hazard) — `ctx.waitUntil` an open transaction so `BEGIN` genuinely reaches
        the origin, bind identity, then abort (throw, or let the query ceiling hit). ISOL-05: an
        abandon that never held an origin is INCONCLUSIVE, so the response must report enough for
        the harness to tell the two apart.

    **Report.** Every handler returns the JSON shape in `<interfaces>`: `impl`, which identity it
    ran as, the five ENTRY_PROBE fields (`userAtEntry`, `claimsAtEntry`, `guestAtEntry` — D-45

    structured log line per request through the `withRequestContext`/`emit` shape copied from
    `apps/web/worker.ts`.

    Declare `ProbeEnv` locally in this package (three `Hyperdrive` bindings, `PROBE_SECRET`,
    `DEPLOY_ENV`) rather than reusing `apps/web`'s `CloudflareEnv` — the two Workers have
    different binding sets, and coupling them would drag the app's bindings into the probe.
    Declare `__VAMOS_ISOLATION_PROBE__` as an ambient `const boolean` so the `define` substitution
    typechecks.
