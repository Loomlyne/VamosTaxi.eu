<objective>
Make `@vamos/db` a real, importable module and land `withIdentity` — the single door into
identity-scoped data — against the frozen contract, with the postgres.js lifecycle Workers
requires and a database-free proof that the contract holds.

This is the hard gate. Every other Phase 3 plan imports what this plan ships; nothing else in
the phase may start until it typechecks.

**Precondition (D-30):** Phase 2 is mid-execution. Nothing in this plan connects to a live
database — the contract test drives the shipped function through `opts.client` with an
in-memory recorder, so this plan is fully provable while Phase 2 plans 02-04…02-10 are still
outstanding. The role names and GUC keys this plan freezes come from the **applied** migration
`packages/db/supabase/migrations/20260823000002_roles_and_helpers.sql`, not from the research
prose.

**This plan adds no migration (D-31).** Its only `.sql`-adjacent artifact is a Node script that
runs two `ALTER ROLE … PASSWORD` statements against the local Docker Postgres.

This plan also **closes the Phase 3<->4 quote-identity seam** (D-44a). Phase 4's `/api/quote`
runs with no customer session, reads the live rate version, zones and surcharges, and must
INSERT `price_snapshots` — a write, which can never go through the cached binding. Phase 3
reserves the `"quote"` identity kind and the `asQuote` door now, on `HYPERDRIVE_NOCACHE`, so
Phase 4 adds a grant rather than renaming an identity that has already written rows.

Purpose: DATA-06 made structural rather than tested — a caller who forgets the wrapper gets
SQLSTATE `42501` because `vamos_edge` holds no grant, not because a test caught it.
Output: `@vamos/db` with `./identity`, `./public`, `./claims` exports; Vitest installed;
`pnpm typecheck` covering `packages/db` for the first time; the five-member `IdentityKind`
union Phase 4 binds to.
</objective>
