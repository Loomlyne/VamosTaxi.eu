D1/D2/D28–D30 do **not** make request-scoped identity unable to survive onto the next request on a pooled connection. D1 is a coding convention (`is_local => true` inside one `BEGIN`); D2/D30 are a grant wall that only holds while `current_user` is still `vamos_edge`; D28 is a file path; D29 is a closed map for the *next* bind, not a revert of the last one. The Phase 3 claim is therefore only as strong as the tests. The tests do not construct the bugs they name.

## Negative-control verdict (the lens question)

A control that can pass while the bug is present is a blocker. Applied:

| Control | Bug it claims to hold | Passes while the bug is present? |
|---|---|---|
| NC1 `impl=session` (no txn) | Mode 1/8 session `SET` surviving on a pooled backend | **Yes.** Orphaned `42501` from connection-split / RESET satisfies D38; `is_local=false` inside `BEGIN`/`COMMIT` is untested and is what PG actually persists. |
| NC2 `impl=nobegin` | Mode 4 | No (deployed). Local surrogate is not this bug (ISOL-10). |
| NC3 `impl=nowrapper` | D2 forgotten wrapper | **Partly.** Fresh `vamos_edge` yes; leftover `SET ROLE` no. |
| NC4 `impl=abandon` | Mode 2/5 dirty origin return | **Yes.** Without `waitUntil`, BEGIN often never runs; 400 clean probes pass. |
| NC5 `impl=waituntil` | Mode 10 captured `tx` | **Yes.** Tests the fence, not the capture. |
| NC6 `impl=cached` | Mode 13 cache serving A’s rows to B | **Partly.** Proves `vamos_public` has no `SELECT`; uses a transaction, so it cannot populate Hyperdrive’s query cache even if grants were wrong. |
| M1 / M2 | Grant layer / policy predicate | No — right shape, local, schema-only. They do not mutant `withIdentity`. |

Two real identities, genuine concurrency, and `S` as sample size are the strongest part of the design (`§7.2–§8`, V2/V4). They do not rescue a green run of a copy of the SQL, or a negative-control set that Hyperdrive `RESET` and Workers I/O cancellation can satisfy without the survival paths being closed.

Do not declare DATA-06 passed on a local run. Do not declare it passed on the deployed gate as specified.
