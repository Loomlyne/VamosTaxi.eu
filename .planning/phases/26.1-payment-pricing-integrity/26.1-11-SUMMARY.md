# Phase 26.1 Plan 11: Checkout price-line rows Summary

**The checkout recap now shows the airport pickup fee and the matched route pair ("Zürich – Bern route") as their own rows. The rows are read from the signed quote lock. The pair line carries both Mapbox city names, and every amount stays at the CHF 000 mark while the class is unpriced.**

## Performance

- **Duration:** ~50 min
- **Completed:** 2026-09-28
- **Tasks:** 2
- **Files modified:** 13 (2 created)

## Accomplishments

- `QuoteLegInput` has two new display-only fields, `origin_city_name` and `dest_city_name`. `ResolvedPlace.cityName` fills them from Mapbox (both the retrieve path and the pin/reverse path). `buildFixedRouteExtraLine` puts `params: { origin, destination }` on the pair line, in the leg's own direction. It does this only when both names are known and not blank. The names never change the match, the amount, `basis` or `source_row`.
- The lock legs carry the names, and `inputFromLock` restores them. A coupon, extras or flight-number reprice therefore keeps the "{origin} – {destination} route" label. A lock minted before this plan still verifies and falls back to "Route price".
- The lock has a new optional top-level field, `price_rows: [{ slug, lines: [{ code, leg_seq, amount_rappen, params? }] }]`. It is built from the priced board on quote and rebuilt on every reprice; a reprice never inherits it from the old lock. It is left out when no class has either line. Intent, pay-link and `lock-to-rpc` do not read it: `lock-to-rpc` maps only named fields, and `shown_alternatives` is still `class_totals`.
- `lib/checkout/price-rows.ts` is pure (no React):
  - `breakdownRows` returns one `plane-landing` row per `airport_fee` line and one `map-pin` row per `fixed_route` line, in line order. It ignores every other code.
  - `breakdownRappen` adds up the known rappen.
  - `peekLockPriceRows` does a display-only read of the lock. Malformed rows are dropped, and a negative or non-finite amount becomes null.
- `CheckoutClient` recap: the breakdown rows sit after the Fare row and before the extras rows. Both `PriceSummary` call sites share the same `priceLines`.
  - The Fare row is now `net − extras − breakdown`, so the rows still add up to the charged total.
  - `toAmount` returns null whenever `classRappen` is null, so an unpriced class shows the rows at `CHF 000`. The `PriceSummary` guard is untouched.
  - The labels are wrapped in `<span data-checkout-breakdown={code}>`. This gives a test hook, and it stops React from getting duplicate keys when a return trip has two same-label rows.
- Copy: `airport_fee` reuses `price.line.airport_fee` from 26.1-04. `checkout.routePair` and `checkout.routePairPlain` are new in en/de/fr/ar, with the exact wording from the plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Breakdown carried on the lock instead of React state only**
- **Found during:** Task 2 (read of `continueTrip` / home hand-off)
- **Issue:** The plan said to keep the class `lines` from "the latest quote/reprice response" in state. But on the normal path (home `.dc.html` mock → unedited `/checkout/trip` → payment), CheckoutClient never receives a quote response. It only has the lock in `vamosTrip`. The rows would have been missing on the main flow, and they would have disappeared on any step navigation that remounts the component.
- **Fix:** A new optional, signed `price_rows` field on the lock payload. It is written by the quote and reprice pipelines and read in checkout by `peekLockPriceRows`, following the same display-only contract as the existing `peekLockClassRappen`. The city names also ride on the lock legs so that a reprice keeps them.
- **Files modified:** `apps/web/lib/quote/lock.ts`, `apps/web/lib/quote/pipeline.ts` (lock.ts was not in the plan's file list)
- **Commit:** `8d7b6186`

**2. [Rule 2] `ResolvedPlace.cityName` did not exist**
- **Found during:** Task 1
- **Issue:** The plan's interface note said `ResolvedPlace.cityName` came from 26.1-09. In fact only `RetrievedPlace`/`ReversePlace` had it; `ResolvedPlace` did not.
- **Fix:** Added it to `ResolvedPlace` and filled it on both resolve paths.
- **Commit:** `8d7b6186`

**3. [Rule 1] The fare row would have double-counted the new rows**
- **Found during:** Task 2
- **Issue:** `fareRappen = net − extras` already included the airport fee and the pair price. Adding them as their own rows would have shown them twice.
- **Fix:** `fareRappen = max(0, net − extras − breakdownRappen(rows))`.
- **Commit:** `001817a6`

### Signature note
The plan wrote `breakdownRows(lines, t, formatAmount)`. `PriceSummary` already formats every `amount` itself (`formatAmount(l.amount, currency)`), so the third argument is `toAmount: (rappen) => number | null`. That is the FX display conversion, and it returns null for an unpriced class. A null amount still reaches `formatAmount(null)`, the `CHF 000` mark, as the plan required.

### Test changes
