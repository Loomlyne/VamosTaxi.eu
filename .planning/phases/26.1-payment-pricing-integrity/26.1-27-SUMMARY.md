## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] cleanKlass also maps live slugs, not only Van**
- **Found during:** Task 1
- **Issue:** Server `bookings-map.ts` labels bookings by class slug. Live slugs come through as "Saden" / "Mercedes-benz-v-class" / "Van-luxury", and `cleanBooking` then collapsed all of them to Economy. That breaks the "revenue by class groups by the three classes" requirement.
- **Fix:** `cleanKlass` turns the value into a slug and looks it up in an alias table covering live slugs and legacy names.
- **Files:** app/vamos-ops-data.js. **Commit:** aac93c3b

**2. [Rule 1 - Bug] OpsFleet inactive-class filter matched display names**
- **Found during:** Task 1
- **Issue:** `inactiveClass[name.toLowerCase()]` contains `economy`/`business`. Once 26.1-19 renames the live classes to Economy/Business, they would drop out of the chauffeur class dropdown.
- **Fix:** The filter now keys on `r.vehicleClassSlug`, which the rate book provides. Legacy slugs still hide the inactive rows.
- **Files:** app/ops/OpsFleet.dc.html. **Commit:** aac93c3b

**3. [Rule 3 - Blocking] Existing finalize test pinned the old four-class list**
- `ops-dc-finalize.test.ts` asserted `["Economy", "Business", "First", "Van"]`. It was updated to the D-14 line-up in Task 1 (the pin follows the decision; no assertion was loosened).

**4. Unused `RATE_DEFAULT_PAX`** now lists the three classes, so it no longer names First/Van.

## Deferred Issues (out of scope, server side)

- `apps/web/lib/ops/fleet-http.ts` `klassToSlug`/`slugToKlass` and `bookings-write.ts` `classSlug` only know the legacy slugs economy/business/van(/first). Two effects:
  - A booking edit with klass "Van luxury" (or any of the three names) resolves to `null`, and the server keeps the stored class.
  - A vehicle save without a `vehicleClassId` gets `classSlug: null`.
  - This needs a server-side mapping to the live slugs. 26.1-31 covers the fixtures only.
- `OpsNewTrip` fare falls back to `j.classes[0]` when the chosen class is not in the quote. This was already there before this plan.
- `app/home/home.dc.html`, `app/pages/manage-booking.dc.html` and `booking-detail.dc.html` still carry `First` copy. These are outside this plan's files; the checkout picked-class label is in 26.1-31.
- ADR-012 recommends Latin-verbatim Arabic for product names. The live Economy/Business Arabic values are still transliterations, so 'Van luxury' matches them as the plan asks. This needs an owner call.
