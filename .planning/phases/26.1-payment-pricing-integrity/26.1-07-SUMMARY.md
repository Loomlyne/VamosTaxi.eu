# Phase 26.1 Plan 07: Checkout fails closed, coupon caps enforced at payment Summary

**Both checkout routes now read the real `pricing_live` through one fail-closed loader, and a coupon is re-evaluated with the payer's identity right before the Stripe session opens — its `coupon_id` reaches `checkout_create_booking` so `coupon_redemptions` is written and a percent coupon discounts checkout extras too, not just the class fare.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 2
- **Files modified:** 9 (4 created, 7 modified — CheckoutClient and intent.test.ts touched across both tasks)

## Accomplishments

- `loadCheckoutReprice(env)` replaces the identical swallow-and-continue `try { mapRateBook(await loadRateBook(...)) } catch { extrasCatalog = [] }` block in both `/api/checkout/intent` and `/api/checkout/pay-link`: a rate-book load failure now refuses `pricing_not_live` before any Stripe session opens (D-12), and `pricing_live` is `derivePricingLive(rate_version) && flags.public_chf` — the exact rule `lib/quote/engine.ts` already uses for the quote path — never the literal `true` the routes previously hard-coded.
- Neither route file contains `pricing_live: true` anymore; `checkIntentAgainstLock` (which already gated on `board.pricing_live`, pre-dating this plan) now actually sees the real value.
- `runCheckoutIntent` re-evaluates `body.coupon` with `deps.actorCustomerId` and `body.contact.email` right before creating the Stripe session — never the quote-time evaluation baked into the lock. A refusal from `evaluate_coupon` (or a coupon typed with no `evaluateCoupon` dep wired) refuses `coupon_no_longer_valid` before any session opens. The evaluated `coupon_id` — not `null` — reaches `createBooking`, so `checkout_create_booking`'s existing step 7 (`insert into coupon_redemptions ... when p_coupon_id is not null`) and `tg_coupon_redemption_caps`'s `FOR UPDATE` cap now actually run (D-11).
- `payableRappen` (`apps/web/lib/checkout/payable.ts`): pure `(lines + extras) − coupon% (floor 0), then VAT` (D-08a). A percent coupon now discounts checkout extras selected after the lock, not just the class fare — the bug the plan closes. Wired into `intent.ts`'s `chargedRappen` and into `CheckoutClient.tsx`'s recap, so the displayed total and the server's charge use the same function.

## Decisions Made

- **Lock format unchanged.** The plan allowed bumping the lock version if grossing up the class total pre-coupon was unavoidable without it; it wasn't — `coupon: string | null` on the lock plus the freshly re-evaluated `percent` from `evaluate_coupon` is enough to gross the post-coupon class total back up (`grossUpBeforeCouponRappen` / `preCouponRappen` on the client), so no HMAC payload change was needed.
- **Amount-kind coupons are out of scope for the extras discount.** D-08a's must-have and the plan's `<behavior>` block name percent coupons specifically; an amount-kind coupon keeps discounting the class fare only, unchanged from before this plan.
- **The coupon-cap SQL race (D-11's "cap reached between quote and pay") is mapped via attachPayment's own not-found, not a new SQLSTATE.** See Deviations below — the plan's text named `23514`/`P0001` for this race, but the actual trigger (`tg_coupon_redemption_caps`, `packages/db/supabase/migrations/20260823000015_coupon_redemptions.sql`) raises `restrict_violation` (`23001`), the same code `checkout_create_booking` already uses for `quote_already_booked`. No migration was added (none was in the plan's `files_modified` and the hard rule is new migrations only, never edited ones) — the two are disambiguated in `lib/checkout/intent.ts` by whether `attachPayment`'s own booking lookup finds anything.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Coupon-cap race mapped correctly instead of surfacing a 500**

- **Found during:** Task 2, while tracing what SQLSTATE `tg_coupon_redemption_caps` actually raises.
- **Issue:** The plan's `<action>` text says "map SQL 23514/P0001 cap errors to coupon_no_longer_valid" — that mapping already existed in `intent.ts` (pre-dating this plan) for errors *outside* the 23505/23001 branch. But the cap trigger itself raises `restrict_violation` (`23001`) — the *same* code `checkout_create_booking` already uses for `quote_already_booked` (`packages/db/supabase/migrations/20260827000003_checkout_rpc.sql`). Left as-is, a coupon-carrying `createBooking` call that failed on the cap trigger would fall into the existing "already booked, try to reuse/attach" retry path, find no committed booking (the whole transaction rolled back), and `attachPayment` would throw `not_found` (`P0002`) — which the pre-existing `attachErr` catch doesn't handle, so it would `throw` out to the route's top-level 500.
- **Fix:** Added one branch in the `attachErr` catch: `P0002` with a non-null `couponId` on this attempt refuses `coupon_no_longer_valid` instead of rethrowing. Reasoning documented inline in `intent.ts` — a genuine "already booked" 23001 always has a real row for `attachPayment`'s own lookup to find (handled by the existing 23505/23001 branch above it); not-found with a coupon on the attempt is the tell that nothing was ever committed.
- **Files modified:** `apps/web/lib/checkout/intent.ts`
- **Verification:** New test `"refuses coupon_no_longer_valid when the cap trigger fires between evaluate and insert (D-11 race)"` in `intent.test.ts`.
- **Committed in:** `1c902699` (Task 2 commit)

**2. [Rule 1 - Bug] Updated a source-grep test regex to match the new call shape**

- **Found during:** Task 2 verification (`lib/checkout/vat.test.ts` failed after `chargedRappen`'s formula changed).
- **Issue:** `vat.test.ts` asserts the literal source text of `intent.ts` still contains `payableWithVatRappen(netRappen + extraAdd, vatRateBps)` — a regression guard from an earlier plan pinning the VAT-on-total call shape. This plan's whole point is that call shape could never discount extras by a coupon, so it had to change.
- **Fix:** Updated the regex to assert the new `payableRappen({ classNetRappen: netRappen, preCouponRappen, extraAddRappen: extraAdd, couponPercent: couponPercentHundredths, vatRateBps }).chargedRappen` shape instead, with a comment explaining the change (D-08a, 26.1-07).
- **Files modified:** `apps/web/lib/checkout/vat.test.ts`
- **Verification:** `pnpm --filter web exec vitest run lib/checkout/vat.test.ts` passes.
- **Committed in:** `1c902699` (Task 2 commit)
