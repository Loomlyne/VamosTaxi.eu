## Issues Encountered

### Blocker: `test:unit` red — `lib/meta/legal-gate.test.ts` times out after the merge

- **Gate:** `pnpm test:unit` (Task 1)
- **Exit code:** 1
- **Failing tests:** `apps/web/lib/meta/legal-gate.test.ts > meta legal gate > policy version unchanged`, `apps/web/lib/meta/legal-gate.test.ts > meta legal gate > flag off`
- **Result:** `Test Files 1 failed | 167 passed (168)`; `Tests 2 failed | 1629 passed (1631)`
- **Root cause:** Both failing tests call a `walk("")` helper that recursively reads every file under `apps/web` (excluding `node_modules`, `.next`, `.wrangler`) as utf8 text and regex-matches it. PR #60 added `apps/web/tests/visual/**/*.png` — 1,161 new Darwin visual-baseline snapshots (`find apps/web -iname '*darwin*.png' | wc -l` → 1161) — that this walk now reads. The added I/O pushes both tests past vitest's 5000ms default `testTimeout`.
- **Confirmed not a logic bug:** re-ran `pnpm --filter web exec vitest run lib/meta/legal-gate.test.ts -t "policy version unchanged" --testTimeout=30000` → 1 passed in 5.38s (just over the default 5000ms, well under 30000ms). The assertions themselves are correct; only the wall-clock budget is wrong for the new file count.
- **Not fixed here:** per the plan's Task 1 instruction. Left for the orchestrator to decide — likely fixes are (a) raise `legal-gate.test.ts`'s two `it()` calls to an explicit timeout (e.g. `30_000`, matching the pattern this plan's own new test uses), or (b) exclude visual-baseline snapshot paths from its `walk("")`.
- **Everything else in `test:unit` is green:** 1629/1631 individual tests pass; only this one file/these two tests are affected.
