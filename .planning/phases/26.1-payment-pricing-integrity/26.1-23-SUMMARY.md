# Phase 26.1 Plan 23: Admin sign-in options UI and ops step-up Summary

**Security settings now let the admin add and remove an authenticator app, switch between password and magic link, and confirm every sensitive change in a "Confirm and continue" dialog. The ops sign-in asks for the 6-digit code when a factor is enrolled. On the server, TOTP enrolment now needs a fresh re-auth (D-17b), and the unguarded staff password action is gone.**

## Performance

- **Duration:** about 35 min
- **Tasks:** 2 plan tasks, 2 extra tasks and 1 coordinator task (each TDD, RED then GREEN)
- **Files:** 3 created, 12 modified

## Accomplishments

- **D-17b on the server:** `enrolTotp(client, { reauth })` returns `reauth-required` / `reauth-unavailable` before it lists, clears or enrols anything. `mfa-totp-enroll` passes `await gate()` and answers 403 through `mfaStatus`, matching `mfa-unenroll`.
- **Password bypass removed:** `staffSignInAction` and `StaffSignInResult` are deleted from `lib/auth/staff-ops.ts`, along with the now-unused schema import. Nothing imported them. A source pin keeps `signInWithPassword` out of that file.
- **OpsSettings Security pane (UI-SPEC §7):**
  - **Authenticator app card.** Not enrolled: primary `shield-check` "Add an authenticator app". Enrolling: Supabase's QR (a `data:image/svg+xml` URI) shown as an `<img>` in a 16px-radius box with a `1px var(--vt-grey-200)` border, then the setup key in `--vt-font-mono` (`data-i18n-skip`, `vt-dir-keep`), a numeric 6-digit field and "Verify and turn on". Enrolled: "Authenticator app turned on." with a secondary "Remove authenticator app". A wrong code shows a danger `Alert` with the approved copy and refocuses the field.
  - **Password / magic link switch.** A ghost "Sign in with a magic link instead" sits under the password block. For a magic-link admin the password fields hide and the pane shows "You sign in with a magic link sent to {email}." with the email in a `vt-dir-keep` span, plus "Use a password instead". Success shows `secUpdated`.
  - **Re-auth dialog.** `Dialog size="sm"`. Password admins get a password field with the existing right-side `data-af-eye` toggle. Magic-link admins get "Send a code" and a 6-digit field. "Confirm and continue" stays disabled until the field is filled or while a request runs. It wraps adding the app, removing the app, the method switch, the email change and the password change. A 403 `reauth-required` reopens it and retries once.
  - Raw error codes no longer reach the screen. Password and email failures map to instructive copy ("Could not save. Try again.", "Too many tries…", "This can't be confirmed right now…").
  - The state loads from `mfa-status` on mount (totp, factor id, passkey, sign-in method). There is no banner when no factor is enrolled (D-16).
  - At 680px and below, the QR and key stack and the new-password pair goes to one column.
- **AuthForm (ops) stage `mfa`:**
  - After a successful ops password sign-in, `mfa-status` is called. If `totp` is true, the form shows "Enter the 6-digit code", a numeric field, "Verify" and "Use another sign-in". Otherwise it goes straight to `/dashboard` as before.
  - On mount, the ops form checks `/api/staff/me`. `needs-mfa` (an aal1 return, for example after a magic link) jumps to the code step.
  - "Verify" calls `mfa-step-up` and redirects to `/dashboard` only after `result.ok`.
  - Mismatch, rate limit and other failures each show a danger alert. A `credentials` answer (a magic-link account signed in by password) returns to the form with the credentials banner.
  - "Use another sign-in" signs out the half session first.
  - `stage` data-props now lists `mfa`.
- **Coordinator items (26.1-20 follow-ups):**
  - `staffStatus('needs-mfa')` now returns `{ code: 'needs-mfa', status: 403 }` instead of `not-staff`.
  - `OPS_AUTH_INTERNAL` drops `/ops/mfa-challenge`.
  - `content-string-edit.spec.ts` signs in as the admin (D-16b) through the AuthForm code step.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security] Email and password change errors no longer print raw codes**
- **Found during:** Task 1
- **Issue:** `changePassword` showed `json.code` (for example `reauth-required`) as the message, and `saveEmail` dropped failures silently.
- **Fix:** Both now go through `withReauth` and `failText`, and email failures get their own status line.
- **Commit:** `4dca4cb4`

**2. [Rule 2 - Correctness] "Use another sign-in" signs the aal1 session out**
- **Issue:** Going back to the form while holding a half-signed-in session would leave a live aal1 session behind.
- **Fix:** It calls the `signout` action first.
- **Commit:** `1b0df69d`
