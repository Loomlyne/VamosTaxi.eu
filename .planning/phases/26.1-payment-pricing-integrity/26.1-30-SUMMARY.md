# Phase 26.1 Plan 30: Checkout flight number re-price (D-08b) Summary

**A flight number typed at /checkout/details now re-prices through /api/quote/reprice into the signed lock (so the kernel adds the airport fee before payment), and the checkout intent refuses `price_changed` before any Stripe call or booking row when the body's flight number is not the one the lock priced.**

## Performance

- **Duration:** about 8 min
- **Completed:** 2026-09-28
- **Tasks:** 2
- **Files:** 2 created, 11 modified

## Accomplishments

- `RepriceRequestSchema` accepts optional `legs: [{ leg_seq: 1|2, flight_no: string|null }]` (max 16 chars, strict per leg, unique leg_seq, max 2). `legs` left the reprice forbidden-key list; any other leg key (`scheduled_local`, `pickup`, `origin_is_airport`) is still refused.
- `runRepricePipeline` applies the override onto the verified lock (`withRepriceFlightNumbers`): trimmed, blank means null, a leg the lock does not have is `untrusted_input`. The kernel input and the re-signed lock both carry it, on the same HMAC path as extras and coupon.
- `checkoutIntentSchema` gains optional `flight_no` (trimmed, blank means null). `runCheckoutIntent` compares it with the verified lock's leg-1 `flight_no` right after lock verification. A mismatch returns the existing `price_changed` (409, `requote`) before the pay gate, Stripe or `createBooking`. Pay-link inherits this through `runCheckoutIntent`. `quote_changed` does not appear anywhere.
- CheckoutClient `syncFlightToLock()` runs on FlightField blur (details step) and before Continue in `continueDetails`. It re-prices only when `lockFlightNoDiffers`. It stores the re-signed lock in the draft, `vamosTrip` and `tripSnap`, drops any Stripe client secret opened on the old lock, and bumps the intent tick. Intent and pay-link bodies send `flight_no`. `startPayment` reads `readDraft()` so it uses a lock re-signed in the same tick.
