# Phase 26.1 Plan 19: Class delete-or-hide, owner names, and three carried fixes

**Deleting a vehicle class is now a real hard delete when only draft rows use it, or a reasoned hide that removes it from every public board. The live display names ship as an owner data file. The confirmation read now carries the refund facts, ops labels follow the D-14 line-up, and the seed is regenerated.**

## Performance

- **Duration:** about 40 min
- **Completed:** 2026-09-28
- **Tasks:** 2 plan tasks + 3 extra (A, B, C)
- **Files modified:** 29

## Accomplishments

- `public.ops_vehicle_class_delete_or_hide(uuid, text)` is admin-only (`app.is_admin()`, 42501). It uses `search_path=''` and grants EXECUTE to vamos_staff only; anon and authenticated are revoked. It checks booking_legs, price_snapshots, vehicles, chauffeurs, reviews and non-draft rate rows. It returns `deleted`, `in-use` or `hidden`. A blank reason counts as no reason. A reason over 140 characters raises 22001.
- The route `DELETE /api/staff/vehicle-classes` requires a UUID and takes an optional `reason`. It returns 200 `{result}` or 409 `in-use`.
- `mapRateBook` drops classes that have `hidden_at`. `hiddenPublicSlugs` also treats `hidden_at` as hidden, as defence in depth.
- OpsPricing: when a class is in use, a second `Dialog size="sm"` opens with a required Textarea (140 max, counter) and two buttons, "Keep it visible" (secondary) and "Hide with a reason" (primary, disabled until the reason is non-empty). An inline error shows if the write fails. The copy exists in en, de (with "ss"), fr and ar. A hidden row shows the reason as a muted caption under the "Hidden from public" chip.
- `owner-sql/26.1-class-names.sql` is data only and safe to run twice.
- **A:** `confirmation_payload` now returns the three refund fields, and `VisibleBooking` maps them. The voucher refund line survives a reload.
- **B:** `bookings-map.ts` and `vehicle-class-label.ts` now resolve names through `class-slug.ts`.
- **C:** The seed is regenerated (`checkout.refundPendingOps` reworded, `checkout.refundDeclinedLabel` added). The content_strings pin is now 2510 + 26. The no-param pin stays 72, which equals the size of en.json `$meta.noParamKeys`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing functionality] The hide reason had to reach the ops list**
- **Found during:** Task 2
- **Issue:** OpsPricing's Distance rows come from `/api/staff/rate-book`, which did not load `hidden_at` or `hidden_reason`. Without them the caption had no data.
- **Fix:** `lib/ops/rate-book.ts` now loads both columns into `VehicleClassRef.hiddenReason`. `mockRates` emits `hiddenReason` and forces `hideFromPublic` for hidden classes, `cleanRate` keeps the field, and OpsTable's bool chip takes an optional `subKey` caption.
- **Files:** apps/web/lib/ops/rate-book.ts, apps/web/app/[locale]/(ops)/api/staff/rate-book/route.ts, app/vamos-ops-data.js, app/ops/OpsTable.dc.html
- **Commit:** 33a07aef

**2. [Rule 3 - Blocking] OpsPricing's delete never reached the class route**
- **Found during:** Task 2
- **Issue:** `deleteDistance` called `ops.rates.remove`, which runs `DELETE /api/staff/rate-book?kind=distance` and only drops the draft rate row. The class route and the new RPC were never called.
- **Fix:** Added `VamosOps.deleteClass(id, reason)`. `deleteDistance(id, row)` now calls it with the row's `vehicleClassId`. It falls back to `rates.remove` only when the row has no class id.
- **Commit:** 33a07aef

**3. [Rule 1 - Bug] Admin RPC errors would have been 500**
- **Fix:** The DELETE route maps P0002 to 404 `not-found` and 42501 to 403 `not-admin`.
- **Commit:** 33a07aef
