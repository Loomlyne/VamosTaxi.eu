# Phase 26.1 Plan 10: Canton and city zones Summary

**26 canton zones plus a draft-only `ops_fill_canton_pairs(version, price)` that writes the 325 canton pairs per class at the owner's typed price, and ops route picks that now resolve through Mapbox to the official city, canton or airport instead of a street or POI zone.**

## Accomplishments

- Migration `20260928130000_canton_city_zones.sql`: zone_type CHECK now includes `canton`. Adds the 26 cantons (`canton-ag` … `canton-zh`, tag `canton:AG` …). Adds their official names as non-translatable `zone.canton-<code>` strings, the same in en/de/fr/ar. Adds `public.ops_fill_canton_pairs(bigint, rappen) returns int`, which is SECURITY DEFINER with `search_path=''`. That function:
  - refuses a null price (22004), an unknown version (P0002), a non-admin caller (42501), and a live or retired version (23001, restrict_violation);
  - locks the version row, inserts one row per unordered active canton pair for each class with a distance_rates row, `live = true`, and skips pairs already present in either direction;
  - returns the number of rows inserted.
- EXECUTE is granted to `vamos_staff` only (anon, authenticated and public are revoked). The function also requires `app.is_admin()`, or the owner's plain postgres session.
- pgTAP `canton_zones.test.sql` (24 assertions) covers:
  - the 26 rows, their slugs and tags, and the names;
  - that the CHECK accepts `canton`, and the grants;
  - 325 × 3 rows on a three-class draft; every row runs from the lower code to the higher, is live, and carries the given price;
  - a second run inserts 0; a draft with one reverse-direction row gets 324;
  - a dispatcher is refused and inserts nothing; the admin fills a draft (325 rows);
  - live and retired versions are refused and insert nothing.
- `packages/db/owner-sql/26.1-zone-cleanup.sql`:
  - deactivates, never deletes, the three audit zones;
  - re-points draft `fixed_routes` from each duplicate to `zrh-airport` / `st-moritz`, only where the canonical pair does not already exist in either direction;
  - never selects rows on live or retired versions;
  - ends with two review selects: active zones by type, and draft routes still on a deactivated zone.
  - Exercised on the local database with fixtures: 3 zones deactivated, 1 origin and 2 destination rows re-pointed, the one colliding row left and listed. The local database was reset afterwards.
- `apps/web/lib/ops/mapbox-zone.ts` gains these pure functions:
  - `zoneTargetFromRetrieved`: airport POI → airport, `mapbox:<id>`; any place inside a city → that city, `mapbox_place:<cityId>`; region → `canton-<code>`; nothing resolved → null;
  - `upsertZoneTarget`: reuse by identity tag, then by slug unless that slug belongs to another area, then insert;
  - `resolveZoneFromPin`: runs retrieve before any transaction; a failure means no store access;
  - `swissCantonCode` and `geoLanguageFromPath` (path locale, then Accept-Language, then en).
  - `zoneSlugFromPlace` now strips accents: `zurich`, not `zu-rich`.
- Rate-book route `ensureMapboxZone`:
  - calls `retrieve` with `crypto.randomUUID()` as the Search Box session token and the staff language;
  - counts the call toward the Mapbox budget (`countMapboxUnit`);
  - backs `ZoneStore` with one `asStaff` transaction, inserting the non-translatable `zone.<slug>` name;
  - answers `mapbox` 400 when resolution fails, so nothing is created.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] seed_idempotent content_strings pins did not count migration-born rows**
- **Found during:** Task 1 (pgTAP run after the migration)
- **Issue:** `seed_idempotent.test.sql` pinned `content_strings` at 2502 and non-translatable at 8. The migration's 26 canton names made these 2528 / 34.
- **Fix:** The pins are now `2502 + 26` and `8 + 26`, with a comment naming the migration. The 26 are pinned on their own in `canton_zones.test.sql`. Both checks keep an exact count; nothing is loosened. No i18n keys were added to en.json, so `db:seed:gen` was not needed.
- **Files modified:** `packages/db/supabase/tests/seed_idempotent.test.sql`
- **Commit:** `d63a56a1`

**2. [Rule 1 - Bug] Loose text matching would bind a street pick to a canton zone**
- **Found during:** Task 2
- **Issue:** The route tried `matchZone(zones, recBody.from)` (substring match on zone labels) before Mapbox. With canton names on file, any address containing "Zürich", "Bern", "Zug" or "Uri" would match the canton.
- **Fix:** A present Mapbox pin always goes through `ensureMapboxZone`; the route's `matchZone` was removed. A zone id alone (an end that was not re-picked) still selects that zone.
- **Files modified:** `apps/web/app/[locale]/(ops)/api/staff/rate-book/route.ts`
- **Commit:** `760ce9f4`

**3. [Rule 1 - Bug] Accented names produced split slugs**
- **Found during:** Task 2
- **Issue:** `zoneSlugFromPlace` kept NFKD combining marks and turned them into dashes ("Zürich" → `zu-rich`). This is where the audit slug `…-zu-ri` came from.
- **Fix:** Strip `̀-ͯ` after NFKD. Existing slugs on the database are untouched.
- **Commit:** `760ce9f4`

**4. [Rule 2 - Correctness] Same-name towns and seeded slugs**
- **Found during:** Task 2
- **Issue:** A slug-only upsert would merge Wil SG and Wil ZH into one zone. It would also create a second zone next to seeded `zermatt`.
- **Fix:** `upsertZoneTarget` reuses a slug only when that row does not already carry a different identity tag of the same kind. It adds the tag to the reused row (seeded `zermatt` gains `mapbox_place:<id>` and keeps `ski`). Otherwise it uses `<slug>-<canton>`. Covered by two extra tests.
- **Commit:** `760ce9f4`

**Test changes:** `mapbox-zone.test.ts` only gained tests. The five plan behaviours plus: no-pin refusal, same-name town, seeded-slug reuse, accent slug, locale. No existing assertion was changed. The only other test change is the seed pin described in deviation 1.
