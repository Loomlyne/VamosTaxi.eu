<objective>
Port `OpsFleet.dc.html`'s vehicles half onto `public.vehicles`, and give the three vehicle classes the
capacity editor they need but the mock never had.

Two things make this more than a table port.

**The class capacities are quote inputs, not display text.** `vehicle_classes.passenger_capacity` and
`.luggage_capacity` are what the Phase 4 quote engine clamps a party size against (QUOTE-02). ADR-014
§6 fixed them at Economy 3/3, Business 3/3, Van 8/8, and D-36 narrowed the seed and the pgTAP to those
three — `first` remains legal in the CHECK so a future class needs no migration, but nothing ships it.
Editing a capacity here changes which class a traveller is allowed to book, which is why the panel
must say so rather than presenting two anonymous number fields.

**The class display name is not in the class table.** `…05_fleet.sql`'s own comment points at a
`vehicle.class.<slug>` key stem in `content_strings`. That stem does not exist. The keys that actually
shipped are `common.vehicleClassEconomy`, `common.vehicleClassBusiness` and `common.vehicleClassVan`,
and all three are listed in `$meta.nonTranslatableKeys` — ADR-012 product names, literal in every
language, marked rather than duplicated. So the screen resolves a class label through those keys, never
translates it, and never adds a `name` column to `vehicle_classes`. There is deliberately no
`common.vehicleClassFirst`: a `first` row would have no label, and the screen must render that as a
labelled gap rather than crashing or inventing one.

**Zero photographs is the shipping state.** ADR-014's still-open list has vehicle photography on it
with no date. `vehicles.photo_path` is nullable and every row will be NULL at launch. The fallback is
therefore the primary rendering path and gets built and tested as one (D-22).

Purpose: the fleet and the class capacities behind every quote are editable without a deploy.
Output: one table with a class panel, five Server Actions, one spec.
</objective>

<interfaces>
`public.vehicle_classes` (…05_fleet.sql):
  id uuid PK, slug text unique CHECK in ('economy','business','first','van')
  passenger_capacity smallint not null CHECK between 1 and 16
  luggage_capacity   smallint not null CHECK between 0 and 16
  sort_order smallint not null default 0, active boolean not null default true
  Seeded: economy 3/3, business 3/3, van 8/8 (ADR-014 §6, D-36). No `first` row.

`public.vehicles`:
  id uuid PK
  vehicle_class_id uuid not null references vehicle_classes ON DELETE RESTRICT
  model text not null, plate text not null UNIQUE
  first_registered smallint CHECK between 1990 and 2100 (nullable)
  seats smallint not null default 3 CHECK between 1 and 16
  bags  smallint not null default 3 CHECK between 0 and 16
  status vehicle_status not null default 'service'   -- enum: 'service' | 'idle' | 'workshop'
  photo_path text (R2 object key, nullable), note text not null default ''
  created_at, updated_at timestamptz not null default now()

`chauffeurs.default_vehicle_id` references `vehicles(id) ON DELETE SET NULL` — deleting a vehicle
does not block on a chauffeur, it clears their default. `vehicle_classes` deletion, by contrast, is
`ON DELETE RESTRICT` from `vehicles`: a class with vehicles cannot be deleted, and that refusal is
SQLSTATE 23503.

Class display names — the shipped keys, all three `$meta.nonTranslatableKeys` (ADR-012):
  common.vehicleClassEconomy, common.vehicleClassBusiness, common.vehicleClassVan
There is no `common.vehicleClassFirst` and no `vehicle.*` namespace.

RLS: `vehicles` and `vehicle_classes` are both in the seventeen-table staff working set
(…23_rls_staff.sql) — full CRUD to `vamos_staff` behind `vehicles_staff_gate` /
`vehicle_classes_staff_gate` (RESTRICTIVE FOR ALL, `app.is_staff()`). Not admin-only.
`vehicle_classes` is additionally readable by `vamos_public`/`anon`/`authenticated`
(`vehicle_classes_public_read`, `using (active)`) — deactivating a class removes it from the public
booking widget immediately.

Audit: both tables are in `tg_audit_row`'s attach list. No manual audit write.
**No touch trigger exists** — `vehicles.updated_at` is set by the statement.

From 06-02: `requireStaffClaims()`. From 06-06: `OpsPhotoField`, `photoUrl`, `PHOTO_PREFIXES`,
`buildPhotoKey`. From 06-07: `mapSqlState`.
