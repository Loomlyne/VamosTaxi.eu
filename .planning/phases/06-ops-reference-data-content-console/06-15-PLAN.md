<objective>
Build the rate book underneath 06-07's version list: the three priced child tables of a
`rate_versions` row, plus the service zones fixed routes are built between.

06-07 shipped the version list, the completeness checklist and the publish gate. This plan is what
staff actually fill in before that gate can pass — and it is the surface where the schema's freeze
rules become a user interface.

**Three tables, one trigger, two permission layers.** `tg_pricing_row_frozen` is attached to
`distance_rates`, `fixed_routes` and `surcharges` on both UPDATE/DELETE and INSERT (Phase 2's F-12
fix). Once a version leaves `draft`, everything except the availability flag is immutable, and the
flag is spelled differently per table — `available`, `live`, `active` — which the trigger handles by
subtracting all three keys from its jsonb comparison on every call. Above that sit the RLS policies:
`*_admin_insert` and `*_admin_delete` are admin-only outright; `*_admin_update` is admin-only **or**
`app.rate_version_published(rate_version_id)`.

That carve-out deserves a note, because it looks like a dispatcher feature and is not reachable as
one. Its purpose is exactly the mock's per-route switch — *"Off keeps the route on file but hides it
from the booking flow"* — for a live version. But `rate_versions_admin_write` is `AS RESTRICTIVE FOR
ALL`, so a dispatcher reads zero rows from `rate_versions` and cannot navigate to a version at all,
and D-12 removes the Pricing nav item for that role entirely. So the carve-out is dead code from this
console's point of view. It is not a bug and this plan does not try to expose it; it is a door Phase 8
may open with a different screen. Recording that is the point, so nobody later reads the policy and
concludes the nav is broken.

**No CHF amount is written by this plan, including in its tests.** D-14 and D-32 are unconditional:
not a migration, not a fixture, not a spec value, not a screenshot. So the priced fields are built and
the write path is proven by a **refusal** — a negative rappen value violating the column CHECK proves
the value reached Postgres — while round-trip persistence is proven on the columns that carry no
pricing meaning (`max_pax`, `applies_to`, and the three availability flags). The gap this leaves is
named rather than hidden: priced-value persistence stays unproven until the owner's matrix lands, and
the same spec gains that assertion on the day it does.

Purpose: an admin can fill a draft matrix so 06-07's publish gate has something to pass on.
Output: three tab editors, one zone panel, nine actions, one spec.
</objective>

<interfaces>
`public.distance_rates` (…08_rate_versions.sql):
  id bigint identity, rate_version_id bigint not null -> rate_versions ON DELETE RESTRICT
  vehicle_class_id uuid not null -> vehicle_classes ON DELETE RESTRICT
  base_fare_rappen / per_km_rappen / min_fare_rappen   rappen, NULLABLE, CHECK >= 0
  max_pax smallint not null CHECK between 1 and 16
  available boolean not null default true
  UNIQUE (rate_version_id, vehicle_class_id)

`public.fixed_routes`:
  id bigint identity, rate_version_id bigint not null
  origin_zone_id / dest_zone_id uuid not null -> service_zones ON DELETE RESTRICT
  vehicle_class_id uuid not null, price_rappen rappen NULLABLE CHECK >= 0
  live boolean not null default false
  UNIQUE (rate_version_id, origin_zone_id, dest_zone_id, vehicle_class_id)
  CONSTRAINT fixed_routes_distinct_zones CHECK (origin_zone_id <> dest_zone_id)

`public.surcharges`:
  id bigint identity, rate_version_id bigint not null
  code text not null                -- i18n key stem: airport_pickup, night, waiting_airport,
                                    -- waiting_city, extra_stop, child_seat, meet_greet, ski_rack
  kind surcharge_kind not null default 'amount'    -- amount | percent | included
  amount_rappen rappen NULLABLE CHECK >= 0, percent numeric(5,2) NULLABLE CHECK 0..100
  applies_to text not null default 'leg' CHECK in ('leg','booking')
  active boolean not null default true
  UNIQUE (rate_version_id, code)
  CONSTRAINT surcharges_kind_field — amount => percent NULL; percent => amount NULL;
                                     included => both NULL
  Labels are NOT stored: the mock's English `label`/`rule` strings live in the dictionary as
  `price.surcharge.<code>.label` / `.rule` in all four languages (D-08). A stored English string
  frozen into an immutable price_snapshot would put English in a German confirmation email.

`public.service_zones`:
  id uuid PK, slug text unique, iata text nullable, active boolean not null default true
  Display names live in `content_strings` as `zone.<slug>`, not in this table.
  Public read: `service_zones_public_read` `using (active)`.
  Staff: full CRUD via the seventeen-table working set (not admin-only).

Triggers and error codes:
  `tg_pricing_row_frozen` on all three priced tables, BEFORE INSERT and BEFORE UPDATE OR DELETE.
  Raises `using errcode = 'restrict_violation'` = SQLSTATE **23001** — 06-07 corrected D-13's
  `23514`/`P0001` against the applied migration. `23514` is a genuine, separate failure (a column
  CHECK) and both are mapped.
  Availability-only UPDATE on a non-draft version is permitted: the trigger subtracts
  `live`/`available`/`active` from its jsonb comparison and returns early when nothing else changed.

RLS on the three priced tables (…23_rls_staff.sql):
  `<t>_admin_insert`  AS RESTRICTIVE FOR INSERT with check (app.is_admin())
  `<t>_admin_delete`  AS RESTRICTIVE FOR DELETE using  (app.is_admin())
  `<t>_admin_update`  AS RESTRICTIVE FOR UPDATE using/with check
                        (app.is_admin() OR app.rate_version_published(<t>.rate_version_id))
  `app.rate_version_published(bigint)` is SECURITY DEFINER precisely because an inline EXISTS would
  evaluate as `vamos_staff` and be hidden by `rate_versions_admin_write` (F-18).

Audit: all four tables are in `tg_audit_row`'s attach list. No manual audit write.
