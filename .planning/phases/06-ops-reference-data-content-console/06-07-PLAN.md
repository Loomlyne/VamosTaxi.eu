<objective>
Replace the mock's per-row `live` switch with the workflow the database actually enforces, and map
the database's error vocabulary to ops copy.

`OpsPricing.dc.html` was designed before Phase 2's schema existed. It mutates each row's `live` flag
directly and has no draft batch and no publish step. `20260823000008_rate_versions.sql` makes that
model impossible: a version is born `draft` (`tg_rate_version_insert_draft`, added by Phase 2's F-04
fix, which now fires on INSERT too), a published version's priced columns are frozen
(`tg_pricing_row_frozen`, F-12, also on INSERT), only `draft -> live` and `live -> retired` are
legal, and a partial unique index means there is exactly one live version ever. Publishing is the
launch trigger for the entire platform — the single statement that opens the charge gate — which is
why it is the most guarded statement in the schema and why the console must treat it as a deliberate
two-step, not a toggle.

**One correction this plan must carry.** 06-CONTEXT D-13 and 06-RESEARCH both name the publish
failure as SQLSTATE `23514` or `P0001`. Reading the migration, every relevant raise is
`using errcode = 'restrict_violation'`, which is SQLSTATE **`23001`** — `23514` is `check_violation`
(a different, also-possible failure) and `P0001` is the code only when no errcode is supplied, which
never happens on these paths. D-13's rule (branch on the code, never on message text) is honoured
exactly; the code itself is corrected against the applied migration.

Purpose: an admin can see what is still unpriced and cannot publish until it is not.
Output: the version list, the completeness checklist, the publish action, and a shared SQLSTATE map.
</objective>

<interfaces>
`public.rate_versions` (…08_rate_versions.sql):
  id bigint identity PK, slug text unique, label text, status public.rate_version_status
  ('draft'|'live'|'retired'), note text, created_at, created_by uuid, published_at, published_by uuid
  CHECK rate_versions_published_stamp: status = 'draft' or published_at is not null
  UNIQUE INDEX rate_versions_one_live on ((true)) where status = 'live'

The three completeness predicates the trigger uses — mirror them EXACTLY:
  distance_rates: rate_version_id = v AND available
                  AND (base_fare_rappen IS NULL OR per_km_rappen IS NULL OR min_fare_rappen IS NULL)
  surcharges:     rate_version_id = v AND active AND kind <> 'included'
                  AND coalesce(amount_rappen, (percent * 100)::integer) IS NULL
  fixed_routes:   rate_version_id = v AND live AND price_rappen IS NULL

SQLSTATE map (read from the applied migration, not from the research doc):
  23001  restrict_violation   — every raise in tg_rate_version_transition,
                                tg_rate_version_insert_draft, tg_pricing_row_frozen, tg_append_only
  23505  unique_violation     — rate_versions_one_live (a second live version), or a slug collision
  23514  check_violation      — rate_versions_published_stamp, or a `rappen >= 0` domain check
  42501  insufficient_privilege — a forgotten wrapper, or a dispatcher reaching an admin-only write
  P0002  no_data_found        — 06-01's staff_update_self against a missing row

RLS reality for this screen (…23_rls_staff.sql):
  rate_versions_admin_write  AS RESTRICTIVE FOR ALL using app.is_admin()  -> a dispatcher reads ZERO ROWS
  distance_rates/fixed_routes/surcharges: *_admin_insert, *_admin_delete restrictive to admin;
  *_admin_update permits a non-admin ONLY when app.rate_version_published(rate_version_id) —
  i.e. a dispatcher may toggle availability on a PUBLISHED version and nothing else.

Seed reality (packages/db/supabase/seed.sql): exactly one `draft` rate_versions row, every priced
column NULL, and no `live` row. That is the state the publish button must be inert against.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dispatcher session -> `/ops/pricing` | A non-admin staff session reaching the route that opens the platform's charge gate |
| Server Action -> `rate_versions.status` | The single statement that makes pricing live for every future quote |
| DB error -> ops copy | An error surface that must not leak internals and must not be parsed from prose |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-40 | Elevation of Privilege | publish action | mitigate | `requireAdminClaims()` in the action and in the page; `rate_versions_admin_write` (RESTRICTIVE FOR ALL, `app.is_admin()`) is the real gate — a dispatcher gets zero rows, proven by `ops-role-gate.spec.ts` |
| T-06-41 | Tampering | publishing a half-priced version | mitigate | `tg_rate_version_transition`'s three completeness checks are the gate; the checklist mirrors them and the spec asserts an incomplete publish is refused with 23001 |
| T-06-42 | Tampering | inserting a version already live | mitigate | `tg_rate_version_insert_draft` (Phase 2 F-04) forces every INSERT to be born draft with null stamps; the action never sets `status` on insert |
| T-06-43 | Tampering | a second live version | mitigate | `rate_versions_one_live` partial unique index raises 23505; the UI maps that code to its own copy rather than assuming success |
| T-06-44 | Information Disclosure | raw DB errors in the UI | mitigate | `mapSqlState` returns an i18n key per code and never touches `err.message` — grep gate returns 0 for `message` |
| T-06-45 | Repudiation | unattributed publish | mitigate | `published_at`/`published_by` are stamped by the trigger from `app.uid()`, not trusted from the caller; `tg_audit_row` records the before/after diff with `actor_kind='staff'` |
