<objective>
Give staff control of the home page's review wall: publish, hide, reorder, edit the manual ones, and
attach an avatar.

`OpsReviews.dc.html` already models most of this correctly — it has the publish toggle, the verified
mark and a move-up affordance. Three things change on contact with the applied schema, and each is a
correctness point rather than a port detail.

**`locked` is real and the database will not enforce it.** `reviews.locked` is
`generated always as (source <> 'manual') stored`. Four of the five seeded reviews come from Google,
Tripadvisor and Trustpilot, so four of five are locked. ADR-008's rule is that an imported review's
words came from the platform and are never rewritten — but there is no trigger and no policy behind
the flag. It is advisory. The console is therefore the only gate, which means the refusal has to be
written deliberately, in the validator, and proven by a test. A generated column also cannot appear in
an INSERT or UPDATE column list; naming it raises before the statement runs.

**Reordering has a tie problem the seed hides.** D-25's move is an adjacent `sort_order` swap. The
seeded rows are 1…5, so a naive swap works on day one — but a review created through this console
defaults to `sort_order = 0`, and two rows at 0 swap to two rows at 0, which is a move button that
does nothing and looks broken. The move action therefore rewrites the affected ordering as a dense
sequence with the two positions exchanged, in a single transaction, rather than exchanging two values
and hoping they differ.

**Hiding a review is a public-cache event.** `reviews` is one of the five tables on the cacheable
`HYPERDRIVE` binding (`PUBLIC_TABLES`), and the public home section reads it through `publicSql`.
`revalidatePath` clears Next's render cache; it does not clear Hyperdrive's query cache. OPS-08 says a
hidden review stops appearing, and the honest version of that promise names the window rather than
pretending there is none.

Purpose: the review wall is curated from the console, and a hidden review is genuinely hidden.
Output: one table, one form, five Server Actions, one spec.
</objective>

| staff edit -> `public.reviews` | Copy that is published verbatim on the home page as a customer's own words |
