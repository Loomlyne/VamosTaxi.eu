<objective>
Port `OpsFleet.dc.html`'s chauffeurs half onto `public.chauffeurs`, with real photo upload and the two
fields the mock stored as free strings now backed by the schema's actual shapes.

`OpsFleet.dc.html`'s chauffeur rows carry `vehicle` as a plain string and no language list at all. The
applied schema is stricter and more useful: `default_vehicle_id` is a real FK to `public.vehicles`
(`ON DELETE SET NULL`, so retiring a vehicle clears a default rather than blocking), and `languages`
is a real `text[]` of ISO codes rather than prose. Both changes turn a display field into something
dispatch can filter on later, and both need a control the mock does not have.

Two things deserve care beyond the CRUD.

**A licence is an operational fact with a date on it.** `licence_expires_on` is nullable, and a
chauffeur whose licence has expired is not a styling problem — it is a driver who must not be
assigned. The row states it plainly in semantic danger, and the sort puts expiring licences where
someone will see them. It is exactly the state a generic admin UI reaches for an amber pill to
express, which is why Law 02 gets named here.

**A chauffeur's record is staff personal data.** Full name, phone, email and licence number are
personal data under nFADP and GDPR. They are legitimately visible to the dispatchers who assign work,
which is why `chauffeurs` sits in the shared staff working set — but a licence number has no reason to
appear in a list column, a URL, or a log line. This plan keeps it inside the detail form only.

The `user_id` column stays out of scope. It exists so a chauffeur can one day hold an auth account;
no chauffeur-facing surface ships in V1, linking one would need the service-role key, and the column
is nullable. This plan writes it nowhere and says so.

Purpose: dispatch has a real, current chauffeur roster before Phase 8 needs to assign against it.
Output: one table, one form, five Server Actions, one spec.
</objective>
