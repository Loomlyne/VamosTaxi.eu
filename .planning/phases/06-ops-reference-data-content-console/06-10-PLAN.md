<objective>
Replace `OpsContent.dc.html` — a link directory to other page mocks — with the string editor I18N-07
actually requires, reading and writing `public.content_strings` directly.

The mock is not a port candidate. It renders a rail of page names and a panel whose only affordance
is "open this page in a new tab"; its own intro copy says *"Copy is edited on the page itself."* That
sentence describes the design-mock era, where copy lived in markup. It stops being true the moment
`content_strings` is the source. This screen is designed fresh (finding a).

**Three facts, never one.** `20260823000007_content_and_reviews.sql` carries a long comment
explaining why `content_strings` has `pending_value`, `non_translatable` and `no_param_reason`
instead of one `translatable` boolean, and it names the failure precisely: *"drop this flag and, when
Phase 6 renders from this table instead of the JSON, a pending value silently becomes a stated fact
on the live cookie page."* The four language cells of a `pending_value` row hold the same English
string **on purpose** (`about.business-bags` in the seed is exactly this) — an editor that treats
"all four languages identical" as an error, or that offers one translatable switch, reintroduces the
failure the column split exists to prevent. `no_param_reason` is `text`, not a boolean: an empty
string is a missing reason, and the coverage gate already refuses it.

**The number is not 600.** ROADMAP's fourth success criterion sizes this work against a
~600-string legal dictionary. That premise is stale (D-16): the dictionary holds 1,516 leaf keys,
`content_strings` is seeded with all 1,516, and every one is translated apart from the proper-noun
residuals. So the editor's job is finding the handful of rows that need a human and editing them —
server-side filter, server-side search, namespace rail — not paging a translator through 600 blanks.

Purpose: staff can change site copy in four languages without a deploy, and can see what is still
owed rather than guessing.
Output: a filtered string table, two Server Actions, a legal-coverage view, one spec.
</objective>
