<threat_model>
| Threat | Mitigation |
|---|---|
| Anyone can make an empty account for any address by asking for a link | Owner's choice (D-01). Same per-IP and per-address limits as today; the account is unconfirmed and unusable until the mail's own link or code is used |
| A finish request writes another person's record | The e-mail is the session's own, never the client's; `getUser()` verified server-side |
| Skipping the tick by editing user metadata | "Must finish" is decided in SQL from auth.users, staff and the agreement table, none writable by the customer |
| Address probing through the sign-in link | One answer body for every address, kept; the floor timing kept |
| Finish page cached with someone's address | The address comes from `/api/auth/session` (private, no-store), never from the HTML |
| A database failure locks customers out | Session reader fails to `finishRequired: false` and logs |
</threat_model>
