<decisions>
## Implementation Decisions

### Phone and tablet booking (comments 4, 5)
- **D-01:** Phone (390) AND tablet (768) get the new pattern: the hero shows ONE bar. Empty, it invites to book ("Where to?"-style, copy in the UI-SPEC); filled, it shows the trip in short. Laptop (≥1081) keeps the 26.3 home box unchanged.
- **D-02:** A tap on the bar opens a full-screen sheet: steps, a progress mark ("1 of 4"), Back, and a close button that returns to home with nothing lost (entries kept for the tab session only; home still never resumes a booking or a draft — D-05 of 26.3).
- **D-03:** Four steps, same order as the laptop box: 1 From (+ flight number on the same step when From is an airport) · 2 To · 3 When · 4 Travellers → SEE PRICES → `/checkout` with the trip in the URL, as today.
- **D-04:** One button at the bottom of each step. It is never disabled: when the step is incomplete, a warning replaces the hint and names what is missing.
- **D-05:** When the page scrolls, the bar docks under the header.
- **D-06:** The owner's example picture is from ALMAR — take the pattern only (one bar, full-screen steps, close button). Colours, type, buttons, icons and spacing are the Vamos design system. No glow, no tinted yellow. Four languages, Arabic RTL, 390/768 checked, 54 px fields and main button.
- **D-07:** Needs a UI-SPEC signed by the owner before any code.

### Flight number and airport fee (comment 6, owner answer 2026-09-29)
- **D-08:** The airport pickup fee is added only when the PICKUP ADDRESS is an airport. A flight number alone adds nothing. (Today `lines.ts:584-586` also triggers the fee from a flight number — this is a change in the calculation trigger, not in amounts.)
- **D-09:** Pickup at an airport → the flight number is asked and required (unchanged). Any other pickup → a flight number field is available but OPTIONAL and adds no fee. Applies to the home box, the phone/tablet sheet, checkout's Edit trip, and the dashboard New trip form.

### One form, automatic fare parts (comment 6)
- **D-10:** The customer types pickup and destination only. The server applies: start + per km; + airport pickup fee when the pickup is an airport (D-08); + at most ONE matching city-to-city or canton-to-canton amount (no match adds nothing); + each ticked extra; then VAT; then voucher (fixed coupon off before VAT, unchanged). All amounts from the dashboard price book. No number is invented or changed.
- **D-11:** Research verdict (read-only, code + live): all four owner cases are already combined automatically by `priceQuote` — this phase is a form/wording change plus D-08. Live facts 2026-09-29: price book row 18 has no airport surcharge row (no double airport charge); its 6 city pairs are all switched off, so today a city-to-city trip adds nothing until the owner publishes pairs (draft row 19 has 975 switched on). Owner controls pricing; not a defect.
- **D-12:** Server tests prove the four cases with fixture price-book rows: plain; airport pickup; city pair; everything together with a ticked extra (+ airport drop-off adds nothing; + flight on a non-airport pickup adds nothing per D-08; + `fare_kind` changes nothing).
- **D-13:** Service links ("Airport transfers", "City to city", "Hourly", …) STAY in the header, footer, services cards and everywhere as services; each opens the same booking flow, which adapts by itself to the trip. (Point to confirm at signature: V1 books one-way only, so "Hourly" opens the normal one-way form; no hourly booking is built.)
- **D-14:** Remove the dead mode leftovers found by research: `?service=` changing the form, the hero kicker driven by `?service=`, HowItWorks chips setting old modes, dead mode state in `home.dc.html`, `fare_kind` no longer read (still accepted in old quote locks), the Stripe product name "Airport transfer" for every ride (use a neutral trip name), unused `city_price_rappen` path.
- **D-15:** Dashboard New trip: the flight field follows D-09; typing a flight after the quote re-quotes only if it changes the fee under D-08 (it no longer does), and the extras list is the live price-book list, not three hard-coded extras.
- **D-16:** Dashboard pricing copy contradiction fixed ("One pair covers both directions" vs "A to B and B to A are separate rows", `OpsPricing.dc.html:395` vs `401`) — state what the code does (pairs match both directions), in four languages.
