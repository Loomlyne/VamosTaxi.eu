# Phase 26.4 Plan 06: Home clean-up and optional flight Summary

Home holds one trip state: modes, the `?service=` reader, the service kicker and mode-driven hero photos are gone; the laptop box offers an optional flight on non-airport pickups.

## Commits
- 66f81de8: remove trip modes, `?service=` reader, service kicker, extra hero slides, dead T-table mode keys, legacy flight gate methods
- 4b1413f1: D-09 optional flight (opener, optional field, format check, `flight=` sent whenever valid), spec and pins

## What changed
- Kicker is always `t.kicker`; only the default hero slide remains; `#book` hash landing preserved.
- Airport pickup keeps the required flight field. Non-airport pickup (once chosen) shows "Add a flight number"; the revealed field shows "Optional" and "It does not change the price."; a typed flight is kept when the pickup stops being an airport (componentDidUpdate clear removed).
- Submit: any filled flight must match FLIGHT_RE, then `flight=` is sent, airport or not.
- Strings were already in app/vamos-i18n-dict.js (plan 05, de/fr/ar); no dictionary edits needed.
