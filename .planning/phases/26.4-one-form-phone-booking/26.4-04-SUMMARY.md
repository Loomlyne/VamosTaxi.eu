# Phase 26.4 Plan 04: BookingBar Summary

BookingBar Design Component (empty, partial, filled, docked, hover/pressed/focus, expanded, RTL) with a 14-card states gallery and a Playwright spec at four widths in four languages.

## Commits
- 697b2666: BookingBar component + dictionary entries
- a3d0c257: states gallery + spec (also line 2 changed to one ellipsis run after a 390 px look)

## Contract (for 26.4-09)
Props: `docked`, `expanded`, `from`, `to`, `whenLabel`, `pax`, `bags`, `travellersSet`, `complete`, `onOpen`, plus `forceState` (gallery only). Empty = no from/to/when.

## Dictionary
Strings: "Where to?", "Pickup, drop-off, time and travellers", "Add date and time", "Drop-off", "Edit trip:", "1 passenger", "1 bag". Pattern: `^Edit trip: (.+)$`. Counted strings ("N passengers", "N bags", "0 bags") reuse existing patterns. "Pickup" reused. No new "ß".

## Verification
- `playwright test tests/visual/booking-bar-states.spec.ts`: 36 passed (component-390/768/1024/1440 x en/de/fr/ar: 14 bars each 54px +-1, no horizontal scroll, `VamosLocale.coverage` empty, trailing icon mirrored only in ar, click calls onOpen; Enter/Space, aria-haspopup, aria-expanded, accessible names).
- Screenshot of the gallery at 390 px in German checked by eye.
- Law greps clean (no tinted yellow, hex, ß, storage, svg, physical left/right); `--vt-shadow-accent:none` and `.vt-input--focus{box-shadow:none}` present.

## Deviations
1. [Rule 2 - a11y] aria-labelledby added so the accessible name is translated in full (a single-tail aria-label pattern would leave "2 passengers" English in de/fr/ar).
2. [Rule 1 - layout] Line 2 first used flex spans that each truncated ("Tue 29 Se..."); now one ellipsis run.
3. `forceState` prop added (not in the plan's contract) for the gallery states.

## Known limits
- Gallery RTL cards force `dir="rtl"` on the wrapper; their text follows the active language, so the layout mirrors but strings stay English when the page is in English.
- Home wiring is plan 26.4-09.
