<interfaces>
SQL (from 27-01): public.consent_choice(p_policy_version text, p_as_of timestamptz default null)
returns 0 or 1 row (method, necessary, functional, analytics, marketing, recorded_at). Subject is
read from GUC request.vamos.consent_subject, which the caller binds with
`select set_config('request.vamos.consent_subject', <uuid>, true)` on the same transaction.

Existing helpers: `readConsentSubject(cookieHeader)` in `lib/consent/cookie.ts` (returns a UUID or
null, rejects non-UUID); `asAnon(env, fn)` in `lib/db/identity.ts`; `CONSENT_POLICY_VERSION` in
`lib/consent/policy.ts`; `getCloudflareContext` from `@opennextjs/cloudflare`.

New contract (plans 27-06 mock runtime and 27-07 Next banner call this):
GET /api/consent/state ->
 200 { ok: true, chosen: false, policyVersion } when no row or no/invalid cookie;
 200 { ok: true, chosen: true, policyVersion, choice: { method, functional, analytics, marketing,
       recordedAt (ISO string) } };
 503 { ok: false, code: "unavailable" } on DB error.
Headers always: Cache-Control "private, no-store", Vary "Cookie". Never Set-Cookie.
read.ts: type ConsentChoice = { method: string; functional: boolean; analytics: boolean;
marketing: boolean; recordedAt: string }; readConsentChoice(tx, subject: string, asOf?: Date |
null): Promise<ConsentChoice | null> — binds the GUC, calls consent_choice(CONSENT_POLICY_VERSION,
asOf ?? null), normalises recorded_at to an ISO string whether postgres.js returns Date or string.
</interfaces>
