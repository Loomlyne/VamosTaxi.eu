<interfaces>
From packages/db/supabase/migrations/20260823000018_consent_log.sql (read lines 10-31 for the exact
column list before writing fixtures): table public.consent_log with id, consent_subject_id uuid,
customer_id (nullable), policy_version text, method text (accept_all | reject_all |
settings_change), necessary / functional / analytics / marketing bool, locale, recorded_at
timestamptz default now(), plus user_agent, ip_truncated, booking_id. record_consent(...) is
SECURITY DEFINER and takes the subject from GUC request.vamos.consent_subject.

Contract of the new function (plan 27-05 and Phases 28/29 call exactly this):
public.consent_choice(p_policy_version pg_catalog.text, p_as_of pg_catalog.timestamptz default null)
returns table (method text, necessary bool, functional bool, analytics bool, marketing bool,
recorded_at timestamptz). 0 or 1 row. Subject only from the GUC (no subject argument). Filter
policy_version first, then recorded_at <= p_as_of when p_as_of is not null, order by recorded_at
desc, id desc, limit 1. The SQL body is written out in 27-RESEARCH.md "Pattern 1: The reader".
</interfaces>
