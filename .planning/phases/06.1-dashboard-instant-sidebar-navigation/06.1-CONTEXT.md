# Phase 06.1: Dashboard instant sidebar navigation - Context

**Gathered:** 2026-09-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Remove the page-like visual interruption from sidebar hash navigation in the authenticated operations dashboard. A dispatcher selecting any sidebar route stays in the existing dashboard shell and sees the selected view immediately, without a white cover, concealment overlay, or fade/translate animation.

Public-site cross-document transitions are outside this phase and must remain unchanged.

</domain>

<decisions>
## Implementation Decisions

### Dashboard navigation
- **D-01:** Dashboard sidebar navigation is an instant, local hash-route switch; it must not feel like navigation to another document.
- **D-02:** Remove the dashboard-specific `150ms` opacity/translate animation and do not substitute another transition or loading overlay.
- **D-03:** The existing desktop and narrow/mobile sidebar flows must retain their hash-routing, route selection, accessibility, and navigation-close behavior.

### Scope protection
- **D-04:** Keep the public site-wide cross-document page transition intact; the change is limited to the dashboard host / ops shell.
- **D-05:** No redesign, new copy, new visual treatment, or data/API changes.

### Claude's Discretion
- Add or update the narrowest durable automated proof that prevents the dashboard hash-transition animation/overlay from returning.

</decisions>
