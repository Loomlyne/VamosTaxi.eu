<interfaces>
Facts the executor needs (read from the tree, 2026-09-29):
- Playwright 1.62.1. Its `emulateMedia` / context options support `colorScheme`, `reducedMotion`,
  `forcedColors`, `contrast` — NOT reduced transparency. So the pin must go through CDP:
  `const cdp = await page.context().newCDPSession(page); await cdp.send("Emulation.setEmulatedMedia", { features: [{ name: "prefers-reduced-transparency", value: "reduce" }] });`
  All four projects are `devices["Desktop Chrome"]`, so a CDP session is always available.
- Playwright re-sends `Emulation.setEmulatedMedia` itself whenever a spec calls `page.emulateMedia(...)`,
  which drops our feature. Call sites that must re-pin afterwards:
  tests/visual/home-reviews.spec.ts:80, tests/visual/home.spec.ts:35, tests/visual/home-why-vamos.spec.ts:92,
  tests/visual/site-footer-animation.spec.ts:37, tests/visual/home-services.spec.ts:167,
  tests/visual/home-how-it-works.spec.ts:77, tests/visual/home-widget.spec.ts:81,
  tests/integration/lenis.spec.ts:128.
- Specs that create their own pages (bypass the `page` fixture): tests/integration/lenis.spec.ts
  (`browser.newContext`, line ~116) and tests/integration/lang-switch.spec.ts.
- 82 spec files import from "@playwright/test" today (tests/visual: 61 files, tests/integration: 47).
- `prefers-reduced-transparency` appears only in `apps/web/components/shell/SiteHeader.css` and
  `app/pages/SiteHeader.dc.html`, so pinning it cannot move any other component's pixels.
