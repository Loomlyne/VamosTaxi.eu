Owner decisions captured from the four in-app comments:
- The visible Cloudflare Turnstile confirmation panel at `#ct-turnstile > div > div` must disappear entirely from the resting contact form. Verification remains mandatory and server-side Siteverify remains unchanged: `success`, `action === "contact"`, and the approved hostname allowlist must all pass before payload normalization, SQL, idempotency lookup, provider access, or send.

Replace the current literal “TikTok” text with the standard TikTok music-note vector, using the existing inline-mask pattern for third-party brand marks.

Cloudflare’s explicit-render configuration supports `appearance: "interaction-only"` with `execution: "execute"`: the widget is not visible in the resting form and the challenge begins only after a valid submit attempt. The existing static/DC form currently assumes a token is issued during render, so its callback, submit state, retry/reset behavior, and route tests must be adapted together. A static visibility hide is forbidden because it would leave an inaccessible or non-functional challenge.

Scope fence: no redesign, no changes to the protected API contract or database/outbox authorization, no changing social URLs, no new mail provider, no real mail send during implementation, no live DNS, and no production deployment.
