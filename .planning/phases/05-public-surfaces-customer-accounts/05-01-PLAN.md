## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> middleware | An untrusted, attacker-controllable cookie jar crosses here on every request |
| Worker -> Supabase GoTrue | The only party that can validate a JWT signature lives on the far side |
| repo -> built client bundle | Anything that reaches `.open-next/assets/**` is public forever |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | server-side session reads | mitigate | `getUser()` only; a CI-visible grep asserts `getSession(` appears nowhere under `apps/web/lib`/`apps/web/app` (Task 2 acceptance) |
| T-05-02 | Denial of Service | middleware cookie write | mitigate | D-02's single-instance mutation; Task 3 asserts `getSetCookie()` returns separate entries, so the folding regression fails a test rather than logging a customer out silently |
| T-05-03 | Information Disclosure | `NEXT_PUBLIC_*` surface | mitigate | No browser Supabase client exists; `scripts/public-env-allowlist.json` keeps `SUPABASE_URL`/`SUPABASE_ANON_KEY` in `forbidden_substrings` and `allowed` stays `[]` |
| T-05-04 | Information Disclosure | committed secrets | mitigate | `.dev.vars.example` carries names and sources only; `.dev.vars` is git-ignored; every real value reaches the Worker via `wrangler secret put` |
| T-05-05 | Elevation of Privilege | Server Action surface | mitigate | `signOutAction` takes no argument and derives identity from the cookie jar via `getUser()`; no action in `lib/auth/actions.ts` accepts a caller-supplied user id |
| T-05-SC | Tampering | pnpm install | mitigate | All five packages carry an `[OK]`/Approved slopcheck verdict with source repo and empty `postinstall` in 05-RESEARCH.md's audit; versions re-verified against the registry before pinning; drift recorded, not absorbed |
