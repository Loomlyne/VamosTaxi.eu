notify the owner.

    `apps/web/lib/turnstile.ts`: `verifyTurnstile(secret, token, { action, idempotencyKey, remoteip })`
    POSTs form-encoded parameters to Cloudflare's `siteverify` endpoint and returns
    `{ ok: true }` or `{ ok: false, codes }`. Rules:
      - `secret` is passed in rather than read from the environment inside the helper, so the
        function is directly unit-testable and has no hidden binding dependency.
      - When `secret` is undefined, return `{ ok: false, codes: ["missing-secret"] }` and log
        once — a missing secret must never be treated as a pass.
      - The `action` and `idempotency_key` parameters are always sent (D-24, D-22).
      - The response is parsed defensively; a non-200 or unparseable body is
        `{ ok: false, codes: ["unavailable"] }`, never a throw that becomes a 500.
      - A timeout (`AbortSignal.timeout`) bounds the call so a slow Cloudflare cannot hold a
        Worker invocation open.
      - The helper is pure with respect to the request: it takes `remoteip` as a parameter, so
        the route decides what to pass and the header parsing is visible at the call site.

    `apps/web/lib/turnstile.test.ts` (Vitest, `fetch` stubbed, no network): success, failure with
    `error-codes`, missing secret, non-200 upstream, unparseable body, and a case asserting the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet -> /api/contact, /api/partner-application | Unauthenticated endpoints that write to the database and send mail |
| route -> Cloudflare siteverify | A third-party call whose failure must not become a pass |
| route -> Postgres | An anonymous identity reaching a definer RPC |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-58 | Denial of Service | form spam reaching the owner's inbox and the database | mitigate | D-22's always-on server-verified Turnstile runs first; a client-supplied "verified" flag does not exist in the schema, so it cannot be trusted; `idempotency_key` collapses retries |
| T-05-59 | Spoofing | siteverify failure treated as a pass | mitigate | Missing secret returns `{ ok:false, codes:["missing-secret"] }`; a non-200 or unparseable upstream body returns `{ ok:false, codes:["unavailable"] }`; unit tests cover both |
| T-05-60 | Elevation of Privilege | anonymous write reaching a table directly | mitigate | D-23: `asAnon` on `HYPERDRIVE_NOCACHE` calling plan 05-08's definer RPC; `anon` holds no table privilege (proven by that plan's pgTAP `42501` cases) |
| T-05-61 | Tampering | SQL injection through form fields | mitigate | Every value is a bound parameter in a tagged template; `tx.unsafe(` appears nowhere in either route and a grep asserts it |
| T-05-62 | Information Disclosure | validation errors as a schema map | mitigate | The response carries a single `code`; no zod `issues`/`flatten`/`fieldErrors` crosses the boundary and a grep asserts it |
| T-05-63 | Information Disclosure | a submission served from a cached read | mitigate | Neither route imports `publicSql`; neither table is granted to `vamos_public`, so a cacheable read of this data is impossible by grant |
| T-05-64 | Repudiation | a record written but never notified, or notified twice | mitigate | The email is sent only when the RPC reports `created: true`; a send failure after a successful write logs and returns success rather than inviting a duplicate submission |
| T-05-65 | Information Disclosure | HTML injection into the owner notification | mitigate | The notification is rendered through `packages/emails`' shared layout, whose single `escapeHtml` helper every interpolation passes through (plan 05-12) |
| T-05-SC | Tampering | package installs | mitigate | This plan installs nothing new — `zod` and `resend` were pinned by plan 05-01 against 05-RESEARCH.md's `[OK]` audit |
</threat_model>
