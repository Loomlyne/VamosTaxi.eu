<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form -> /api/partner-application | Untrusted input carrying personal and licensing data |
| consent checkbox -> stored record | The stored booleans are the evidence that consent was given |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-97 | Denial of Service | application spam | mitigate | D-22's always-on widget with `action="partner-application"`, verified server-side by plan 05-13; no client path can fabricate a token |
| T-05-98 | Repudiation | a stored application with a false consent record | mitigate | `z.literal(true)` on both consents in the shared schema, enforced client-side and server-side; a test proves an unticked box issues no request at all |
| T-05-99 | Information Disclosure | licensing/permit detail echoed back | mitigate | The route returns `{ ok, created }` or a `code` only; no submitted value crosses the response boundary (plan 05-13) |
| T-05-100 | Information Disclosure | an invented permit requirement or vehicle class | mitigate | Both remain `PendingSlot` pills, English in every language, asserted present in all four locales |
| T-05-101 | Information Disclosure | the Turnstile site key or secret in the client bundle | mitigate | The site key arrives as a server-rendered prop; no `NEXT_PUBLIC_TURNSTILE*` identifier exists; `forbidden_substrings` already covers `TURNSTILE_SECRET` |
| T-05-102 | Repudiation | consent captured cookie-only | accept | This page stores its two consents as columns on the application row; the cookie-banner consent record is SITE-08's, deferred to Phase 10 with `consent_log` (D-20) |
| T-05-SC | Tampering | package installs | mitigate | This plan installs no package. |
</threat_model>
