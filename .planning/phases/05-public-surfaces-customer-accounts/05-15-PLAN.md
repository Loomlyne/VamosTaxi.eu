<objective>
Port the services section and the card it is made of — the one component in this phase whose
mock declares a visual effect the platform laws constrain.

`ServiceCard.dc.html` declares `shineColor`, `shineIntensity` and `proximity`. Whatever the mock
does with them, the law is not negotiable: no glow anywhere in this application, ever — no
coloured or soft glow on hover, focus, press or active, no `box-shadow` with a colour tint, no
blurred halo. So this plan ports the card's proximity RESPONSE (a fill and border step that
tracks the pointer) and not a halo, and records the substitution rather than shipping a law
violation because the mock had one.

`app/[locale]/page.tsx` is untouched; composition is plan 05-21.

Purpose: SITE-01's services section is the page's main navigation into the product, and the card
is the piece most likely to be forked later if its states are not all built now.
Output: `ServiceCard` with seven states, `Services`, a dev route and four-language baselines.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pointer input -> CSS custom property | A pointer handler writes values consumed by a stylesheet |
| card href -> navigation | Cards are the section's main navigation into the product |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-71 | Tampering | pointer-driven custom properties | mitigate | Only two numeric properties are written, both clamped to the card's own bounding box; no user-supplied string ever reaches a style value |
| T-05-72 | Denial of Service | unthrottled `pointermove` | mitigate | The handler is `requestAnimationFrame`-throttled, registered only on pointer-capable devices, removed on unmount and disabled entirely under reduced motion |
| T-05-73 | Spoofing | a card linking to a route that does not exist | mitigate | Every `href` is a next-intl navigation helper against a route this phase has built or the home booking anchor; a 404 from the home page's main navigation is a trust failure, not a cosmetic one |
| T-05-74 | Elevation of Privilege | a "disabled" card that is still clickable | mitigate | `state="disabled"` renders a non-link element with `aria-disabled`; Task 3 asserts it is not focusable and carries no `href` |
| T-05-75 | Information Disclosure | a price on a marketing card | mitigate | Grep-asserted: no `formatAmount` and no `CHF` in this section; pricing is Phase 4's and appears only inside the widget |
| T-05-SC | Tampering | package installs | mitigate | This plan installs no package. |
</threat_model>
