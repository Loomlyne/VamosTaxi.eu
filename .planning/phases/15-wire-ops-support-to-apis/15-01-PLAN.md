- PatchTicketInput is { status?: string; reply?: string }
- PatchTicketResult ok false reasons: not-found | invalid-status | empty-reply | send-failed
- Status-only path uses staffPatchStatus. Reply path sends Resend then inserts outbound_staff. Do not reopen that path.

From resolve-booking-id.ts:
- resolveStaffBookingId(env, claims, key) → uuid or null
- Lookup: erased_at is null AND (id::text = key OR reference = key)
- Must run asStaff. Do not SELECT bookings as system role.

Save JSON (any of the three keys selects the branch):
- { phone, booking_ref, note }
- Do not combine with { reply } or { status } on the same request (treat as invalid-status).
- Persist phone even if empty string (clear). Persist booking_ref empty (clear chip).
- Note empty / whitespace → no support_messages insert.
- Note non-empty → insert direction staff_note, body_text = trimmed note.
- Filled booking_ref that does not resolve → { ok: false, reason: "invalid-booking-ref" } before any UPDATE/INSERT.
- Route maps invalid-booking-ref to jsonErr 400 (generic overlay; DC does not show the reason string).
- Return { ok: true, status: current TicketStatus } so jsonOk shape stays { id, status }.
