Split out of 30-05 in revision 2.

Why this plan has 23 files (over the 15-file guide): it is one atomic rename. The DC loader resolves a screen by file name, the API whitelist by key, and about a dozen tests read `app/ops/OpsFleet.dc.html` by path; if the rename landed in two commits, the commit in between would leave the shell importing a missing file or tests reading one. The edits per file are one-line substitutions, so the context cost stays small even though the file count is high. That is the accepted reason not to split further.

Purpose: nothing stays half-renamed; 30-07 then edits a screen that already has its final name.
Output: the renamed component, every reference, the moved spec, a pruned public copy.
