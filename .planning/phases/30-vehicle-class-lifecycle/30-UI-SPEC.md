# Phase 30 — UI Design Contract

> Visual and interaction contract for Phase 30, vehicle class lifecycle. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Surface: dashboard (ops): Pricing page class rows, Retire and Go live dialogs, Retired list, Chauffeurs screen, Assign picker. Plus one public block: the `VehicleClasses` section on About and home (title only, added to scope 2026-10-12). Nothing else on Pricing moves.
> **Governing fact:** the owner signed the five design sheets on 2026-10-11 (`30-DESIGN-SIGNED.md`; pictures `screens/sheet-1-table.png` to `sheet-5-chauffeurs.png`). On 2026-10-12 he signed rev 3 (`16a3aa40`) against sheets 1 to 5 and answered the 14 open questions; this revision (rev 4) records those answers. Elements that are new in rev 4 were signed on sheets 6 to 10 on 2026-10-12, with his answers to the two rev 4 questions (Assign line, Arabic count forms). Everything in this contract is signed and is built as written.

Sources: `.planning/decisions/2026-10-11-fleet-lifecycle.md` (signed, includes amendments 2 and 7a), `30-CONTEXT.md`, `30-DESIGN-SIGNED.md`, the five signed sheets, the owner's 14 answers of 2026-10-12, the unsigned prototype `30-prototype-wip.patch` (raw material for strings only), committed code at HEAD, the Vamos design system tokens and bundle.

**Focal point:** the Pricing class table (the "Distance rules" pane). The Live/Draft badge in the class cell is the one new thing a reader's eye should land on; every dialog and the Retired list hang off that table.

## Spacing Scale

The scale is the Vamos 4px token scale (`--vt-space-*` in `design-system/tokens/spacing.css`), not the generic 8-point list. `--vt-space-3` (12px) is a real kit token and is used on the signed screens, so it stays. Every value below is a multiple of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gap, gap between name and badge when wrapped |
| sm | 8px | Gap between dialog checklist rows, gap between the info lines in the Retire dialog, button pair gap |
| md | 16px | Dialog body padding steps, Retired row padding, section gap inside dialogs |
| lg | 24px | Gap between the class table and the Retired section |
| xl | 32px | Not used by new elements (page rhythm owned by Pricing) |

12px (`--vt-space-3`) is used for the gap between the Retired head and its first row, between a Retired row's text block and its button when stacked, and between the two icon buttons in a class row (see Tap areas).

**Tap areas (binding, owner answers 5 and 6, 2026-10-12).** Every control below keeps the 32px look the owner signed and gets a 44px tap area. The tap area is invisible: a centred 44px by 44px hit area on the control (a pseudo-element on a `position:relative` button), never padding, so the drawn size and the row height do not change.

| Control | Visible size | Tap area | Accessible label |
|---------|--------------|----------|------------------|
| DRAFT badge button (class cell) | 32px high | 44px high, at least 44px wide | "Draft: see what is missing" (`draftBtnLabel`) |
| Row icon Edit (`pencil`) | kit `IconButton` `size="sm"`, 32px | 44px by 44px | "Edit" (existing) |
| Row icon Retire (`eye-off`) | kit `IconButton` `size="sm"`, 32px | 44px by 44px | "Retire" |
| Dialog close X (every Phase 30 dialog) | kit `IconButton` `size="sm"`, 32px (`.vt-iconbtn--sm`) | 44px by 44px | "Close" |

- The two row icons sit 12px apart (`--vt-space-3`, was 6px) in the Pricing class table's actions cell only, so their 44px areas do not overlap. This is a prop of the class table, not a change to other `OpsTable` tables.
- The close X keeps the kit look and the kit position; the 44px area stays inside the dialog edge. Escape and scrim click also close.
- The row must not grow: the tap area may extend past the 32px control into the row's own padding, never past the row edge into another row's control.

Other exceptions:
- BRING BACK is the kit `size="sm"` (36px) at 1081px and wider, as sheet 4 draws it on a desktop pointer; at 1080px and narrower it is 44px (`size="md"`).
- Forbidden from the prototype: `padding:10px 16px` on the Retired head (off-scale), `max-width:78px` on the class cell, `padding:8px 16px` on a Retired row (rows are 16px, see Layout).

## Typography

Four sizes, two weights. Badge 11px uppercase is kit-owned (`--vt-label-sm`) and the kit `.vt-btn--sm` 12px button label (BRING BACK at 1081px and wider) is kit-owned too; neither is counted as a page size.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body | 16px (`--vt-body-md`) | 400 | 1.6 | Dialog body sentence, Retire reason input text |
| Label | 14px (`--vt-body-sm`) | 600 for names and item labels, 400 for sentences | 1.45 | Class name in a Retired row, checklist labels, reason text in a Retired row, why-line, error text, last-Live warning in the Retire dialog |
| Small | 13px (`--vt-body-xs`) | 400 | 1.45 | Chauffeur retired flag, count in the Retired head, 0 / 140 counter, chauffeur count line in the Retire dialog, "left out" line under the Assign picker |
| Heading | 20px (`--vt-heading-3`, Qurova) | 600 | 1.18 | Dialog titles only (kit `Dialog`) |

Why 13 and 14 both exist: they are the kit's own `--vt-body-xs` and `--vt-body-sm` steps. The kit Dialog subtitle (`.vt-dialog__sub`) and the existing OpsTable and chauffeur screen already use them, so the two sizes are inherited, not invented. Inventing a single merged size would restyle kit and existing text.

The Retired head reads 14px Poppins at weight 600 with the count at 13px 400, as sheets 1 and 4 draw it. Weight 500 is not used anywhere (the prototype used it in places; remove).

The About block keeps the typography it already has in `VehicleClasses.dc.html`; this phase changes its title text only.

Button labels, badges, kickers: UPPERCASE through the kit (`--vt-label-sm` tracking). Everything else is sentence case.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F6F6F6` page ground, `--vt-bg-surface` white panels, `--vt-border-subtle` grey hairlines | Pricing page ground, table, dialog surface, Retired list, row hairlines |
| Secondary (30%) | Charcoal `#1E1F1F` | Ops sidebar, LIVE badge (`Badge tone="inverse"`), secondary buttons (EDIT CLASS, CANCEL; kit `secondary` renders charcoal, as on the signed sheets), BRING BACK |
| Accent (10%) | Yellow `#FDC20B` | See reserved list |
| Destructive / semantic | `--vt-danger` | Chauffeur "Retired class" flag, missing items in the Go live checklist, failed-action error text, the last-Live warning line in the Retire dialog |
| Positive | `--vt-success` | Done items in the Go live checklist only |
| Muted text | `--vt-text-muted` | Retired row reason, Retired count, chauffeur count line in the Retire dialog, "left out" line under the Assign picker |

Accent reserved for: ADD CLASS (existing primary), RETIRE confirm in the Retire dialog (primary), GO LIVE in the Go live dialog (primary, only while enabled). Nothing else is yellow, except the kit focus ring `--vt-ring` on focus-visible (allowed by the no-glow law): not badges, not the Draft badge, not icons, not the Retired list.

Rules:
- LIVE = `Badge tone="inverse"` (bundle: `background:var(--vt-charcoal-800); color:var(--vt-text-inverse)`). DRAFT = `Badge tone="outline"` (bundle: transparent, `border-color:var(--vt-border-subtle)`, `color:var(--vt-text-secondary)`).
- No RETIRED badge appears on any signed sheet (sheet 4 rows show name, reason, BRING BACK only), so none is built. For the record, the kit default `Badge tone="neutral"` maps to `background:var(--vt-grey-100); color:var(--vt-charcoal-700)` in `_ds_bundle.js` (Badge.jsx); it is not used in this phase.
- Retire is reversible, so it is not red: the row action is neutral charcoal. `--vt-danger` is never used on a Retire control. Red stays for the data problem (chauffeur flag, missing checklist item) and for the one-line last-Live warning, which is plain `--vt-danger` text: no panel, no border, no icon tile, no `Alert`.
- No tinted panels for Draft or Retired rows. Row background is the table's own surface in all states. Retired rows use white with a `--vt-border-subtle` hairline.
- Disabled GO LIVE uses the kit disabled button style (grey, as on sheet 2; no opacity tricks, no custom grey).

## Copywriting Contract

All strings go in the page `T` tables and in `app/vamos-i18n-dict.js` in the same pass. Class names are Latin in every language (D-14a) and sit in `data-vt-no-i18n` with `unicode-bidi:isolate` in Arabic. Numbers and counts sit in `vt-dir-keep`. Strings with a number or a name are `patterns` entries or split nodes (`{{ value }}` splits a sentence into text nodes: translate the parts, wrap the value in `vt-dir-keep` + `data-vt-no-i18n`). German is Swiss ("ss", never "ß"). The Arabic word for chauffeur is the one the dictionary already uses (`سائق`, plural `سائقين` after a numeral); do not introduce a second term.

Label exceptions, recorded: CANCEL and RETIRE are owner-signed labels (sheet 3). They are exceptions to the generic or single-word label rule ("Cancel" and "Retire" as the whole label), kept because he signed them.

Signing status used below: **signed 2026-10-11** (on a sheet), **signed 2026-10-12** (the owner's answers, and sheets 6 to 10 for elements new in rev 4).

Buttons render as CANCEL and RETIRE (kit uppercase). The counter is built as sheet 3 draws it and stays so (binding, signed 2026-10-12): English "0 / 140", Arabic "140 / 0", both in `vt-dir-keep`.

**Count line (owner answer 4).** One muted line, 13px, shown only when the count is above 0. The number is its own span (`vt-dir-keep` + `data-vt-no-i18n`) followed by the translated text: "2 chauffeurs are on this class" / "1 chauffeur is on this class". Built as split text nodes (number node, then `retireCountMany` or `retireCountOne`), not as a `patterns` regex, because a `{{ value }}` splits the sentence into text nodes and the number stays out of the translation. Count = chauffeurs whose class is the class being retired, read from the chauffeur store Assign already uses; if that list has not loaded, the line is hidden (never a guessed number).

**Arabic count forms (owner answer, 2026-10-12, open question 2).** Only these two lines get count-specific Arabic; de, fr, en are unchanged and the rest of the dashboard keeps `سائقين` (later job). The forms follow the dictionary's existing rule for bags (`vamos-i18n-dict.js` patterns, quick 261002): 1 and 2 are said in words with no numeral (the dual already says "two"), 3–10 take the genitive plural, 11–99 the singular accusative, 100 and above the genitive singular (house rule, as for bags; not reachable with today's chauffeur count). The participle agrees with the noun in each form.

**Last-Live warning (owner answer 3).** One red line (`--vt-danger`, 14px, sentence case, no panel), `retireLastLive`. Shown only when the class being retired is Live and no other class is Live. Computed from the loaded class rows. RETIRE stays enabled: warn, never block. A Draft class never shows it.

**Body order (top to bottom):** body sentence (16px), 8px, count line (muted, 13px), 8px, last-Live warning (red, 14px), 16px, Reason label + Textarea + counter, error line (when present), footer buttons. Reason for the order: the facts about the class come first, the consequence sits directly above the optional input and the buttons it applies to, and the reason field, which is optional, stays last. Both lines are absent at zero chauffeurs on a class that is not the last Live one, which is exactly what signed sheet 3 draws.
