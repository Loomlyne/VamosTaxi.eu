# Phase 26.5 Plan 04: PAY account choice and Pay limits Summary

`POST /api/checkout/intent` now takes an optional strict `account` block. The switch, the create tick rule, the guest informed record, the known-e-mail sign-in link and the server-side record write are in. D-20 adds an 8-per-minute-per-IP limit and a 5-presses-per-price cap.

## Behaviour
- Absent block, signed-in request, or guest with the switch off: today's flow, no check, no record (D-09, D-01).
- Create needs the Text 1 tick (`account_consent_required`) and the service-role key on the Worker (`account_create_unavailable`), before Stripe.
- Check order: Turnstile (action account), IP limiter (`account:<ip>`), e-mail bucket (`auth-account:<email>`, missing binding refuses), then `checkout_email_has_account`. Known e-mail: sign-in link, `sign_in_first`, no Stripe. Query failure: `account_check_failed`, no Stripe.
- Only a PKCE `*code-verifier` cookie can ride on `sign_in_first`; no PAY answer carries a session cookie.
- `afterBooking` runs on reuse, attach, race-winner and create paths and calls `record_account_agreement('checkout', booking, null, choice, "2026-09-29", locale, ua, truncated ip)`. Rows go to `account_agreement_records` only. A failure logs the SQLSTATE only; PAY still returns the Stripe URL.
- The Worker never names the service-role key in these files (`serviceRoleConfigured` only).

## D-20
