# Phase 26.5 Plan 02: Account choice components Summary

Two new checkout components with every UI-SPEC state, a dev gallery, two vendored icons and 32 strings in four languages. Nothing is wired into `/checkout` (plan 06).

## What was built

- `AccountChoice`: native `role="radiogroup"` labelled by the kicker, three option cards (guest preselected by the host), whole card clickable, 2px charcoal selection, no yellow. Guest has no tick box; Text 2 shows as a plain 13px line only when `guestAccountsOn`. Create shows the info line plus one unticked `Checkbox` labelled with Text 1 (rich tags link "Terms" and "Privacy notice" to `/{locale}/terms` and `/{locale}/privacy`, opening in a new tab so the checkout is not lost). The box never disables anything. `createAvailable=false` removes the option and treats an incoming `create` as `guest`.
- `CheckoutSignIn`: form stage (email, Turnstile action `account`, EMAIL ME A SIGN-IN LINK, More ways to sign in) and one neutral sent stage (heading in a polite live region with focus, echo of the email, 6-digit code, SIGN IN, SEND ANOTHER LINK behind its own Turnstile instance, Use a different email, hint). No password field. The code field carries the passwords-off removal comment.
- `account-sign-in-api.ts`: the `/api/auth` requests as plain functions so they run under the node test runner. The link body is exactly the contract and never carries `createUser`.
- Gallery `/[locale]/dev/components/checkout-account`: 9 AccountChoice tiles and 10 CheckoutSignIn tiles, all on a mocked fetch.
- Owner texts: Text 1 and Text 2 are in `acctCreateNotice` and `acctGuestNotice`, four languages, byte-identical to the decision file (tags stripped for Text 1). Tests read the decision file and compare.

## Deviations from Plan

1. **[Rule 3] Requests moved to `account-sign-in-api.ts`.** The vitest config has environment `node`, no jsdom, no testing-library, and I may not install packages. Click, focus and fetch behaviour cannot run in a DOM, so the requests became pure functions tested with a fake fetch. The plan's grep `origin: "checkout"` in CheckoutSignIn.tsx therefore counts 0 there; it is in the api file.
2. **[Rule 3] Icons also copied to `apps/web/public/brand/icons/`.** `Icon` reads `/brand/icons/`, a tracked folder, not the gitignored sync output. Without those two files the new icons would 404. Files copied from lucide `main` fetched over HTTP; both equal the upstream bytes (newer Lucide formatting than the older vendored files).
3. **[Rule 3] Extra files:** `CheckoutAccountGallery.tsx` (client half of the gallery, same split as the forms gallery) and `account-sign-in-api.ts`. Not in the plan's list.
4. **Strings not reused across namespaces.** "Sent again just now.", "Sign in", "Send another link" exist in `common`/`ops`, but the checkout code strings ("6-digit code", "Check the code…", "Too many tries…") exist only in the DC mock dictionary, not in the message files. All were added as `checkout.acct*` keys instead; only `contactEmail`, `enter-an-email-address` and `errEmailCheck` are reused. `acctCodeLabel` and `acctCodeError` take a `{digits}` placeholder because i18n:check flags a bare digit.
5. **`acctSentTo` carries a tag:** `Sent to <addr>{email}</addr>` (all four languages) so the address stays left-to-right in Arabic. Wording unchanged.
6. **Merge guard.** `git merge-base --is-ancestor origin/main HEAD` returns 1: origin/main has one commit not in this branch (`a4519cde`, a control-board docs commit). Both guard files (`phase-26-4-laws.test.ts`, `home-laptop-bar.spec.ts`) exist on origin/main and in HEAD, so the 26.4 and 26.4.1 code is present. I did not merge, as instructed.
7. **Dev-only bypass.** With no Turnstile site key and `NODE_ENV !== "production"`, `CheckoutSignIn` skips the widget and uses a dev token so the gallery can drive the flow. Production builds inline `NODE_ENV`, so a missing key in production still shows the widget's failure note. A `previewState` prop exists for the gallery only.
8. The checked state of the design-system `Checkbox` paints its box yellow (`--vt-accent`), the existing 26.3 component, unchanged. The panel's own surfaces use no yellow.

## Not verified

- **Nothing was rendered in a browser.** No pixel check at 1440 / 1024 / 768 / 390, none in de or ar. Layout is reasoned from CSS: `repeat(auto-fit, minmax(200px, 1fr))` gives 3 across at 1440, 1024 and 768 and 1 column at 680 and below; the email row wraps and stacks full width at 680 and below; only logical properties are used (stylelint-use-logical passed); `dir=rtl` drops uppercase and tracking on kickers. The button's vertical offset beside the field (label height plus 6px) is a calculation, not a measurement, and is the most likely thing to need a nudge. German wrapping and Arabic direction are covered only by string render tests (all four locales render without missing keys), not by sight.
- **Interactive behaviour did not run** (no DOM runner): arrow keys, click, focus moved to the sent heading, focus and select on "Use a different email", the `resetNonce` rotation of the Turnstile token, the pending disabled state. The request layer is tested, including that a resend posts the token it is given and that it differs from the first. The component wiring that hands over that fresh token is read, not executed. Recommended: one Playwright pass on the gallery.
- The gallery route was type-checked and linted, not opened.
- Live `/api/auth` was never called.
