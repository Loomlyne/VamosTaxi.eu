## Where main does NOT match "probably already true"
- **The link is not trip-only.** It also carries `class`, `extras`, the Mapbox ids `fid`/`tid`/`gs`, and after Back from Stripe `resume=<quote uuid>&pay=`. None of them opens the booking without the cookie (point 2), but a pasted link does name the first browser's quote. Guard G2 below drops `resume`/`pay` from the address bar when this browser cannot resume. The owner has since answered (D-16a): class and ticked extras may stay in a pasted link, as well as addresses, date and time. Contact data, company, note, voucher and booking reference never carry over. This plan keeps those keys.
- **Signing in links the unpaid booking to the account.** `…/migrations/20260930180000_account_list_grants_and_customer_on_demand.sql:107-111` — `customer_claim_guest_bookings()` sets `customer_id` on every booking with the confirmed e-mail, pending included, and `/api/account/bookings` calls it on every open (`route.ts:30-35`). The booking stays hidden only because each route filters it out.
- **The database lets a signed-in customer read the unpaid row.** `…/migrations/20260910000001_bookings_select_by_contact_email.sql:8-23` (`bookings_select_own`: `customer_id` link OR `contact_email` = JWT e-mail, any status) with the column grant `…/migrations/20260823000021_rls_customer.sql:32-36` (`reference, contact_name, contact_email, contact_phone, status, …` to `authenticated`). Any query run as that customer, including a future route or a direct Data API call with the customer's access token, returns the unpaid booking's reference, name and phone. Company, note and coupon are not granted. 26.5 creates accounts automatically (plan 05), so more people will hold such a session. Guard G1 closes this in the database.

## Guards this plan adds
- **G1 (DB, Task 2):** a restrictive RLS policy on `public.bookings` for role `authenticated` only. The row must not be `quote`, and it must not be `pending` unless `pay_link_sent_at is not null`. Staff (`vamos_staff`), guest (`vamos_guest`, manage token), checkout (`vamos_checkout`) and system roles are untouched. `booking_legs` and `price_snapshots` inherit it through their parent policies.
- **G2 (client, Task 3):** when `/api/checkout/resume` answers `none` or `purged`, `CheckoutForm` rewrites the address bar to `buildTripQuery(trip)` without `resume`/`pay`. This browser then cannot pass the other browser's quote id on. Same-device resume (`open`/`expired`) is unchanged.
- **Tests (Tasks 3-4):** they pin every point above. Sign-in from checkout (plan 03), `sign_in_first` (plan 04), signed-in prefill (plan 06) and account linking must never hand back the reference, company, note or voucher of an unpaid booking.
