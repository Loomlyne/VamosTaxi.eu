<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (dashboard) -> staff API | booking key in the path is untrusted; session claims decide access |
| Worker config -> URL | STRIPE_ACCOUNT_ID and STRIPE_SECRET_KEY are server config; the pi_ id comes from the database |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering | stripePaymentUrl | mitigate | fixed origin https://dashboard.stripe.com; acct_ and pi_ regex-checked; malformed account dropped, malformed pi_ row dropped; no request/query input reaches the URL; unit tests cover `../`, `?`, `#`, whitespace |
| T-31-02 | Spoofing (open redirect) | GET stripe-payments | mitigate | the route returns data only, never redirects; the DC opens only server-returned URLs (plan 31-09) |
| T-31-03 | Information disclosure (IDOR) | GET stripe-payments | mitigate | withAdmin (admin role + active staff row + document-navigation 404), resolveStaffBookingId as asStaff under RLS, 404 for unknown keys; response holds only that booking's kind, amounts, captured time and URL |
| T-31-04 | Information disclosure | STRIPE_ACCOUNT_ID | accept | not a secret; used only in server code on a staff-only route; never serialised into a public page (memory "no internal ids in public") |
| T-31-05 | Elevation | withStaff vs withAdmin | mitigate | source pin test asserts withAdmin and no withStaff/POST |
</threat_model>
