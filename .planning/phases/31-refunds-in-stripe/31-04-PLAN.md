## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe event -> Worker | refund id and amount re-read from Stripe by the webhook consumer (plan 31-05) |
| Worker -> Resend -> customer inbox | personal data leaves the system to the booking's own addresses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-16 | Information disclosure | refund mail recipients | mitigate | recipients only from checkout_booking_for_email through refundMailRecipients (lowercased, deduped); none -> no send, claim settled "no_recipient"; never from event metadata |
| T-31-17 | Repudiation / annoyance | duplicate customer mails | mitigate | notification_claim_refund dedupe 'booking:refund:<re_id>' (one claim per refund), Resend idempotencyKey 'refund-mail:<re_id>' (+ ':payer'); tests for null claim and for retry by claim id |
| T-31-18 | Tampering | amount in the mail | mitigate | amount = Stripe refund amount from the event or the booking_refunds row recorded from it; tests pin pass-through; no arithmetic in refund-mail.ts |
| T-31-19 | Information disclosure | logs | mitigate | emit carries bookingId, refundId, claimId, stage only; tests assert no '@' and no amount in emitted fields |
| T-31-20 | Spoofing (copy) | unsigned wording | mitigate | blocking signature checkpoint; decision-file byte pins |
| T-31-20a | Repudiation (silent lost mail) | claim failure | mitigate | failed or empty claim -> one info@ alert (reference + re_ id only, idempotency key 'refund-mail-alert:<re_id>'); alert failure logged with ids and stage; tests for both paths; alert text listed for the owner's sign-off in the 31-13 hand-over |
