# 26.3-G8 Summary: staff pay-link, Take card and extra-fare payment on Stripe's hosted page

Owner decision D-48. No card form of ours anywhere, the ops dashboard included.

## What changed

- **Send pay-link (staff):** `staffPayLink` checks the stored session with `hostedSessionIsPayable` (open, url, CHF, amount equal) instead of `sessionIsPayable`, so hosted bookings (site flow and New trip) no longer answer 409 `session-expired`. It mints the token and e-mails `/checkout/pay/<token>`; the response no longer carries `client_secret_hex` / `publishable_key`.
- **Take card (staff):** new `POST /api/staff/bookings/:id/take-card` (`staffTakeCard`). It loads the unpaid booking (same refusals as pay-link, plus expired snapshot) and calls the shared `openHostedPayLinkSession`, which reuses the open hosted session or creates one (`hosted_page`, card plus TWINT flag, Stripe expiry clamp). Back returns to the dashboard booking. The dashboard opens the URL in a new tab (tab opened on the click so the popup blocker allows it).
- **Shared builder:** `lib/checkout/pay-link-hosted-session.ts` is the one get-or-create for the customer's `pay-link/open` and Take card; the route keeps every guard before it.
- **Extra fare:** `acceptPaidEdit` creates a hosted `kind=extra` session (reuse check is `hostedSessionIsPayable`); success goes through `/api/checkout/return` (which settles through `handleStripeMessage`, kind=extra path unchanged; the webhook stays the durable path), Back goes to the ops booking. New `POST /api/staff/bookings/:id/extra-pay` (`staffExtraPayUrl`) reads the open extra session (must be open, `kind=extra`, same booking) and returns its URL. The pending-edit panel shows "Open Stripe payment page" and "Copy payment link" once an extra session exists. The extra session has no `quote_id` on its payment intent.
- **Removed:** `ui_mode: "elements"` and `returnUrl` from `createCheckoutSession` (`uiMode` is now the literal `"hosted_page"`), `sessionIsPayable`, the dashboard Elements mount, `hexToUtf8`, `loadStripeJs`, the `js.stripe.com` script, and the CSP hosts `js.stripe.com`, `*.js.stripe.com`, `checkout.stripe.com`, `hooks.stripe.com`, `link.com`, `*.link.com`, `api.stripe.com`, `*.stripe.com` (img). Nothing of ours loads Stripe.js, frames Stripe or calls Stripe from the browser; card entry is a top-level navigation to Stripe.
- **LOW items:** `pay-link-gate.test.ts` asserts `intent/route.ts` passes `legacyUaeAccount: stripeAccountIsLegacyUaeTest(` and that the runner stops on it before minting a token. `runPayLinkIntent`, `okIntentResponse`, `sessionWithSecret`, `payableFromOpen`, `mode: "pay_link"`, `publishableKey` and `returnUrl` deleted from `intent.ts`. `checkout.emailFailed` removed from en/de/fr/ar, `seed.sql` (regenerated) and its test.
