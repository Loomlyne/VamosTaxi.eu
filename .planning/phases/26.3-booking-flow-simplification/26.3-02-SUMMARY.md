# Phase 26.3 Plan 02: Paid return, customer link, no checkout pay-link Summary

A Stripe-paid return now always lands on the confirmation (settle and mail failures cannot turn it into a failure page), signed-in checkout bookings carry the customer's `customers.id`, and the checkout client can no longer send a "Not paid yet" pay-link e-mail.

## What changed

**Task 1 (bd11a29d)**
- `settle.ts`: `deliverConfirmation` wrapped in try/catch; failure emits `error confirmation_mail_failed {bookingId}` and the result stays `{ ack: true }` (no queue retry).
- `return-settle.ts`: `readReturnSession` (one Stripe retrieve, never throws; error → `unknown`), `sessionFacts` (uuid-validated quote id from `metadata.booking_id`, reference from `metadata.booking_reference`/`client_reference_id` validated by `BOOKING_REFERENCE_RE`), `settlePaidReturn(env, session)` now takes the retrieved session, `returnRedirectTarget(deps, input)` holds the D-27 decision:
  - invalid session id → `/{loc}/checkout`
  - Stripe read failure / no env → `/{loc}/checkout?pay=unknown`
  - unpaid → `/{loc}/checkout?resume=<quote uuid>&pay=unpaid`
  - paid (settle ok, failed or throwing) → `/{loc}/confirmation/<ref>`; ref from query → DB lookup → session metadata; none → `/{loc}/confirmation?session=<cs>`
  - duplicate → `/{loc}/confirmation/<ref>?charge=refunded` (unchanged)
- `return/route.ts`: thin; no `/checkout/payment` or `pay=failed` left.

**Task 2 (09096fba)**
- `actor-customer.ts`: `resolveActorCustomerIdWithDeps` + `resolveActorCustomerId(env, request)`; sub from `customerClaims` (Supabase `getUser`) only, uuid-checked, then `select public.customer_id_for_user(sub::uuid)` via `asCheckout`. No session / no row / error → `null` (guest), error logged as `actor_customer_lookup_failed`. Session module loaded by dynamic import so the pure core is vitest-loadable.
- `intent` and `pay-link` routes: `actorCustomerId: await resolveActorCustomerId(env, request)`. `evaluateCoupon` already receives `deps.actorCustomerId` inside `lib/checkout/intent.ts`, so no extra wiring.
- `CheckoutClient.tsx`: removed `sendPayLink()`, the "Send pay link" button, the payer e-mail input, `payerEmail`/`payUrl`/`payLinkKept` state, the pay-result block, the two `setPayerEmail` prefills and the now-unused `billingKindFromFields`. Nothing else restructured.
