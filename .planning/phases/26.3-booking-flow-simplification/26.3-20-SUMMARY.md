# Phase 26.3 Plan 20: Ops half of generic extras Summary

Ops now shows every ticked extra by its owner-given name, prints the fare block from the stored snapshot lines without derived amounts, and customer time changes store the true Zurich instant.

## Behaviour
- `EXTRA_CODES` and its filter are gone. Extras come from snapshot `surcharge` lines (policy.extras is the fallback when a snapshot has no lines).
- Fare lines carry `kind`, `names` (per language) and a signed amount. A fare or surcharge that absorbed part of a voucher (plan 03 stores `params.list_rappen`) shows its list amount, and the coupon row shows `-params.discount_rappen`, so the rows sum to the stored total without arithmetic in the UI.
- OpsDetail label order for an extra: names[ops language], names.en / line label, humanised code. Rendering is DC text binding only (T-26.3-20-01).
- Legacy bookings (three codes, price.surcharge.child_seat.label) still render. A booking with no stored lines shows the stored total as one transfer row and its extras as "Included".
- `requestCustomerTimeChange` converts `scheduledLocal` with `zurichLocalToUtcMs`; a client `scheduledAt` is ignored; a non wall-clock text returns `not-found`. "2026-10-01T08:00" stores `2026-10-01T06:00:00.000Z`.
- draft-preview counts both `extra` (quote) and `surcharge` (snapshot) lines.
