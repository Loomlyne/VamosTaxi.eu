# Phase 26.3 Plan 10: Hosted Pay endpoint Summary

`/api/checkout/intent` now prices with `checkoutCharge` against the live catalog, creates one pending booking with generic snapshot lines, answers `{ ok, reference, booking_id, url, expires_at, amount_rappen }` with the hosted Stripe URL and the `vt_manage` cookie, reuses the same booking on Pay again, and replaces an unpaid booking only after Stripe confirms every session is expired and unpaid.

## What was built

- Schema: `extra_codes` (max 20, deduped, `^[a-z0-9_-]{1,64}$`), `company_name/address/vat`, `driver_note` (200/400/40/500), `supersedes` (booking uuid), `trip` validated by `parseTripQuery`. Old `extras` object is rejected (strict). Pay-link schema and `CheckoutIntentRequest` unchanged.
- `runCheckoutIntent` dispatches on `deps.mode`; absent or `"pay_link"` runs the old function untouched (renamed `runPayLinkIntent`). `pay-link/route.ts` needed no change.
- Web mode order: lock verify, trip vs lock (`when`, `pax`, `bags`, `flight` else `price_changed`), catalog, coupon re-evaluation, `checkoutCharge` (unknown code gives `price_changed`), Zurich manage expiry (D-36), then reuse / re-attach / replace / create.
- Reuse: same quote and open session at the same amount returns the same booking and URL, `createBooking` not called. Expired session at the same amount attaches a new hosted session to the same booking. Changed amount: expire all sessions of the booking, read all back, `allSessionsExpiredUnpaid`, then `purge_unpaid_booking(id,'superseded')`, then create. A complete session refuses `quote_already_booked` and never purges.
- `supersedes` (new quote_id after a re-quote): only when the request's vt_manage hash owns the old booking (guest-role RLS); same expire/confirm/purge sequence; a complete old session refuses.
- Stripe idempotency key gets an `:after:<id>` suffix after a replace or re-attach, so Stripe does not return the old expired session.
- Route: `mode:"web"`, `uiMode:"hosted_page"`, origin from `publicSiteOrigin`, `WEB_CHECKOUT_MINUTES` (31), TWINT flag, live catalog, `checkout_set_booking_details`, `checkout_booking_session_ids`, `purge_unpaid_booking`. No client secret or publishable key is returned or referenced.

## Fix: reuse compares the selection (coordinator request)

Reuse used to compare the Stripe session amount only. Now `runWebIntent` computes a SHA-256 selection fingerprint (quote_id, class, sorted extra codes with quantities, voucher code, rate and settings version, charged amount) and sends it as Stripe session `metadata.selection` (new optional `selectionFingerprint` input on `createCheckoutSession`, `lib/checkout/stripe.ts`). The reuse and re-attach branches require `stored.metadata.selection === fingerprint`; any other case (different extra or class at the same total, different voucher, a session with no fingerprint) takes the changed-selection path: expire all sessions, purge only if all are expired and unpaid, create a new booking. New unit tests: same total + different extra, same total + different class, session without fingerprint; identical selection reuse (same booking and URL) was already tested.
