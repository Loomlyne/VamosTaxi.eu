# 26.3-G2 Summary: account surfaces translation gap (Law 03)

Account and bookings now resolve every visible string in de, fr and ar; `VamosLocale.coverage(document.body)` is empty on both (bar the signed-in person's own name, e-mail and initials, which are data).

## Added to app/vamos-i18n-dict.js
- 11 exact entries: phone hint, "Save number", account-deletion paragraph, account footnote, "Explore", "WhatsApp", "Vamos Taxi" (Latin in all languages), "info@vamostaxi.site", YouTube and TikTok aria labels, "Zurich Airport (ZRH)".
- 29 patterns, generated in one block from month and status tables (plain strings, because the runtime reads patterns back as templates): `CHF n`, `n passengers · VT-ref` (plural and singular, refs with hyphens), 12 "Month YYYY" group headings, 14 booking-row aria labels (with and without time, 7 statuses).
- Swiss German uses "ss"; no legal or data-tok text touched.

## Test
apps/web/tests/integration/account-i18n-coverage-26-3.spec.ts: coverage empty on /account and /bookings in de, fr, ar; no sideways scroll at 390 in de and ar. 10/10 pass, plus the 7 in account-bookings-26-3.spec.ts. `pnpm i18n:check` passes.

## Notes
- The booking-row aria label translates ref, time word and status; the date part ("Fri 14 Aug") stays as the API sends it, because a static pattern cannot map weekday and month.
- A bare "$1" identity pattern must never be added: the runtime reads templates back as regexes and it would match every string.
