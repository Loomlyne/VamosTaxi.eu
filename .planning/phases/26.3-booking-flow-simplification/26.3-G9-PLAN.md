# 26.3-G9 Plan: the pay-link page lists the extras

Owner decision (2026-09-29, via the control session): /checkout/pay/<token> lists every ticked extra before 26.3 ships.
Plan 18 found the pay-link read (`checkout_pay_link_by_hash`) returns no snapshot lines.

## Objective

1. The page shows the booking's saved fare lines: fare (ex VAT), one line per extra with the owner's name in the page language, a voucher line if any, VAT, then the total. Lines sum to the total and to `charged_rappen` (the Stripe hosted `unit_amount`).
2. Same page and same data path for a pay link sent from the dashboard (New trip, Send pay link): `/api/checkout/pay-link/open` is the only source.
3. No extras: no extras block, no empty heading, the page is exactly as before.

## Data

New migration `20260930170000_pay_link_lines.sql` (never edits the seven existing 26.3 migrations): `public.checkout_pay_link_lines(p_token_hash bytea)`, SECURITY DEFINER, `set search_path = ''`, same validity filter as `checkout_pay_link_by_hash` (token purpose `pay`, not revoked, not expired, snapshot or hold window open, booking pending/quote). Returns only `seq, kind, code, names, vat_rate_bps, amount_rappen` of the booking's own price snapshot. Wrong or expired token: zero rows. Grants: `vamos_checkout` only.

## Files

- New: `packages/db/supabase/migrations/20260930170000_pay_link_lines.sql`, `packages/db/supabase/tests/pay_link_lines.test.sql`, `apps/web/lib/checkout/pay-link-lines.ts` (+ `.test.ts`).
- Changed: `app/api/checkout/pay-link/open/route.ts` (adds `lines`), `app/[locale]/checkout/pay/[token]/PayClient.tsx`, `pay-link.css` if needed, `lib/db/database.types.ts`, `tests/visual/pay-link-page.spec.ts`, tests that read the route source.

## Acceptance

- `child-seat` (fixture 1000) and invented `pet-crate` (fixture 1500) show with the owner's name in en/de/fr/ar (fallback names[locale], names.en, humanised code, never the raw code); fare + extras + VAT = total = Stripe amount.
- Amounts come from the saved snapshot lines, never today's price book. Amounts via `formatAmount` (the money helper checkout uses), PriceSummary component, logical properties, `ar` dir=rtl, 1440/1024/768/390 no sideways scroll.
- pgTAP: valid token returns lines; wrong and expired token return nothing; grants.
- The pay-link e-mail is NOT changed; the finding is reported.

## Threat model

| ID | Threat | Disposition | Mitigation |
|----|--------|-------------|------------|
| G9-01 | Token guess reads another booking's lines | mitigate | Lookup by SHA-256 token hash only, same filter as the pay-link read; no booking id parameter |
| G9-02 | Function leaks unrelated snapshot data (policy, coupons, contact) | mitigate | Returns six columns; names reduced to the four locale keys |
| G9-03 | Function callable by anon or authenticated | mitigate | revoke from public, anon, authenticated; grant to vamos_checkout only; pgTAP asserts |
| G9-04 | Page total differs from Stripe amount | mitigate | Lines come from the same snapshot whose total is `charged_rappen`; route refuses to send lines whose sum is not the charged amount |
| G9-05 | Owner-typed extra name injected as markup | mitigate | Rendered as React text, never as HTML |
