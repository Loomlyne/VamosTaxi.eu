## Deviations from Plan

1. **[Rule 1] Rate limit scope.** Plan says reuse the /api/quote limiter. That limiter is 8/min per subject, which would throttle extra ticks. It is applied only when a voucher is looked up (the brute-force path, T-26.3-11-04). CSRF check applies to every call.
2. **[Rule 2] Voucher on a coupon-carrying lock.** A different code than the lock's coupon returns `coupon_no_longer_valid` (action: requote), because the lock's class totals are already post-coupon. Changing a voucher is a requote, not a price tick.
3. **Extra file `lib/checkout/me.ts`** holds the pure handler (not in files_modified, plan's me.test.ts needs something to import).
4. **Erased customers.** `customers.erased_at` is not readable by `authenticated`, so the route first resolves `customer_id_for_user` (null when erased) and only then reads the own row under RLS.
5. **Full pgTAP suite not run** (a full reset is forbidden in the shared stack). Only my own test ran.
