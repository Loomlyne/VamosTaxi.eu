# Phase 26.3: Booking flow rebuild - Research

**Researched:** 2026-09-29
**Domain:** Stripe hosted Checkout, settle/e-mail path, generic price-book extras, Zurich time, unpaid-row lifetime, account linking, DC-mock → React URL hand-off, local test harness
**Confidence:** MEDIUM-HIGH (code paths HIGH from file:line reads; Stripe facts HIGH from official docs + SDK types; two root causes need one read-only live query each to move from MEDIUM-HIGH to proven)

## Summary

Three findings change the plan more than anything else. **First, the missing confirmation e-mail, the missing confirmation page and the "card payment failed" screen share one probable root cause:** `deliverConfirmation` (`apps/web/lib/checkout/notify.ts:54-76`) runs as `vamos_system` and does a raw `select policy from public.price_snapshots`, but `vamos_system` has had every table grant revoked (`20260827000002_checkout_roles.sql` "revoke all on all tables in schema public from vamos_checkout, vamos_system"; `20260827000005_confirmation_mail.sql:3` "vamos_system has EXECUTE on settlement RPCs only — no table grants"). That read throws (42501) **after** the settle transaction has committed and **before** `notification_claim`. The return route catches it and redirects to `/checkout/payment?pay=failed` (`app/api/checkout/return/route.ts` catch); the queue retry then sees `already_settled = true` and skips the e-mail forever (`lib/checkout/settle.ts:363-365`); no claim row exists, so the 03:00 sweep never finds it. One read-only query proves it (see Open Questions 1). **Second, `actorCustomerId: null` is hard-coded** in both `/api/checkout/intent/route.ts:156` and `/api/checkout/pay-link/route.ts:151`, so no booking is ever linked to a signed-in customer. **Third, Stripe's hosted Checkout does not support Arabic**: the official Checkout Session `locale` enum and stripe-node 22.6.1's `Locale` type have no `ar` (D-22 says it does). Arabic must map to `en` (the Deferred list already names "English fallback now").

Moving to hosted Checkout is not a one-line `ui_mode` flip. The value is `hosted_page` (not `hosted`, which Stripe API `2026-03-25.dahlia` rejects). `sessionIsPayable`, `sessionWithSecret` and `okIntentResponse` all require `client_secret`, which a hosted session does not have (`lib/checkout/stripe.ts:238-249`, `lib/checkout/intent.ts:178-265`). `fxFromSession` reads `session.currency_conversion`, which Stripe only fills for sessions created before 2025-03-31, so presentment currency (D-21) has never been recorded; the replacement is `session.presentment_details`, and `booking_payments` has no presentment-currency column. `createCheckoutSession` is shared with the pay-link page (`/checkout/pay/[token]`, PaymentPanel) and ops extra-fare sessions (`lib/ops/edit-request.ts:370`), so the UI mode must become a parameter.

D-25 "hard delete" collides with the database's own design: `price_snapshots`, `price_snapshot_legs`, `booking_events`, `booking_refunds`, `audit_log`, `consent_log` are append-only by trigger, and `stripe_events` / `booking_notifications` have `no_delete` triggers (`20260823000019_append_only.sql:107-118,180-181`). An unpaid booking already has rows in `price_snapshots` and three `booking_events` at creation. A purge needs a narrow, audited carve-out in `tg_append_only`, and the D-37 one-off script must disable those triggers inside its own transaction.

**Primary recommendation:** Fix the settle/e-mail path first (definer RPC for the e-mail read, e-mail failure never fails the settle or the redirect), wire the signed-in customer into the intent, then build the hosted-page intent with an explicit `payment_method_types: ["card","twint"]`, `wallet_options.link.display: "never"`, `expires_at` now + 31 min, `success_url` to `/api/checkout/return?…&session_id={CHECKOUT_SESSION_ID}` and a `cancel_url` that carries the trip query plus `resume=<quote_id>`.

### Pattern 1: Hosted Checkout Session (what `createCheckoutSession` must send)
```typescript
// Sources: https://docs.stripe.com/api/checkout/sessions/create , changelog 2026-03-25.dahlia ui_mode,
// https://docs.stripe.com/payments/checkout/payment-methods?payment-ui=stripe-hosted
stripe.checkout.sessions.create({
  mode: "payment",
  ui_mode: "hosted_page",                       // NOT "hosted" (rejected since dahlia)
  success_url: `${origin}/api/checkout/return?locale=${loc}&session_id={CHECKOUT_SESSION_ID}`, // braces unencoded
  cancel_url:  `${origin}${prefix}/checkout?${tripQuery}&resume=${quoteId}`,   // own param; no template here
  payment_method_types: twintOn ? ["card", "twint"] : ["card"],  // overrides Dashboard PMC; card brings Apple Pay/Google Pay
  wallet_options: { link: { display: "never" } },
  locale: loc === "ar" ? "en" : loc,             // Stripe Checkout has no Arabic
  expires_at: Math.floor(Date.now() / 1000) + 31 * 60,   // 30 min minimum; 60 s skew buffer
  adaptive_pricing: { enabled: true },
  customer_email: contact.email,
  client_reference_id: bookingRefOrIdempotencyKey,
  metadata: { booking_id: quoteId, booking_reference: idempotencyKey },
  payment_intent_data: { metadata: { quote_id: quoteId } },
  line_items: [{ quantity: 1, price_data: { currency: "chf", unit_amount: chargedRappen, product_data: { name: "Airport transfer" } } }],
}, { idempotencyKey });
// Response: session.url (redirect target), session.expires_at, session.status "open". No client_secret.
```

### Pattern 2: "Paid means confirmation page" return route
- Retrieve the session server-side (already done in `settlePaidReturn`).
- If `payment_status === "paid"`: run settle inside try/catch; **whatever happens after that**, 303 to `/{loc}/confirmation/<ref>` (ref from `checkout_reference_for_session`). The loading screen (D-27) covers "not confirmed yet".
- If `payment_status !== "paid"` (TWINT declined, etc.): 303 to `/{loc}/checkout?<trip>&resume=<quote_id>&pay=unpaid` (not `/checkout/payment`, which D-31 forwards anyway).

### Pattern 3: One pure charge function for display and charge
Today the screen and the server compute extras differently (deferred-items "The screen totals any priced extra; the server charges three kinds only"). Build `checkoutCharge({ payload, classSlug, extraCodes, catalog, couponEval, vatRateBps })` returning `{ lines: [{kind, code, label, amount_rappen}], netRappen, vatRappen, chargedRappen }` using the existing `payableRappen` (keep D-34 exactly). Call it from the new `/api/checkout/price` (display, "Updating price") and from intent (charge + snapshot). The browser never adds amounts itself.

### Anti-Patterns to Avoid
- **Flipping `CHECKOUT_UI_MODE` globally:** breaks `/checkout/pay/[token]` (PayClient + PaymentPanel need `client_secret`) and ops extra-fare sessions. Pass the mode per caller.
- **Reusing `sessionIsPayable` for hosted:** it returns false without `client_secret`; every hosted session would be expired and retried, then refused (`intent.ts:421-439`).
- **Quoting server-side in the page's GET:** each page view would spend Mapbox units without Turnstile/rate limit.
- **Sending `kind:"coords"` places from the URL:** `coords` needs a seen geo session or `vamos_qs` (`pipeline.ts:585-590`) and never sets `isAirport` (`pipeline.ts:291-297`) — the airport fee would silently drop.
- **Matching extra codes by name/normalisation:** D-35 forbids it; select catalog rows by exact code within the live book.
- **Deleting by clock only:** a session paid at 29:59 with a late webhook must never lose its booking.

## Common Pitfalls

### Pitfall 1: `expires_at` exactly 30 minutes
**What goes wrong:** Stripe rejects `expires_at` less than 30 min after *its* creation time; Worker clock skew of a second fails every Pay. **How to avoid:** now + 31 min (or reuse the existing clamp with +60 s). [ASSUMED skew behaviour; the 30-min floor is CITED]

### Pitfall 2: `twint` in `payment_method_types` before activation
**What goes wrong:** session create likely errors → no one can pay. **How to avoid:** `STRIPE_CHECKOUT_TWINT` flag default off; one sandbox call after the owner's activation; a unit test that the list is `["card"]` or `["card","twint"]`. [ASSUMED error behaviour]

### Pitfall 3: Arabic locale
**What goes wrong:** `locale:"ar"` on a hosted session is outside Stripe's enum → 400 or silent fallback. **How to avoid:** map `ar → "en"`; test it. D-22's claim is contradicted by the API reference.

### Pitfall 4: `client_secret` assumptions
**What goes wrong:** `sessionIsPayable`/`okIntentResponse` refuse every hosted session. **How to avoid:** hosted helpers check `status === "open"`, `url`, amount; tests with a hosted-shaped fixture (no `client_secret`, has `url`).

### Pitfall 5: E-mail failure after settle
**What goes wrong:** exactly VT-26-0737. **How to avoid:** definer RPC read; claim first; `try/catch` around delivery; return route redirects to confirmation whenever Stripe says paid; sweep "confirmed without confirmation claim".

### Pitfall 6: Coords places from the URL
**What goes wrong:** airport fee dropped, `retrieve_without_suggest` refusals. **How to avoid:** carry `mapbox_id` + geo session; server resolves.

### Pitfall 7: Purge races
**What goes wrong:** a late `checkout.session.completed` for a purged booking → settle P0002 forever → DLQ with money captured. **How to avoid:** purge only on Stripe-confirmed `expired` + unpaid; settle for a missing booking alerts ops (`deliverStuckPaymentAlert`) and refunds.

### Pitfall 8: Seed/i18n drift
`pnpm db:seed:check` fails when messages change without `db:seed:gen` (26.1 deferred item). Regenerate in the same commit.

### Pitfall 9: Rate limit in local runs
`/api/quote` is limited (8/min, `QUOTE_RATE_LIMITER`); every inline-edit and extra tick must not call `/api/quote` (ticks call the new price route, which does no Mapbox work).

```typescript
// Source: Stripe Session object fields status/url/amount_total (API ref); CHF integration currency (adaptive-pricing doc)
export function hostedSessionIsPayable(s: Stripe.Checkout.Session | null, chargedRappen: number): s is Stripe.Checkout.Session {
  if (!s || s.status !== "open" || !s.url) return false;
  if ((s.currency ?? "").toLowerCase() !== "chf") return false;
  return (s.amount_total ?? s.amount_subtotal) === chargedRappen;
}
```

## Security Domain

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes (sign-in link, account linking) | Supabase Auth; link only confirmed e-mails |
| V3 Session Management | yes | `vt_manage` HttpOnly/Secure/Lax; no tokens in URLs except the existing pay-link token |

| V5 Input Validation | yes | zod on URL params and bodies; server re-prices everything |
| V6 Cryptography | no new | HMAC lock, token hashing stay |

### Threat-model inputs
| Pattern | STRIDE | Mitigation |
|---------|--------|------------|
| Client tampers price/extras/coupon | Tampering | lock HMAC + server `checkoutCharge`; `is_airport` forbidden from client |
| Unknown/forged extra code | Tampering | exact match against live catalog; refuse |
| Webhook forgery / replay | Spoofing | signature verify; `stripe_events` dedupe (unchanged) |
| Success URL visited without paying | Spoofing | return route retrieves the session; paid is Stripe's word |
| `resume=<quote_id>` guessing → PII leak | Info disclosure | requires matching `vt_manage` hash; returns nothing otherwise; quote ids are UUIDv4 |
| PII in URL (trip addresses, flight) | Info disclosure | addresses are in URL by design (D-05); never put name/e-mail/phone in the URL; `Referrer-Policy` check for the Stripe redirect; logs never print query strings |
| Account-link takeover by registering someone's e-mail | Elevation | link only when `email_confirmed_at` is set |
| Hard delete destroys evidence | Repudiation | purge only pending/no-pay-link/no-success; non-PII audit row; carve-out gated by transaction-local GUC inside a definer function |
| Late payment for a purged booking | Tampering/Availability | purge after Stripe-confirmed expiry; settle-missing → alert + refund |
| D-37 script run by mistake | Tampering | owner-only, backup schema first, FK self-check, single transaction |
| Open redirect via `cancel_url`/`returnTo` | Spoofing | build from `publicSiteOrigin` + fixed path; sign-in `returnTo` must be same-origin path |
| Quote abuse via shared URLs | DoS/cost | client-side `/api/quote` keeps Turnstile, rate limit, Mapbox breaker |
