## Spacing Scale

Declared values (all multiples of 4). This is the project token scale in `design-system/tokens/spacing.css` (`--vt-space-*`), so 12px, 40px and 56px are allowed tokens, not exceptions:

| Token | Value | Usage |
|-------|-------|-------|
| xs (`--vt-space-1`) | 4px | Icon-to-text gaps, kicker-to-field gap |
| sm (`--vt-space-2`) | 8px | Counter internals, badge gaps, gap between stacked hint and field |
| sm+ (`--vt-space-3`) | 12px | Gap between class cards, pay-bar vertical padding, extra-row gap |
| md (`--vt-space-4`) | 16px | Gap between fields in a section, card inner padding on phone |
| lg (`--vt-space-6`) | 24px | Section card inner padding (≥681px), gap between the three sections on phone |
| xl (`--vt-space-7`) | 32px | Gap between sections on tablet/desktop, main ↔ rail column gap |
| 2xl (`--vt-space-8`) | 40px | Top padding of checkout main below the trip strip, loading/confirmation card padding (desktop) |
| 3xl (`--vt-space-9`) | 56px | Space between last section and footer |

Exceptions (fixed by `CLAUDE.md` and the design system, not spacing tokens):
- Control heights: 44px (`--vt-control-h-md`) minimum for any tap target (counter −/+, disclosure rows, links rendered as
  buttons, back chevron); **54px** (`--vt-control-h-lg`) for every home box field, the Travellers button, SEE PRICES, the
  checkout contact/flight fields and PAY.
- Sticky header 76px (60px ≤1080px); sticky rail `top: 96px`; scroll-to-error offset = header height + 16px.
- Phone/tablet pay bar: 12px block padding + 54px CTA + `env(safe-area-inset-bottom)`. The page reserves the same height
  as bottom padding so the footer and the last field are never hidden under the bar.
- Page gutter `clamp(20px,5vw,56px)`; container 1200px.

## Layout and Interaction Contract per Surface

**Focal point per screen**
- Home: the booking card and its SEE PRICES button.
- Checkout: section 1 class cards; PAY is the single yellow accent on the page.
- Confirmation (and loading-screen phase B): the charcoal check disc and the word "Booked".

Breakpoints (existing): desktop ≥1181 · desktop-narrow 1081–1180 · tablet 681–1080 · phone ≤680. Check 1440, 1024, 768,
390 in en, de (German +30%) and ar (RTL). Nothing scrolls sideways at 390. Logical properties only
(`margin-inline-start`, `inset-inline-end`, `padding-inline`); arrows and chevrons mirror in RTL.

### S1 — Home booking box (`app/home/home.dc.html`, DC mock)

DOM and tab order at **every** size (D-10): From → Flight (only when From is an airport) → To → When → Travellers → SEE PRICES.
Removed: trip-type tabs (both the compact and sheet tab bars and their mode note), every price, class list, "Pick one to skip a step".

| Width | Arrangement |
|-------|-------------|
| ≥681 (tablet, desktop) | 2-column grid inside the floating card (24px radius, `--vt-shadow-lg`, the page's one lg shadow). Row 1: From · swap button · To. Row 2 (airport only): Flight in the From column, To column empty. Row 3: When · Travellers. Row 4: SEE PRICES full width. Trust line under the button (existing three items: "Price fixed before you pay", "Flight tracked", "Free cancellation window") |
| ≤680 (phone) | 1 column, box stacks first under the hero: From, Flight, To (swap button sits inline-end on the To kicker row, as in sketch), When, Travellers, SEE PRICES, trust line |

- **Airport detection [discretion]:** From is an airport when the selected place's zone/place type is an airport
  (Mapbox `poi` category airport or the service-area zone type). Detection runs on selection, not on typing.
- **Flight field:** appears directly under From after an airport is selected; fades in over 140ms with no height
  animation beyond the field's own height (reduced-motion: instant). Kicker `FLIGHT NUMBER`, icon `plane-landing`,
  placeholder `LX 318`, hint "We track it and move the pickup if you land late". Value upper-cased, spaces normalised, kept
  LTR (`.vt-dir-keep`). Required for airport pickups. If From changes to a non-airport, the field hides and its value is dropped.
  The swap button re-evaluates: flight follows the pickup only.
- **Travellers:** one 54px pill button, icon `users`, reads "2 passengers · 3 bags" (defaults: 1 passenger · 0 bags
  [discretion, matches existing min]). Opens a popover anchored under the button (≥681) or the existing bottom sheet
  (≤680). Contents: `Passengers − n +` (1–8) and `Bags − n +` (0–16), 44px steppers, `DONE` button (secondary,
  44px). Escape / scrim click closes; focus returns to the Travellers button. Sheet body carries `data-lenis-prevent` if it scrolls.
- **SEE PRICES:** `Button variant="primary" size="lg" block iconEnd="arrow-right"`, always enabled. On click with gaps:
  every missing field shows its inline error, focus moves to the first one in DOM order, nothing navigates. On success:
  navigate to `/{locale}/checkout?from=…&to=…&when=…&pax=…&bags=…&flight=…` (D-05). No `localStorage.vamosTrip`, no
  `saveTrip`, no abandon call.
- Lead-time and same-place errors reuse the existing `quote error.*` messages under the relevant field.

### S2 — Checkout (`apps/web/app/[locale]/checkout`, one page, React)

Shell: `SiteHeader variant="inverse"` with the header CTA dropped (booking already in view) + `SiteFooter`.

**Trip strip** (below header, white, hairline bottom): back `IconButton` `chevron-left` (44px, mirrors in RTL) → home (home always opens empty; nothing is carried back);
line 1 "Zurich Airport" + `Icon arrow-right` (mirrors) + "Bahnhofstrasse 1" (ellipsis, `min-width:0`); line 2
"Tue 29 Sept, 08:15 · 2 passengers · 3 bags"; inline-end link "Edit trip" that opens the **inline trip editor** on this page (owner, 2026-09-29). There is no route back to a
prefilled home: home is never prefilled and always starts empty.

**Inline trip editor** (owner, 2026-09-29) — the same four fields as the home box, same components, same order and same
validation: From → Flight (only when From is an airport, required) → To → When → Travellers, then `UPDATE PRICES` (primary, 54px)
and `CANCEL` (ghost, 44px).
- Opens in place of the trip strip, pushing the sections down (no overlay). ≥681: the home box 2-column grid; ≤680: 1 column.
  Fields are prefilled with the current trip. Focus moves to From; `Escape` or `CANCEL` closes without change and returns
  focus to "Edit trip". While open, the pay bar / rail PAY stays visible; clicking PAY first closes the editor only if it is
  unchanged, otherwise it names the editor: "Update the prices first".
- `UPDATE PRICES` validates like SEE PRICES (inline errors, focus the first gap). Valid → **re-quoting** state: button
  loading "Updating prices", fields disabled, section 1 shows the class loading state, rail/bar total reads "Updating price".
  On success the editor closes, the trip strip shows the new trip, the URL is replaced (`history.replaceState`, same query
  shape as the home hand-off), prices re-quote, ticked extras and the applied voucher are re-priced by the server; if the
  selected class becomes too small, the selection clears. A contact already typed is kept.
- **Error** state: the editor stays open with the entered values, `Alert tone="danger"` above `UPDATE PRICES` carrying the
  matching `quote error.*` message (e.g. out of service area, too soon), the previous trip and prices stay untouched in the
  page, and `UPDATE PRICES` is ready again.
- Changing the trip after Back from Stripe re-quotes; the Pay flow then creates or updates the booking per the server rules (planner).

**Columns**

| Width | Layout |
|-------|--------|
| ≥1081 | Main column (sections 1–3) + sticky right rail 360px at `top:96px`, 32px gap. Rail: `RouteSummary`, trip facts (When, Travellers, Class, Flight), `PriceSummary` (fare, each ticked extra, voucher credit, VAT, total), legal line, **PAY** (54px, block), reassurance line. No pay bar |
| ≤1080 | One column. Sticky bottom pay bar: inline-start "Total" (13px label) over amount (20px Qurova) ; inline-end **PAY** (54px). Tapping "Total" scrolls to section 3's summary. No rail |

Exactly one PAY button is visible at any width. Sections are white cards (16px radius, hairline, `--vt-shadow-sm`),
each headed by a 28px charcoal numbered disc + Heading 20px title.

**Section 1 — Choose your class**
- Three `VehicleCard`s: Economy, Business, Van luxury (Latin in every language). Photo = supplied brand photography;
  subtitle/examples from fleet data; `users n` and `luggage n` capacity; price via `VamosLocale.money` / `money()` in React; note "fixed price".
- Grid: ≥681 `repeat(auto-fit,minmax(200px,1fr))` vertical cards (photo on top); ≤680 horizontal rows (photo 72px at inline-start, price at inline-end).
- No preselection unless the URL carries `class=` **[discretion]**; until a class is chosen the rail/bar total reads "Choose a class" and PAY stays enabled (it validates).
- Selected: 2px charcoal border + charcoal check disc on the photo; section-1 title disc becomes the yellow check disc.
- Too small (D-11): card `disabled` (42% opacity, `aria-disabled`, not selectable), price still shown, note replaced by
  "Seats up to {n}" (passengers) or "Takes up to {n} bags" (bags) **[discretion for the bags case]**. If the selected class
  becomes too small after editing the trip in the inline editor, the selection clears.
- Loading: three `VehicleCard loading` placeholders plus the sentence "Getting your fixed prices" above them (words, per DS §3 States). The rail total shows the same sentence.
- Quote error: replace the cards with `Alert tone="danger"` carrying the matching `quote error.*` message + `TRY AGAIN` (secondary) button; generic failure copy below.
- Pricing not live: existing `quote error.pricing_not_live` copy in an `Alert tone="info"`; PAY disabled.
- Amounts in design/mocks/tests read `CHF 000`; real amounts only from the live price book (Law 04).

**Section 2 — Who is travelling**
- Header row: title + inline-end link "Have an account? Sign in" (D-13) → sign-in with `returnTo` = this checkout URL;
  on return the contact fields are prefilled and the link is replaced by "Signed in as {email}" (13px, secondary).
- Fields (2-up at ≥681, 1-up at ≤680; 54px): First name, Last name, Email (icon `mail`, hint "Your confirmation goes here"),
  Mobile (`PhoneField`, hint "The driver calls this number on arrival").
- Flight (airport pickups only): `FlightField` prefilled from the URL, editable, same kicker/hint as home; never asked
  again if already present. Not shown for non-airport pickups.
- Extras (D-14/D-35, only if the live price book has passenger extras): subheading "Extras" + hint "Optional. Added to the
  fixed price." Each row = `Checkbox` (44px row) + extra name **from data** + inline-end "+ CHF 000" from data. All
  unticked on load. Ticking reprices through the server; the rail/bar total shows "Updating price" until the reprice
  returns. No section when the book has none. Never hard-coded extra names.
- Disclosures (44px rows, icon + label + "Optional" + `chevron-down` rotating 180°): "Need a company receipt?" →
  Company name, Company address, VAT number; "Add a note for the driver" → `Textarea` (hint "Meeting point, gate code, ski equipment").
  Collapsed by default; open state survives Back from Stripe.

**Section 3 — Payment**
- ≤1080: `RouteSummary` + `PriceSummary` + legal line here (the rail's content). ≥1081: section 3 holds only the
  method note and voucher (summary lives in the rail).
- Method note (with `Icon lock`): "You pay on Stripe's secure page: card, Apple Pay, Google Pay or TWINT." No wallet
  buttons, no card fields, no pay-link option (D-02, D-18).
- "Have a voucher?" link → `Input` "Voucher code" + `APPLY VOUCHER`; applied state shows "Voucher {CODE} applied" +
  `REMOVE VOUCHER` (ghost button, 44px); credit line appears in `PriceSummary`. Errors reuse `couponNotFound` / `couponNoLongerValid`.
- Legal line (13px), existing string verbatim (owner, 2026-09-29): "By continuing you accept the terms and the cancellation
  policy." (`app/vamos-i18n-dict.js:575`, `checkout.by-continuing-you-accept-the-terms-and-the-cance`; de/fr/ar already exist).
  Under it, the existing line verbatim (owner approved 2026-09-29): "Fixed price, all taxes and tolls included. Free
  cancellation up to 24 h before pickup." (`app/vamos-i18n-dict.js:572`, `fixed-price-all-taxes-and-tolls-included-free-ca`;
  de/fr/ar already exist). No new legal copy.
- Reassurance under PAY: "No charge until the Stripe page."
- Turnstile (if a challenge is shown) sits directly above PAY; managed/invisible otherwise.

**PAY interaction (D-17, D-23)**
- Label `PAY {total}` with `Icon lock` at start, e.g. `PAY CHF 000`; "PAY" when no class is chosen.
- Click validates in DOM order: class → first name → last name → email → mobile → flight (airport) → company name
  (only if the company disclosure is open and anything in it is filled). First failure: smooth-scroll it into view with
  header offset, focus it, show its inline error, and announce the error text in a polite live region inside the bar/rail.
  Section 1 failure shows "Choose a class" in `--vt-danger` with `circle-alert` under the title.
- Valid: button enters loading (spinner + "Opening payment"), all inputs `disabled`, then redirect to Stripe hosted page.
  If the redirect call fails: `Alert tone="danger"` above PAY with "Payment did not start. Try PAY again." and the
  button returns to idle.

**Return and expiry states**
- Back from Stripe (D-24): everything refilled, `Alert tone="info"` at the top of section 3 (and scrolled to):
  "Payment not finished. Your details are still here. Pay when you are ready." PAY reuses the same booking.
- Expired (D-25): `Alert tone="info"` at the top of the page: "This booking expired — see current prices" with
  `SEE CURRENT PRICES` (primary) which re-quotes from the URL trip; contact fields stay filled.
- Quote lock expired while on the page: existing `quoteExpired` copy + the same `SEE CURRENT PRICES` action.
- Old routes `/checkout/trip|details|payment` forward to `/checkout` (D-31) — no UI.

### S3 — Post-payment loading screen (confirmation route while unconfirmed, D-27)

Shell: header + footer. One centred white card (max 560px, 40px padding ≥681, 24px ≤680).
- Phase A (0–~20 s): `ProgressIndicator` (charcoal, indeterminate) · Display 26px "Confirming your booking" · body
  "Your payment went through. This takes a few seconds." · reference `VT-XXXX` (Qurova, `.vt-dir-keep`) when known.
  `aria-live="polite"`, `aria-busy="true"`. Polling mechanism **[discretion]**.
- Confirmed → replace in place with the confirmation page (S4); no reload flash.
- Phase B (after ~20 s unconfirmed): indicator stops; charcoal disc with yellow `check`; Display "Payment received." ·
  body "Your confirmation is on its way by e-mail." (verbatim, D-27) · reference · `BOOK ANOTHER TRANSFER` (secondary) ·
  contact line "Questions? Write to info@vamostaxi.site." Keeps polling quietly and swaps to S4 if confirmation lands.
- Never shows an error, "failed" or retry copy after a successful Stripe return (the old `failedBody` / `giveUpBody` are not used on this path).

## Accessibility and Motion

- Tap targets ≥44px; booking fields and primary CTAs 54px. Visible focus everywhere (ring on controls, charcoal border on fields).
- Travellers popover/sheet: `role="dialog"`, labelled, focus trapped, Escape closes, focus returns.
- Disclosures: `button` with `aria-expanded` / `aria-controls`. Disabled class cards: `aria-disabled="true"` with the "Seats up to" note in the accessible name.
- Errors: `aria-invalid` + `aria-describedby` on the field; one polite live region announces the first PAY error.
- Motion: 140ms hover/focus, 200ms alerts, 320ms sheet; easing `cubic-bezier(.2,0,.2,1)`; nothing scales, springs or loops (spinner excepted); `prefers-reduced-motion` honoured.
- Scrolling: follow the project scroll owner on main at execution time (Lenis via `assets/lenis-boot.js` / `VamosScroll`, or native if the pending "remove Lenis" quick task has landed). Never a second Lenis instance, never `scroll-behavior:smooth`.
