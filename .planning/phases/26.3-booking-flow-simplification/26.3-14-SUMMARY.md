# Phase 26.3 Plan 14: Loading screen after payment, "Booked" confirmation, no calendar Summary

After Stripe returns, the confirmation route shows "Confirming your booking" with a charcoal progress bar, switches to "Payment received." after 20 s, and swaps in place to a "You're booked, {firstName}." page with the e-mail's money rows. Add to calendar and its document route are gone.

## What was built

- `confirmationPhase({ elapsedMs, status, paymentStatus })` returns `confirming | received | booked | hidden`. No error phase exists.
- S3: `ProgressIndicator` charcoal (animated with CSS, `aria-busy`, `aria-live=polite`), then charcoal disc plus yellow check, "Payment received.", BOOK ANOTHER TRANSFER, contact line. Polls every 1 s, quietly, until booked.
- S4: disc, kicker BOOKED, heading with first name, reference and e-mail line, StatusBadge "Booked", RouteSummary, When / Travellers / Class / Flight, PriceSummary from `receipt.rows` (fare with class, extras by name, voucher, VAT rate, Total paid), presentment line when present, legal line, MANAGE BOOKING and BOOK ANOTHER TRANSFER. Cancel, time change and flight save stay.
- `/confirmation?session=` renders static "Payment received." copy only (no lookup).
- Removed: `FailedRoom`, give-up constants, Add to calendar, the disabled Resend button.
- 20 strings in en/de/fr/ar (ICU plurals and rich tags), seed regenerated.

## Deviations from Plan

1. **[Rule 3] de and ar not captured in the browser.** Middleware 308-redirects `/de|/fr|/ar/...` to the unprefixed URL, and with `localeDetection:false` the `NEXT_LOCALE` cookie does not select the Next route locale, so a Next page cannot be opened in German or Arabic locally. The visual spec covers en at four widths; de/ar are covered by the string-format unit test. Owner should know: this also means the `dir=rtl` check on Next pages cannot be run by URL right now. CSS uses logical properties only.
2. **[Rule 3] Two tests outside the file list edited** because they asserted removed behaviour: `confirmation-unmock.test.ts` (failed room, notVisible on index) and `callback-redirect.test.ts` (invite route no-store check, now asserts the file is gone).
3. **[Rule 1] `pendingTicket()` lacked `receipt`** (type error from plan 09); added an empty receipt.
4. Unpaid pay link now points to `/checkout` instead of `/checkout/payment` (D-31 forwards it anyway).
5. The unused message key `checkout.add-to-calendar` was left in place.

## Deferred / still open
