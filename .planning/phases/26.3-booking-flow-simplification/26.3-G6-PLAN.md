# G6 Plan - the live extra row is shown, charged and recorded, and the path is generic

## Objective
Prove with tests that an owner-added extra (live fact, read-only GET /api/checkout/extras: code `child-seat`, 1000 rappen, toggle true) is labelled, priced, sent to Stripe, saved and shown in ops by its own code and amount. Owner rule: extras are generic dashboard surcharges; no code is matched, mapped or renamed. `child-seat` (1000) and an invented `pet-crate` (fixture amount 1500) are TEST FIXTURES only; the live price book is never written.

## Points and where each is proven
1. Label readable in en/de/fr/ar (not the raw code), given `extra_labels` names; and what shows before the owner saves names (humanised fallback).
   - `apps/web/lib/checkout/extras-g6.test.ts`: real `loadCheckoutCatalog` + real `GET /api/checkout/extras` handler (context mocked), names per locale for both codes, partial names, no names.
2. Price route amount equals the amount sent to Stripe, VAT included (`vat_rate_bps` 81 = 8.1 %).
   - unit: same file (`priceCheckoutWithDeps` vs `checkoutCharge`).
   - real code: `apps/web/tests/integration/extras-charged-recorded-db.spec.ts` (price route amount == intent `amount_rappen` == `unit_amount` in the params the real `createCheckoutSession` hands to a fake Stripe client).
3. Saved fare lines hold the extra by the owner's name and amount (lock-to-rpc snapshot -> `checkout_create_booking` on local stack 55322), and the ops read (`mapBoardBooking` over the same `price_snapshots` row `loadBookings` selects) shows it.
   - same DB spec.
4. Unticked: nothing added (total, Stripe amount, saved lines).
   - same DB spec (case "none"); unit file.

Each of 1-4 runs for `child-seat`, then `pet-crate`, then both together.

## Method
- DB spec follows plan 10's `intent-supersede-db.spec.ts`: real `runCheckoutIntent` (mode web) + real SQL, only Stripe faked in process, ONE transaction, rolled back. Refuses anything but 127.0.0.1:55322. No reset.
- No checkout client, CheckoutClient.tsx or messages json edits (plan 15 owns them). Minimal source fixes only if a test exposes a bug in lib code.

## Known finding to record (not fixed here)
The committed `CheckoutClient.tsx` tile still labels through the legacy `extraUi` map and `code.replace(/_/g, " ")`, ignoring the route's `names`. Plan 15 / 21 own that. This plan proves the data the tile needs is correct.
