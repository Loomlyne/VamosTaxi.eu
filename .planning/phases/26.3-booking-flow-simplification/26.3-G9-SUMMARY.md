# Phase 26.3 Plan G9: the pay-link page lists the extras

/checkout/pay/<token> now shows the booking's saved fare lines (fare ex VAT, one line per extra in the owner's name, voucher, VAT) above the total, for site bookings and dashboard Send pay link alike (one page, one data path: `/api/checkout/pay-link/open`).

## What changed

- New function `public.checkout_pay_link_lines(bytea)`: SECURITY DEFINER, empty search_path, same token/hold filter as `checkout_pay_link_by_hash`, returns kind, code, names (four locale keys only), VAT bps, amount. Execute granted to `vamos_checkout` only.
- The open route sends `lines` only when they sum to `charged_rappen` (the hosted session amount). Otherwise `lines` is empty and the page shows the plain total.
- PayClient uses `PriceSummary` and the same labels as checkout (`fareExVat`, `receiptVat`, `couponCode`), names via `extraLabel` (names[locale], names.en, humanised code). No extras: no breakdown, no heading.

## E-mail finding (not changed)

The pay-link e-mail (`PayLinkEmail.tsx`, fed by `lib/checkout/pay-link.ts`) lists the total and does list the extras: one "Extras" fact with the names joined by " · ", in the e-mail language, names only, no per-extra amounts (HTML and plain text). It also lists the voucher code.

## Deviations

None. One test-harness note: a first Playwright rerun hit a browser-session crash on a pre-existing spec while other sessions' dev servers were running; the rerun passed 36/36.
