# G5 Summary - the customer's language follows them onto the Next pages

`NEXT_LOCALE` (en|de|fr|ar, validated) is now the single source. Middleware rewrites unprefixed Next pages to `/{locale}/...` from it, so checkout, confirmation and review render in the chosen language with correct `<html lang>` and `dir="rtl"` for ar. Addresses stay unprefixed.

## Changes
- `apps/web/lib/locale-cookie.ts` (new): `resolveCookieLocale` (exact match, else en), `localeRewriteResponse` (rewrite + `X-NEXT-INTL-LOCALE` header + `Vary: Cookie`).
- `apps/web/middleware.ts`: public host, unprefixed, cookie != en -> rewrite; otherwise next-intl as before. 308 for prefixed URLs, DC serving, /api guard, browser-openable routes, security headers untouched. Marketing cache branch now appends to Vary; a non-en cookie on the Next-page path forces `private, no-store`.
- `apps/web/lib/locale-shim.ts`: `setLang` writes the cookie and `router.refresh()` (was `router.replace(path,{locale})`, which 308'd back to English).
- `app/vamos-locale.js`: `setLang` (and boot) mirrors the language into `NEXT_LOCALE` (Path=/, SameSite=Lax, 1 year, Secure on https), so the home choice carries over.
