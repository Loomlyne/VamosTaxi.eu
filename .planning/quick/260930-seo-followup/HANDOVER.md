# SEO follow-up: three live differences (main 5b394833)

Branch `fix/seo-head-followup`, cut from `origin/main` (see `git log`). No push, no deploy.

1. **Dashboard robots.txt answered the public rules.** Cause: `dashboard-gateway.ts` sends dotted files to the apex (K92), so `/robots.txt` on `dashboard.vamostaxi.site` never reached `vamos`; the `worker.ts` block I added could not run there. Fix: the gateway answers `/robots.txt` itself, `Disallow: /`, `X-Robots-Tag: noindex`; the dead `worker.ts` block is removed. Test: `apps/web/lib/seo/dashboard-robots.test.ts`. **Needs `pnpm --filter web deploy:dashboard`** (Worker `vamos-dashboard`), not only the `vamos` deploy. Not proved on a deployed gateway; read `https://dashboard.vamostaxi.site/robots.txt` after it.
2. **`/de/faq` "private, no-store".** Not a bug. Live `curl -I` sends HEAD; the Worker caches only GET. Live GET of `/de/faq`, `/terms`, `/` answers `public, s-maxage=300, stale-while-revalidate=3600` and `x-consent-present: 0` (read 2026-09-30). No change.
3. **Stored language and cookie disagree.** A real visitor reaches it: an old visitor with a stored language and no cookie (or a cookie older than its one-year life). Before this branch: first view at `/` was English in the head (title, canonical), the body relabelled to the stored language, and the address stayed `/`; `vamos-locale.js` writes the cookie at load, so the next request redirected to `/ar`. The stored language wins over a cookie that says otherwise, because the cookie is rewritten from it at load. Fix: `followAddress()` also runs at start, so the first view moves the address to `/ar/...` and retitles the tab. Proved in Chromium with the real `vamos-locale.js` on a stub page: stored ar with no cookie, stored ar with cookie en, stored ar on `/sign-in` (title only, address unchanged), nothing stored (unchanged), `/ar/about` (unchanged). Not proved on the live Worker.
