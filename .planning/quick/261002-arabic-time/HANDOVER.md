# Hand-over — the pickup time read backwards in Arabic

**From:** job session `vamostaxi-eu-bb`, branch `fix/arabic-time-spinner`, cut from `origin/main` `3978fda9`.
**Queue item:** "Arabic polish 2 — home time spinner reads '30 : 04' for 04:30 in Arabic" (control board).

## The fault

`app/home/WhenPicker.dc.html` lays the time out as three boxes in a flex row: hour, colon,
minute. The row inherited the page direction, so under `dir="rtl"` the browser painted it
right to left and the minute came first. A customer picking 04:30 in Arabic saw **30 : 04**.

The two numbers already carried `.vt-dir-keep`, which is why this was missed — each number was
individually correct. The *row* was the problem, not the digits.

## The fix

One attribute on that row in the mock, and the same on the React twin:

- `app/home/WhenPicker.dc.html` — `dir="ltr"` + `.vt-dir-keep` on the spinner row.
- `apps/web/components/forms/TimePicker.tsx` — same on `.vt-time__spin`.

A time is written hour-first in every language this product ships.

## Proof

`node .planning/quick/261002-arabic-time/tools/drive.mjs` (`VT_LANG=ar|en|de|fr`) opens the home
booking box in a real browser, opens the When picker and compares **markup order against painted
order**. Language-independent on purpose: `aria-label` is translated at runtime, so the hour
column cannot be found by its English label.

- With the fix: all four languages pass, Arabic paints `15:55`.
- **With the fix reverted, Arabic paints `55:15` and the check fails** — so the check really
  catches this, it does not just pass by default.
