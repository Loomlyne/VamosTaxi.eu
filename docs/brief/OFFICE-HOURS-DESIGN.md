## Problem Statement

Vamos Taxi GmbH sells pre-booked airport and private transfers in Switzerland but runs on an Inware Freshpage agency CMS: weak conversion UX, vendor lock-in, discoverable admin, and no owned modern booking/ops stack. The operator needs a product customers can use like Transfeero (clear fixed price, book ahead) while dispatch runs a simple web dashboard — without Uber on-demand complexity.

## Demand Evidence

- Live business already takes online bookings on vamostaxi.eu (Freshpage booking module + Stripe/PayPal/TWINT logos).
- Legal entity, phone, partner-driver funnel, airport + ski routes already marketed.
- Client engaged rebuild: discovery invoice, brand guide, Scope of Work for 3–4 week V1.
- Product model validated by owner intent: book now for tomorrow; driver waits at set time (not street-hail).

## Status Quo

1. Customer uses dated jQuery/PHP multi-step form on Freshpage.  
2. Company confirms; may use partner carriers.  
3. Ops uses Freshadmin / `buchungen` contentmanager behind classic auth.  
4. No clean owned API, weak admin posture, mixed legal residue (“Connecto”), stock imagery.  
5. Android app exists separately (`com.app.vamostaxim`) — out of V1 rebuild scope.

## Target User & Narrowest Wedge

| Who | Job |
|-----|-----|
| Primary | Traveller / corporate guest needing ZRH (then CH) airport or city transfer at a known future time |
| Secondary | Phone-book customer handled by dispatch staff |
| Operator | Vamos dispatch: confirm, assign driver, manage price rules |

**Narrowest wedge worth shipping:**  
Mobile-first scheduled book → fixed price → Stripe pay → voucher email → admin sees booking and assigns driver. Everything else is scaffolding around that loop.

## Constraints

- Web only (no native apps V1)  
- Swiss local operator (not global marketplace)  
- No driver app / no live GPS tracking  
- Stripe **standard** (not Connect); first-party coupons  
- Mapbox free first (pin + route for price only)  
- Supabase Auth: accounts + history; guest checkout still allowed  
- ~6h/day builder capacity; multi-tool: Claude Design → Claude Code / Cursor / Hermes  
- Client blocking inputs (pricing, vehicles, policies) shift calendar day-for-day  
- Greenfield Next.js — do not fork Freshpage  

## Premises

1. Scheduled transfer is the product; on-demand is a different company.  
2. Transfeero is a quality bar for the funnel, not a feature checklist.  
3. Manual dispatch is enough for a single Swiss fleet + partners.  
4. Server-authoritative pricing + payment webhooks beat clever client UI.  
5. Owning code/data beats agency CMS even if V1 is thinner than Transfeero globally.

## Approaches Considered

### Approach A: Full marketplace (Transfeero clone)
Global supply, driver apps, auto matching, Connect payouts.  
**Reject:** Wrong business, wrong timeline, wrong ops model.

### Approach B: Template taxi SaaS / open-source port
Ship a generic multi-tenant taxi clone.  
**Reject:** Licence/quality gaps; still needs custom pricing/dispatch; not Vamos brand.

### Approach C: Owned scheduled-transfer OS (recommended)
Next.js + Supabase + Mapbox + Stripe standard + Resend + thin admin.  
**Accept:** Matches SOW, 3-week build path, full ownership.

## Recommended Approach

**Approach C** — product locked in `docs/DECISIONS.md` and client `docs/SCOPE-OF-WORK.md`.

Core loop:

```text
Map pin/search → datetime → quote → vehicle → coupon → auth/guest
  → Stripe → webhook confirmed → Resend voucher
  → Admin assign driver for pickup time
```

Stack: Next.js App Router, TypeScript, Tailwind, shadcn, Supabase, Vercel, Mapbox, Stripe standard, Resend.

## Open Questions (client)

- Final CHF price matrix + fixed ZRH routes  
- Vehicle class names/capacities/photos  
- Cancel window + min advance booking  
- TWINT eligibility on Stripe account  
- Instant confirm vs dispatcher approval on pay  
- Hourly chauffeur in V1 yes/no  

## Success Criteria

1. Phone: complete scheduled booking under ~1 min form time with clear fixed price.  
2. Pay (test/live Stripe) → voucher email.  
3. Account shows history; guest can book.  
4. Admin: list by pickup time, assign driver in 2 clicks, manual booking.  
5. Coupon reduces total correctly; price snapshot stable.  
6. Production on agreed domain; code owned by client.
